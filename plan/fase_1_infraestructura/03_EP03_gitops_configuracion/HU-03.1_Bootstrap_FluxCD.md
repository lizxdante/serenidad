# HU-03.1 — Bootstrap de FluxCD v2

## Descripción General

FluxCD es el motor GitOps pull-based de la plataforma. A diferencia de los modelos push donde las herramientas externas empujan cambios al cluster, FluxCD opera como un agente dentro del cluster que monitorea el repositorio Git y aplica los cambios declarativamente. Este modelo garantiza que el estado del cluster siempre converja con el estado declarado en Git.

El bootstrap instala 6 controladores en el namespace `flux-system`, crea una Deploy Key en GitLab, y establece la sincronización inicial. Adicionalmente se configura **SOPS + age** para que FluxCD pueda descifrar automáticamente los secretos almacenados cifrados en Git antes de aplicarlos al cluster.

### Controladores instalados

| Controlador | Función |
|---|---|
| `source-controller` | Monitorea fuentes externas: repositorios Git, registros de Helm, buckets OCI |
| `kustomize-controller` | Aplica manifiestos Kustomize al cluster, descifra SOPS |
| `helm-controller` | Gestiona releases de Helm a partir de declaraciones HelmRelease |
| `notification-controller` | Envía alertas y recibe webhooks externos |
| `image-reflector-controller` | Scannea registros de imágenes Docker |
| `image-automation-controller` | Actualiza automáticamente referencias de imágenes en Git (usado por CI/CD) |

## Ejecución Detallada

### T-03.1.1 — Pre-checks antes del bootstrap

```bash
source .envrc
export KUBECONFIG="$(pwd)/infra/clusters/hetzner-prod/kubeconfig"

# 1. Verificar que el cluster está disponible y tiene los recursos mínimos para FluxCD
flux check --pre
# Salida esperada:
# ► checking prerequisites
# ✓ Kubernetes 1.33.x >= 1.28.0
# ✓ prerequisites checks passed

# 2. Verificar que las credenciales de GitLab están configuradas
echo "GITLAB_TOKEN length: ${#GITLAB_TOKEN}"  # Debe ser > 20 caracteres
echo "GITLAB_USER: ${GITLAB_USER}"
echo "GITLAB_REPO: ${GITLAB_REPO}"

# 3. Verificar acceso al repositorio remoto con las credenciales
git ls-remote "https://oauth2:${GITLAB_TOKEN}@gitlab.com/${GITLAB_USER}/${GITLAB_REPO}.git" HEAD
# Debe mostrar el hash del commit HEAD sin errores 401/403
```

---

### T-03.1.2 — Ejecutar el bootstrap de FluxCD

```bash
# Bootstrap completo de FluxCD con integración a GitLab
# Este comando instala los 6 controladores, crea una Deploy Key en GitLab,
# y commitea la carpeta flux-system/ al repositorio

flux bootstrap gitlab \
  --owner="${GITLAB_USER}" \
  --repository="${GITLAB_REPO}" \
  --branch=main \
  --path=./infra/clusters/hetzner-prod \
  --personal \
  --components-extra=image-reflector-controller,image-automation-controller

# El proceso tarda entre 2 y 5 minutos
# Al completar, FluxCD habrá:
# 1. Instalado los 6 controladores en el namespace flux-system
# 2. Creado una Deploy Key en GitLab con acceso de lectura al repositorio
# 3. Commitado la carpeta infra/clusters/hetzner-prod/flux-system/ al repositorio
# 4. Iniciado la reconciliación del cluster con el repositorio
```

### T-03.1.3 — Verificar la sincronización inicial

```bash

# 2. Verificar que los 6 controladores están en Running

# helm-controller-xxx

# image-reflector-controller-xxx
# kustomize-controller-xxx

# source-controller-xxx

# 3. Verificar la fuente Git activa
flux get source git flux-system
# Debe mostrar el repositorio y la revisión del commit HEAD

# 4. Verificar la kustomization principal
flux get kustomization flux-system
# Debe mostrar: Ready True, y la revision del último commit
```

### T-03.1.4 — Configurar SOPS + age para decryption automático

FluxCD puede descifrar automáticamente los archivos SOPS al aplicar manifiestos al cluster.

> **Advertencia crítica:** La clave privada age que se genera aquí es el único medio de descifrar todos los secretos del repositorio. Su pérdida implica la necesidad de recrear todos los secretos. Realizar backup inmediato al Password Manager.

```bash
# 1. Crear el directorio de claves age
mkdir -p ~/.config/sops/age

# 2. Generar la clave asimétrica age
age-keygen -o ~/.config/sops/age/keys.txt

# Verificar la generación
cat ~/.config/sops/age/keys.txt
# Formato esperado:
# # created: 2026-...
# # public key: age1...
# AGE-SECRET-KEY-1...

# 3. Extraer la clave pública
AGE_PUBLIC_KEY=$(age-keygen -y ~/.config/sops/age/keys.txt)
echo "Clave pública age: ${AGE_PUBLIC_KEY}"
# Formato: age1xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx...

# 4. BACKUP CRÍTICO — HACER AHORA
echo "================================================================"
echo "BACKUP REQUERIDO: Copiar el siguiente contenido al Password Manager"
echo "Clave: serenidad-prod-age-private-key"
echo "================================================================"
cat ~/.config/sops/age/keys.txt
echo "================================================================"

# 5. Crear el secret de SOPS en el namespace flux-system
kubectl create secret generic sops-age \
  --from-file=age.agekey="${HOME}/.config/sops/age/keys.txt" \
  --namespace=flux-system

# Verificar que el secret fue creado
kubectl get secret sops-age -n flux-system
# Debe mostrar: sops-age   1      Xs

# 6. Parchear la Kustomization de flux-system para habilitar decryption
kubectl patch kustomization flux-system \
  --namespace flux-system \
  --type=merge \
  --patch='{
    "spec": {
      "decryption": {
        "provider": "sops",
        "secretRef": {"name": "sops-age"}
      }
    }
  }'

# Verificar que el patch fue aplicado
kubectl get kustomization flux-system -n flux-system -o json \
  | jq '.spec.decryption'
# Debe mostrar: {"provider": "sops", "secretRef": {"name": "sops-age"}}

# 7. Crear las reglas SOPS para el repositorio
mkdir -p infra/secrets/
cat > infra/secrets/.sops.yaml << EOF
creation_rules:
  - path_regex: infra/secrets/.*\.yaml\$
    encrypted_regex: ^(data|stringData)\$
    age: ${AGE_PUBLIC_KEY}
EOF

# Verificar el archivo creado
cat infra/secrets/.sops.yaml

# 8. Commitear y pushear la configuración SOPS
git add infra/secrets/.sops.yaml
git commit -m "feat(gitops): add SOPS age encryption rules for infra/secrets/"
git push origin main

# 9. Forzar reconciliación para que FluxCD aplique los cambios inmediatamente
flux reconcile kustomization flux-system --with-source

# Verificar que el estado es Ready con la nueva revisión
flux get kustomization flux-system
```
