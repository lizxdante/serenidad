# HU-03.1 — Bootstrap de FluxCD v2.x

## Descripción General
En esta historia de usuario, realizaremos el "bootstrap" (inicialización) de FluxCD en nuestro clúster de Kubernetes e integraremos nuestro repositorio de GitLab para que funcione como la única fuente de la verdad (Source of Truth). Además, instalaremos y configuraremos las herramientas criptográficas `sops` y `age` para permitir el cifrado de secretos (como tokens y contraseñas) directamente en nuestro repositorio público/privado de forma segura, siendo descifrados en automático al momento de ser aplicados dentro del clúster.

### ¿Qué herramientas y procesos tocamos?
1. **FluxCD CLI**: Interactúa con el clúster y la API de GitLab para instalar los controladores necesarios e inyectar *Deploy Tokens*.
2. **Age & SOPS**: `age` es una herramienta moderna de cifrado asimétrico (como GPG pero más simple). `SOPS` (Secrets OPerationS) es un editor de archivos cifrados de Mozilla. Juntos garantizan que el código GitOps no contenga contraseñas en texto claro.

## Ejecución Detallada

### T-03.1.1 — Chequeos Previos (Pre-checks)
Asegurémonos de tener los permisos y variables necesarios antes de lanzar la instalación.

```bash
# Entrar al monorepo y cargar variables de entorno
source .envrc

# 1. Verificar conectividad del clúster y soporte para FluxCD
flux check --pre

# Deberías ver un resultado indicando éxito, como:
# ✓ Kubernetes 1.33.x >= 1.28.0
# ✓ prerequisites checks passed

# 2. Verificar tener exportadas las credenciales del repositorio en tu sesión
# Deben estar en tu .envrc o exportadas manualmente
echo $GITLAB_TOKEN
echo $GITLAB_USER
echo $GITLAB_REPO # ej: serenidad-platform

# 3. Probar que podemos leer el repositorio remoto en la línea de comandos
git ls-remote https://oauth2:${GITLAB_TOKEN}@gitlab.com/${GITLAB_USER}/${GITLAB_REPO}.git
# Deberías ver una lista de referencias (ramas, tags) del repositorio remoto.
```

### T-03.1.2 — Ejecutar el Bootstrap de FluxCD
Esta tarea instalará los binarios (pods) en Kubernetes y creará un *Deploy Key* en GitLab.

```bash
# Lanzamos el comando principal. Esto demorará un un par de minutos.
flux bootstrap gitlab \
  --owner=${GITLAB_USER} \
  --repository=${GITLAB_REPO} \
  --branch=main \
  --path=./infra/clusters/hetzner-prod \
  --personal \
  --components-extra=image-reflector-controller,image-automation-controller

# Cuando finalice:
# 1. Flux creará la carpeta 'infra/clusters/hetzner-prod/flux-system/' en tu repositorio.
# 2. Hará un commit inicial conteniendo toda la declaración de sus propios componentes.
# 3. El clúster y GitLab estarán oficialmente enlazados.
```

### T-03.1.3 — Verificar Sincronización
Garantizar que todo se desplegó y está reconciliando de forma saludable.

```bash
# 1. Verificar estado global de recursos de Flux
flux get all
# El 'gitrepository' y 'kustomization' bajo flux-system deben decir 'Ready: True'

# 2. Verificar que los 6 controladores principales están 'Running'
kubectl get pods -n flux-system
# source-controller, kustomize-controller, helm-controller, notification-controller,
# image-reflector-controller y image-automation-controller deben estar operacionales.

# 3. Visualizar URL y rama monitoreada
flux get source git flux-system
```

### T-03.1.4 — Configurar SOPS+age para Descifrado
Para la gestión segura de contraseñas de Base de Datos y APIs, usamos SOPS y Age.
**PRECAUCIÓN CRÍTICA**: Al generar la clave `age`, su parte PRIVADA te permite recuperar todo accidente criptográfico en tu repo. Debes custodiarla como si fuera oro en tu Gestor de Contraseñas.

```bash
# 1. Generar la clave asimétrica "age" (si no existe la carpeta, crearla)
mkdir -p ~/.config/sops/age
age-keygen -o ~/.config/sops/age/keys.txt

# 2. Extraer la Clave Pública (empieza con 'age1...') y exportarla
export AGE_PUBLIC_KEY=$(grep -oP 'public key: \K.*' ~/.config/sops/age/keys.txt)
echo "Tu Clave Pública Age es: $AGE_PUBLIC_KEY"

# !! IMPORTANTE !!
# Abre el archivo de llave privada y copia su contenido textual a tu Gestor de Contraseñas (Bitwarden, 1Password):
cat ~/.config/sops/age/keys.txt
echo "Asegúrate de que la has copiado antes de continuar."

# 3. Inyectarle la llave Age como secreto dentro de Kubernetes para autorizar a Flux
kubectl create secret generic sops-age \
--from-file=age.agekey=${HOME}/.config/sops/age/keys.txt \
--namespace=flux-system

# 4. Modificar la configuración "kustomization" residente en el clúster para que entienda que usaremos sops con la llave inyectada.
# Este archivo ya está en tu repositorio git desde el Bootstrap.
cat <<EOF > infra/clusters/hetzner-prod/flux-system/kustomization.yaml
apiVersion: kustomize.toolkit.fluxcd.io/v1
kind: Kustomization
metadata:
  name: flux-system
  namespace: flux-system
spec:
  interval: 10m0s
  path: ./infra/clusters/hetzner-prod
  prune: true
  sourceRef:
    kind: GitRepository
    name: flux-system
  decryption:
    provider: sops
    secretRef:
      name: sops-age
EOF

# 5. Configurar el archivo raíz de encriptación '.sops.yaml'
# Definiremos que solo vamos a encriptar los valores ('data', 'stringData') y no las llaves, lo cual ayuda mucho a leer los diffs de Git.
mkdir -p infra/secrets/
cat <<EOF > infra/secrets/.sops.yaml
creation_rules:
  - path_regex: infra/secrets/.*\.yaml\$
    encrypted_regex: ^(data|stringData)\$
    age: ${AGE_PUBLIC_KEY}
EOF

# 6. Empujar (Commitear) todo al repositorio
git pull origin main
git add infra/clusters/hetzner-prod/flux-system/kustomization.yaml infra/secrets/.sops.yaml
git commit -m "feat(infra): enable SOPS age decryption rule for secrets tracking"
git push origin main
```
