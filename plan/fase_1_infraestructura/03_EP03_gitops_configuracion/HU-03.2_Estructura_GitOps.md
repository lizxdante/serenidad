# HU-03.2 — Estructura GitOps del Repositorio

## Descripción General

Para que FluxCD sepa qué desplegar y en qué orden, el directorio del cluster necesita un punto de entrada declarativo: un `kustomization.yaml` principal que referencia todas las subcarpetas de infraestructura y aplicaciones. Esta historia establece esa estructura jerárquica y prepara los directorios con sus kustomizations base.

La arquitectura de directorios sigue el patrón recomendado por FluxCD para monorepos:

```
infra/
├── clusters/
│   └── hetzner-prod/          ← Punto de entrada de FluxCD
│       ├── flux-system/       ← Autogenerado por bootstrap
│       └── kustomization.yaml ← ÍNDICE MAESTRO (esta HU)
├── infrastructure/            ← Componentes base del cluster
│   ├── hcloud-ccm/
│   ├── cert-manager/
│   ├── traefik/
│   ├── cnpg/
│   └── network-policies/
├── apps/                      ← Aplicaciones de dominio
│   ├── kratos/
│   └── iam-service/
└── secrets/                   ← Secretos SOPS (referenciados desde infra/ y apps/)
    ├── .sops.yaml
    └── README.md
```

## Ejecución Detallada

### T-03.2.1 — Crear el punto de entrada maestro del cluster

Este archivo es el único punto que FluxCD monitorea directamente. A partir de él, se despliegan todos los demás componentes en el orden declarado.

```bash
source .envrc

cat > infra/clusters/hetzner-prod/kustomization.yaml << 'EOF'
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization

# FluxCD aplica estos recursos en orden secuencial.
# Los componentes de infraestructura deben ir ANTES que las aplicaciones.
resources:
  # Controladores de FluxCD (autogenerado por bootstrap)
  - flux-system/

  # Capa 1: Infraestructura base del cluster
  - ../../infrastructure/hcloud-ccm/           # CCM de Hetzner
  - ../../infrastructure/cert-manager/         # Gestión automática de certificados TLS
  - ../../infrastructure/traefik/              # Ingress controller y proxy reverso
  - ../../infrastructure/cnpg/                 # Operador PostgreSQL CloudNativePG
  - ../../infrastructure/network-policies/     # Zero-Trust networking (EP-10)

  # Capa 2: Aplicaciones de dominio (Fase 1)
  - ../../apps/kratos/                         # Ory Kratos: gestión de identidades
  - ../../apps/iam-service/                    # IAM Domain Service (JWT, Outbox)

  # Capa 3: Fase 2 (comentado hasta estar disponible)
  # - ../../infrastructure/nats/               # Event Bus (Fase 2)
  # - ../../apps/scheduling-service/           # Servicio de Agendamiento (Fase 2)
  # - ../../apps/clinical-service/             # Servicio de Historia Clínica (Fase 2)

  # Capa 4: Fase 3 (comentado)
  # - ../../apps/billing-service/              # Servicio de Facturación (Fase 3)
  # - ../../apps/openfga/                      # Motor de autorización ReBAC (Fase 3)
EOF
```

### T-03.2.2 — Crear kustomizations base para cada componente

Cada directorio de infraestructura y aplicación necesita su propio `kustomization.yaml` para que Kustomize sepa qué archivos incluir.

```bash
# hcloud-ccm: en HU-02.4 ya fue desplegado manualmente
# Este kustomization permite que FluxCD lo gestione en el futuro
cat > infra/infrastructure/hcloud-ccm/kustomization.yaml << 'EOF'
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
resources:
  # Los manifiestos del CCM se instalan via kubectl apply en HU-02.4
  # Este placeholder permite que FluxCD monitoree el namespace
EOF

# cert-manager
cat > infra/infrastructure/cert-manager/kustomization.yaml << 'EOF'
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
resources:
  - helmrepository.yaml
  - helmrelease.yaml
  - clusterissuers.yaml
EOF

# traefik
cat > infra/infrastructure/traefik/kustomization.yaml << 'EOF'
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
resources:
  - helmrepository.yaml
  - helmrelease.yaml
  - middlewares.yaml
EOF

# cnpg
cat > infra/infrastructure/cnpg/kustomization.yaml << 'EOF'
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
namespace: serenidad-data
resources:
  - helmrepository.yaml
  - helmrelease.yaml
  - cluster.yaml
  - scheduled-backup.yaml
  # Secretos cifrados con SOPS (se añaden cuando estén creados):
  # - ../../secrets/cnpg-serenidad-admin-creds.yaml
  # - ../../secrets/cnpg-b2-credentials.yaml
EOF

# network-policies
cat > infra/infrastructure/network-policies/kustomization.yaml << 'EOF'
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
resources:
  - allow-rules.yaml
  - deny-all-default.yaml
EOF

# kratos
cat > infra/apps/kratos/kustomization.yaml << 'EOF'
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
resources:
  - helmrepository.yaml
  - helmrelease.yaml
  - ingressroute.yaml
  # - ../../secrets/kratos-secrets.yaml  # Habilitar cuando esté creado
EOF

# iam-service
cat > infra/apps/iam-service/kustomization.yaml << 'EOF'
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
resources:
  - deployment.yaml
  - service.yaml
  - ingressroute.yaml
  # - ../../secrets/iam-service-secrets.yaml      # Habilitar cuando esté creado
  # - ../../secrets/gitlab-registry-secret.yaml   # Habilitar cuando esté creado
EOF
```

### T-03.2.3 — Documentar el inventario de secretos en el directorio secrets/

```bash
cat > infra/secrets/README.md << 'EOF'
# Gestión de Secretos — SOPS + age

Este directorio contiene los secretos de la plataforma cifrados con SOPS y age.

## Regla de oro

**Nunca hacer commit de valores en texto plano en este directorio.**
Usar el script `scripts/encrypt-secret.sh` para cifrar antes de commitear.

## Inventario de secretos

| Archivo | Namespace destino | Descripción |
|---|---|---|
| `iam-service-secrets.yaml` | `serenidad-core` | Claves JWT Ed25519 privada y pública |
| `kratos-secrets.yaml` | `serenidad-core` | Cookie secret, cipher secret, RESEND_API_KEY |
| `cnpg-serenidad-admin-creds.yaml` | `serenidad-data` | Credenciales de administrador de PostgreSQL |
| `cnpg-b2-credentials.yaml` | `serenidad-data` | Application Key de Backblaze B2 para WAL archiving |
| `gitlab-registry-secret.yaml` | `serenidad-core` | dockerconfigjson con el Deploy Token de GitLab |

## Cómo crear un nuevo secreto

```bash
# Uso: ./scripts/encrypt-secret.sh <namespace> <nombre-secret> KEY=valor [KEY2=valor2 ...]
./scripts/encrypt-secret.sh serenidad-core mi-nuevo-secreto \
  API_KEY=valor_sensible \
  OTRO_CAMPO=otro_valor

# Commitear el archivo cifrado
git add infra/secrets/mi-nuevo-secreto.yaml
git commit -m "feat(secrets): add mi-nuevo-secreto encrypted with SOPS"
git push origin main
```

## Cómo descifrar localmente para verificar

```bash
sops -d infra/secrets/mi-nuevo-secreto.yaml
```
EOF
```

### T-03.2.4 — Commitear y verificar la estructura

```bash
# Agregar todos los nuevos archivos
git add infra/clusters/hetzner-prod/kustomization.yaml
git add infra/infrastructure/*/kustomization.yaml
git add infra/apps/*/kustomization.yaml
git add infra/secrets/README.md

git commit -m "chore(gitops): establish directory structure and cluster kustomization entrypoint"
git push origin main

# Forzar reconciliación
flux reconcile kustomization flux-system --with-source

# Verificar el estado (no debe haber errores fatales)
# Algunos componentes pueden fallar porque los manifiestos de infraestructura aún no existen
flux get kustomizations -A
```
