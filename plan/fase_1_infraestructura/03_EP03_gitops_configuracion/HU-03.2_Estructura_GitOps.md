# HU-03.2 — Estructura GitOps del Repositorio

## Descripción General
Para un esquema ordenado de GitOps, el directorio principal del clúster necesita un "master planner". Kubernetes (mediante FluxCD) recurrirá a un archivo `kustomization.yaml` ubicado en la carpeta central para determinar qué carpetas satélite debe vigilar, cargar y desplegar, y en qué secuencia jerárquica. Aquí "enrutaremos" nuestra infraestructura compartida, las aplicaciones de dominio y nuestros secretos cifrados.

### ¿Qué componentes tocamos?
1. **Estructura del Repositorio Git:** Definiremos la arquitectura final de los directorios para infraestructura y *apps*.
2. **Kustomize (`kustomization.yaml`)**: Crearemos el punto de entrada principal para que Flux sepa recursivamente dónde buscar manifiestos yaml.

---

## Ejecución Detallada

### T-03.2.1 — Crear Estructura de Directorios (Infraestructura y Apps)
Ejecutaremos una serie de comandos en nuestra máquina local dentro del repositorio principal (`serenidad-platform`) para generar el árbol de archivos.

```bash
# Navegar a la raíz del monorepo si no te encuentras ahí.
cd /ruta/hacia/tu/monorepo/serenidad-platform/

# 1. Crear directorios para Infraestructura (Herramientas base que darán soporte a apps)
mkdir -p infra/infrastructure/hcloud-ccm/
mkdir -p infra/infrastructure/cert-manager/
mkdir -p infra/infrastructure/traefik/
mkdir -p infra/infrastructure/cnpg/
mkdir -p infra/infrastructure/network-policies/

# Añadimos un .gitkeep a cada carpeta vacía para que Git permita subirlas.
touch infra/infrastructure/hcloud-ccm/.gitkeep
touch infra/infrastructure/cert-manager/.gitkeep
touch infra/infrastructure/traefik/.gitkeep
touch infra/infrastructure/cnpg/.gitkeep
touch infra/infrastructure/network-policies/.gitkeep

# 2. Crear directorios para Aplicaciones propias y de terceros (Dominio/Negocio)
mkdir -p infra/apps/kratos/
mkdir -p infra/apps/iam-service/

touch infra/apps/kratos/.gitkeep
touch infra/apps/iam-service/.gitkeep
```

### T-03.2.2 — Generar Referencia `kustomization.yaml` Central
Configuraremos el "Índice" en el nivel general del clúster. Como algunas piezas aún no existen temporalmente dejaremos algunas líneas comentadas o solo como preaviso arquitectónico, pero el andamiaje estará formalmente listo.

```bash
# Crear el archivo kustomization integrador
cat <<EOF > infra/clusters/hetzner-prod/kustomization.yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization

# Se indica explícitamente a Kustomize dónde encontrar los recursos.
# Nota: La sintaxis de directorios debe ser precisa (rutas relativas al archivo kustomization.yaml).
resources:
  - flux-system/                         # Autogenerado por el bootstrap inicial
  - ../../infrastructure/hcloud-ccm/     # Controladores del Proveedor Hetzner
  - ../../infrastructure/cert-manager/   # Administrador de certificados TLS/SSL
  - ../../infrastructure/traefik/        # Ingress Controller (Enrutamiento HTTP)
  - ../../infrastructure/cnpg/           # Operador de postgres CloudNativePG
  - ../../apps/kratos/                   # Sistema de Identidad Cloud Native
  - ../../apps/iam-service/              # Servicio interno IAM (Custom)
EOF
```

### T-03.2.3 — Documentar Secretos Destinados a Cifrado
Para mantener la visibilidad a todo el equipo de ingenieros, listaremos (a modo de documentación README) qué secretos manejaremos en la capa de secretos en una fase posterior.

```bash
# El directorio /infra/secrets ya existe (lo creamos en HU-03.1). Proveemos un README explicativo.
cat <<EOF > infra/secrets/README.md
# Gestión Central de Secretos (SOPS+Age)

Todos los directorios de infraestructura y aplicaciones referenciarán a los archivos de esta carpeta. 
**Regla de oro:** Jamás hacer commit de valores en texto plano aquí. Usa el script \`encrypt-secret.sh\`.

## Inventario Referencial Futuro:
1. \`iam-service-secrets.yaml\` — JWT Ed25519 keys de backend.
2. \`kratos-secrets.yaml\` — Cookie auth keys y secret ciphers de Kratos.
3. \`cnpg-serenidad-admin-creds.yaml\` — Cuentas administrativas base de datos PostgreSQL.
4. \`cnpg-b2-credentials.yaml\` — Acceso a Backblaze B2 (Bucket S3 backups).
5. \`gitlab-registry-secret.yaml\` — Archivo \`dockerconfigjson\` de acceso a contenedores privados en GitLab.
EOF
```

### T-03.2.4 — Commitear y Reconciliar en Kubernetes
Llevamos todos estos cambios hacia nuestro branch `main` y obligamos a Flux a evaluar nuestros cambios en vez de esperar su temporizador habitual (polling interval de 10 min).

```bash
# Agregar cambios subyacentes
git add infra/
git commit -m "chore(gitops): setup full folder skeleton and central kustomization entrypoint"
git push origin main

# Confirmar la ruta del commit
git log --oneline -1

# Solicitar explícitamente a Flux reconciliar el entorno base con el repositorio Git modificado:
flux reconcile kustomization flux-system --with-source

# Validar que los objetos han sido procesados. 
# Si bien muchas carpetas están vacías, esto confirmará el parseo del kustomization central.
flux get kustomizations -A 
# Verás un estado de Ready, con revision apuntando a tu última hash de commit en main, libre de errores irrecuperables.
```
