# HU-03.3 — SOPS + age: Cifrado de Secretos GitOps

## Descripción General
Tener SOPS y Age instalados es solo la mitad del trabajo. Debemos "operacionalizar" el uso cotidiano de la encriptación creando una utilidad (script) simple para que todo miembro técnico (incluso con breves conocimientos analíticos o bash) pueda inyectar contraseñas al repositorio de manera encriptada y rápida.
Finalmente validaremos el viaje completo (End-to-End) de "Texto Loco -> Git Cifrado -> Cluster K8S Resuelto".

---

## Ejecución Detallada

### T-03.3.1 — Creación del Script Utilitario de Cifrado
Para no requerir escribir largos y dolorosos manifiestos YAML y correr comandos de validación para cada nueva clave a registrarse, programaremos una solución Bash rápida que empiece a empaquetar por nosotros.

```bash
mkdir -p scripts/

# Crear el core script del utilitario
cat <<'EOF' > scripts/encrypt-secret.sh
#!/usr/bin/env bash
set -e

# Imprimir instrucciones simples en caso de mal uso
if [ "$#" -lt 3 ]; then
  echo "Usage: $0 <namespace> <secret-name> <key>=<value> [<key2>=<value2> ...]"
  echo "Example: $0 database app-db-cr DB_PASSWORD=ultrasecret"
  exit 1
fi

NAMESPACE=$1
SECRET_NAME=$2
shift 2

# Verificación de validación de contexto para no fallar despues.
if [ ! -f "infra/secrets/.sops.yaml" ]; then
  echo "Error: infra/secrets/.sops.yaml is missing. Run from monorepo root."
  exit 1
fi

DEST_FILE="infra/secrets/${SECRET_NAME}.yaml"

# Construyendo dinámicamente un comando de kubectl usando "--dry-run"
# Este truco obliga a kubectl a crear el objeto YAML perfectamente formateado sin llegar jamas enviarlo al clúster directamente.
CMD="kubectl create secret generic ${SECRET_NAME} --namespace=${NAMESPACE}"

for pair in "$@"; do
  CMD="${CMD} --from-literal=${pair}"
done

CMD="${CMD} --dry-run=client -o yaml"

echo "Generando manifiesto base y cifrando fuertemente..."
# Canalizamos la salida del kubectl hacia la herramienta de Mozilla SOPS
eval ${CMD} | sops --encrypt --mac-only-encrypted - > ${DEST_FILE}

echo "Éxito! Archivo de secreto encriptado generado en: ${DEST_FILE}"
EOF

# Otorgar los atributos correctos de ejecución.
chmod +x scripts/encrypt-secret.sh

# Commitear al repositorio fuente
git add scripts/encrypt-secret.sh
git commit -m "feat(scripts): add utility script to encrypt K8s secrets via SOPS"
git push origin main
```

### T-03.3.2 — Test de Integración: End-to-End
Probaremos el generador enviando un secreto y pidiendo a Kubernetes que nos devuelva el texto plano demostrando el proceso de reversión.

```bash
# 1. Utilizar nuestro nuevo script para crear un secreto bobo en la carpeta "default"
./scripts/encrypt-secret.sh default test-sops-secret TEST_KEY=hello_world_supersecret

# 2. Revisa el archivo generado usando Cat (localmente). Notarás todo en 'data' encriptado (caracteres inentendibles)
cat infra/secrets/test-sops-secret.yaml

# 3. Haz la reversión de muestra usando tu propia computadora (local SOPS decode)
sops -d infra/secrets/test-sops-secret.yaml
# Si logra descifrar, nuestra clave Age generada en la HU anterior está funcionando.

# 4. Enviar nuestro "secreto bobo fuertemente blindado" al monorepo Git.
git add infra/secrets/test-sops-secret.yaml
git commit -m "test(sops): verify sops end-to-end decryption pipeline"
git push origin main

# 5. Forzamos la actualización o reconciliación en la nube:
flux reconcile kustomization flux-system --with-source

# 6. Demostración en vivo en Kubernetes de que fue traducido nuevamente:
kubectl get secret test-sops-secret -n default -o jsonpath='{.data.TEST_KEY}' | base64 -d
# Esto debe imprimir en la consola pura: hello_world_supersecret. 

# 7. Borrar vestigios del test porque ya validamos y estamos contentos
git rm infra/secrets/test-sops-secret.yaml
git commit -m "test(sops): clean up test secret"
git push origin main

# Al reconciliar de nuevo, FluxCD lo eliminará del sistema y del cluster ya que fue abstraido del repositorio
flux reconcile kustomization flux-system --with-source
```

### T-03.3.3 — Plantillas Básicas para Consumir Secretos
Pre-armaremos los kustomization indexadores de carpetas a las que el clúster se adueñará en las próximas Épicas para indicarles cómo acceder a contraseñas.

```bash
# CNPG Kustomization Template
cat <<EOF > infra/infrastructure/cnpg/kustomization.yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
resources:
  # Descomentar a medida que los secretos se provean.
  # - ../../secrets/cnpg-serenidad-admin-creds.yaml
  # - ../../secrets/cnpg-b2-credentials.yaml
EOF

# IAM Service Kustomization Template
cat <<EOF > infra/apps/iam-service/kustomization.yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
resources:
  # Descomentar a medida que los secretos se provean.
  # - ../../secrets/iam-service-secrets.yaml
  # - ../../secrets/gitlab-registry-secret.yaml
EOF

# Aseguramos el esqueleto en version control
git add infra/infrastructure/cnpg/kustomization.yaml
git add infra/apps/iam-service/kustomization.yaml
git commit -m "chore(gitops): lay out kustomization secret loading placeholders"
git push origin main
```

### T-03.3.4 — Verificación en Logs (Troubleshooting proactivo)
En caso de que en un futuro los secretos no apunten o surjan fallas de decodificación, el primer sitio a mirar se listan en estos logs.

```bash
# Esto inspeccionará al controlador de kustomize de flux para visualizar reportes de decodificación asimétrica (sops|decrypt|age).
kubectl logs deployment/kustomize-controller -n flux-system | grep -i -E "sops|decrypt|age"

# Si no hay outputs sospechosos o "errors", entonces el viaje de desciframiento desde GitLab hasta K8s transcurre saludable.
```
