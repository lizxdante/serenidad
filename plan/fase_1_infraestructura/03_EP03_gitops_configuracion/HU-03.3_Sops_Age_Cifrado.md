# HU-03.3 — SOPS + age: Operacionalización del Cifrado de Secretos

## Descripción General

La configuración de SOPS y age en HU-03.1 establece la infraestructura criptográfica. Esta historia operacionaliza el uso cotidiano mediante un script utilitario que encapsula el proceso de generación y cifrado de secretos de Kubernetes, y valida el flujo completo end-to-end (local → Git → cluster).

El flujo de un secreto en este sistema es:

```
Texto plano (local) → SOPS cifra → Git (cifrado) → FluxCD + kustomize-controller → K8s Secret (descifrado)
```

## Ejecución Detallada

### T-03.3.1 — Crear el script utilitario de cifrado

```bash
cat > scripts/encrypt-secret.sh << 'SCRIPT'
#!/usr/bin/env bash
# encrypt-secret.sh — Crea y cifra un Kubernetes Secret con SOPS + age
# Uso: ./scripts/encrypt-secret.sh <namespace> <nombre-secret> KEY=valor [KEY2=valor2 ...]
# Ejemplo: ./scripts/encrypt-secret.sh serenidad-core db-credentials DB_PASS=secreto123

set -euo pipefail

if [[ "$#" -lt 3 ]]; then
  echo "Uso: $0 <namespace> <nombre-secret> <KEY=valor> [<KEY=valor> ...]"
  echo ""
  echo "Ejemplos:"
  echo "  $0 serenidad-core jwt-keys JWT_PRIVATE=... JWT_PUBLIC=..."
  echo "  $0 serenidad-data db-admin username=admin password=secret123"
  exit 1
fi

NAMESPACE="$1"
SECRET_NAME="$2"
shift 2

# Verificar que se está en la raíz del monorepo
SOPS_CONFIG="infra/secrets/.sops.yaml"
if [[ ! -f "${SOPS_CONFIG}" ]]; then
  echo "Error: '${SOPS_CONFIG}' no encontrado."
  echo "Ejecutar este script desde la raíz del monorepo serenidad-platform."
  exit 1
fi

# Verificar que kubectl está disponible
if ! command -v kubectl &>/dev/null; then
  echo "Error: kubectl no está instalado o no está en el PATH."
  exit 1
fi

# Verificar que sops está disponible
if ! command -v sops &>/dev/null; then
  echo "Error: sops no está instalado o no está en el PATH."
  exit 1
fi

# Construir argumentos --from-literal para kubectl
KUBECTL_ARGS=()
for pair in "$@"; do
  # Validar formato KEY=valor
  if [[ "$pair" != *"="* ]]; then
    echo "Error: El argumento '${pair}' no tiene el formato KEY=valor."
    exit 1
  fi
  KUBECTL_ARGS+=("--from-literal=${pair}")
done

DEST_FILE="infra/secrets/${SECRET_NAME}.yaml"

echo "Generando y cifrando secret '${SECRET_NAME}' en namespace '${NAMESPACE}'..."

# Generar el manifiesto YAML del Secret con kubectl --dry-run
# Luego cifrarlo con SOPS usando la configuración en .sops.yaml
kubectl create secret generic "${SECRET_NAME}" \
  --namespace="${NAMESPACE}" \
  "${KUBECTL_ARGS[@]}" \
  --dry-run=client \
  --output=yaml \
  | sops \
    --encrypt \
    --input-type=yaml \
    --output-type=yaml \
    --config="${SOPS_CONFIG}" \
    /dev/stdin \
  > "${DEST_FILE}"

echo "✓ Secret cifrado guardado en: ${DEST_FILE}"
echo ""
echo "Próximos pasos:"
echo "  1. Verificar el cifrado: sops -d ${DEST_FILE}"
echo "  2. Agregar referencia en el kustomization.yaml del componente"
echo "  3. Commitear: git add ${DEST_FILE} && git commit -m 'feat(secrets): add ${SECRET_NAME}'"
SCRIPT

chmod +x scripts/encrypt-secret.sh

# Verificar que el script es ejecutable
ls -la scripts/encrypt-secret.sh

# Commitear el script
git add scripts/encrypt-secret.sh
git commit -m "feat(scripts): add encrypt-secret.sh utility for SOPS-encrypted K8s secrets"
git push origin main
```

### T-03.3.2 — Verificar el flujo end-to-end con un secret de prueba

```bash
source .envrc
export KUBECONFIG="$(pwd)/infra/clusters/hetzner-prod/kubeconfig"

# 1. Crear un secret de prueba cifrado
./scripts/encrypt-secret.sh default test-sops-validation \
  TEST_KEY=hello_serenidad \
  TEST_VALUE=verification_ok

# 2. Verificar que el archivo está cifrado (los valores en data/stringData son ilegibles)
echo "=== Contenido cifrado en Git ==="
cat infra/secrets/test-sops-validation.yaml
# El campo "data:" debe contener valores base64 cifrados por SOPS, no texto plano

# 3. Verificar que se puede descifrar localmente con la clave age
echo ""
echo "=== Contenido descifrado localmente ==="
sops -d infra/secrets/test-sops-validation.yaml
# Debe mostrar: TEST_KEY: hello_serenidad, TEST_VALUE: verification_ok en texto plano

# 4. Agregar referencia al kustomization de flux-system temporalmente para la prueba
# En la práctica, cada secret se referencia en el kustomization del componente que lo usa
# Para esta prueba, lo aplicamos directamente
kubectl apply -f <(sops -d infra/secrets/test-sops-validation.yaml)

# O alternativamente, pushear y esperar a que FluxCD lo aplique:
git add infra/secrets/test-sops-validation.yaml
git commit -m "test(sops): add validation secret — will be deleted after verification"
git push origin main
flux reconcile kustomization flux-system --with-source
sleep 30  # Esperar reconciliación

# 5. Verificar que FluxCD aplicó el secret al cluster correctamente
kubectl get secret test-sops-validation -n default
kubectl get secret test-sops-validation -n default \
  -o jsonpath='{.data.TEST_KEY}' | base64 -d
# Debe imprimir: hello_serenidad

# 6. Limpiar el secret de prueba
git rm infra/secrets/test-sops-validation.yaml
git commit -m "test(sops): remove SOPS end-to-end validation secret"
git push origin main
flux reconcile kustomization flux-system --with-source
kubectl delete secret test-sops-validation -n default --ignore-not-found
```

### T-03.3.3 — Verificar logs de descifrado en el kustomize-controller

```bash
# Verificar que el controlador está procesando SOPS sin errores
kubectl logs deployment/kustomize-controller \
  -n flux-system \
  --tail=100 \
  | grep -iE "sops|decrypt|age"

# Resultado esperado: líneas informativas sobre decryption, sin errores
# Si hay errores de tipo "failed to decrypt": verificar que el secret sops-age
# contiene la clave privada correcta
```

**Troubleshooting del descifrado:**

```bash
# Verificar que el secret sops-age existe y tiene la clave age
kubectl get secret sops-age -n flux-system -o json | jq '.data | keys'
# Debe mostrar: ["age.agekey"]

# Verificar que la clave pública en .sops.yaml coincide con la clave privada en el cluster
REPO_PUBKEY=$(grep "age:" infra/secrets/.sops.yaml | awk '{print $2}')
CLUSTER_PUBKEY=$(kubectl get secret sops-age -n flux-system \
  -o jsonpath='{.data.age\.agekey}' | base64 -d | grep "public key:" | awk '{print $4}')
echo "Clave pública en .sops.yaml: ${REPO_PUBKEY}"
echo "Clave pública en cluster:    ${CLUSTER_PUBKEY}"
# Deben ser idénticas
```
