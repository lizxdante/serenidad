# HU-08.1 — BFF: Cloudflare Workers y Hono v4.x

## Descripción General
Para evitar exponer nuestros microservicios internos directamente a internet y sufrir posibles penalizaciones de latencia o problemas CORS complejos con el Frontend web, estableceremos un **BFF (Backend for Frontend)** habitando en la *Edge Network* de Cloudflare. 
Este servidor hiper-ligero será programado en TypeScript usando el framework enrutador `Hono` y será capaz de descargar de trabajo al backend (ej: Verificará la firma criptográfica de los *Tokens JWT* en el mismo nodo geográfico del usuario antes de dejarlos pasar al VPS de Hetzner).

---

## Ejecución Detallada

### T-08.1.1 — Inicializar Proyecto Serverless
Construiremos la arquitectura base requerida por la computadora distribuida de Cloudflare (Workers) en vez de en contenedores típicos.

```bash
# Regresa a la raíz de tu monorepo
mkdir -p apps/bff
cd apps/bff

# 1. Utilizar Bun (runtime veloz equivalente a node) para inicializar plantilla Hono
bun create hono@latest . --template cloudflare-workers

# 2. Instalar el empaquetado verificador criptográfico JSON Web Token y actualizar hono
bun add hono@^4.0.0 jose
```

### T-08.1.2 — Definir la Plantilla del Manifiesto de Despliegue (wrangler)
`wrangler` es la CLI de Cloudflare. Configuraremos su archivo `.toml` para indicar bajo qué dominio debe interceptar llamadas.

```bash
cat <<EOF > wrangler.toml
name = "serenidad-bff"
main = "src/index.ts"
compatibility_date = "2026-04-01"
compatibility_flags = ["nodejs_compat"]

[vars]
BACKEND_URL = "https://api.sereni.dad"
ENVIRONMENT = "production"
JWT_ISSUER = "iam-service.sereni.dad"
JWT_AUDIENCE = "sereni.dad-services"

[[routes]]
pattern = "api.sereni.dad/bff/*"
zone_name = "sereni.dad"
EOF
```

### T-08.1.3 y T-08.1.4 — Implementar Index.ts y Middleware JWT 
Acá definimos las reglas de intercepción: El Worker será transparente (Proxy-Pass) cuando se hable con Ory Kratos para inicio de sesión, pero para las consultas privadas, verificará el token usando la llave asimétrica, inyectando cabeceras de confianza `X-User-ID`, `X-User-Role`, `X-Tenant-ID`.

```bash
# Dado que el código completo TS excede este manual infraestructural, 
# se detalla el esqueleto central:
cat <<'EOF' > src/index.ts
import { Hono } from 'hono';
import { secureHeaders } from 'hono/secure-headers';
import { cors } from 'hono/cors';

type Bindings = {
  BACKEND_URL: string;
  JWT_PUBLIC_KEY_ED25519: string;
}

const app = new Hono<{ Bindings: Bindings }>()

// Aplicar Cross-Origin Resource Sharing exclusivamente para nuestro Frontal
app.use('*', secureHeaders());
app.use('*', cors({
  origin: 'https://app.sereni.dad',
  allowHeaders: ['Authorization', 'Content-Type']
}));

// Route Libre: Control de Salud 
app.get('/health', (c) => c.json({ status: 'ok', service: 'bff' }));

// Route Libre: Dejar pasar los flujos de Passkey de Ory Kratos tal como vienen
app.all('/auth/*', async (c) => {
   // Lógica de proxy fetch(c.env.BACKEND_URL + c.req.path)
   return new Response("Not configured in outline", {status: 501})
});

// Route Protegido: Evaluar usando 'jose' jwt verification, extraer identity
// claims, y reenviar al backend real con X-Headers limpios.
app.all('/api/*', async (c) => {
   // middleware logic
   return new Response("Not configured in outline", {status: 501})
});

export default app;
EOF

# Validar que TypeScript no llore
bun run tsc --noEmit
```

### T-08.1.5 — Configurar Secrets del Trabajador de Borde (Edge)
Tu llave pública de Ed25519 jamás debe escribirse en texto plano en el repositorio GitHub. Lo enviaremos herméticamente usando la herramienta Cloudflare. Necesitarás consultar tu gestor de contraseñas por esa llave que creamos en la Fase EP07.

```bash
# Comando interactivo de Cloudflare CLI (ingresará en tu consola un prompt esperando pegar el secreto).
# Asegúrate de haber hecho login local con `wrangler login` previo a esto (HU-01.1).
wrangler secret put JWT_PUBLIC_KEY_ED25519
# Pega tu valor multilínea "-----BEGIN PUBLIC KEY----- ..." y oprime Enter.
```

### T-08.1.6 y T-08.1.7 — Publicar Worker y Validar Tuberías
Enviaremos el programa a los servidores CDN mundiales y revisaremos respuesta.

```bash
# Empaquetado minificado y envío atómico
wrangler deploy

# Test 1: Verificar accesibilidad del subdominio 
curl https://api.sereni.dad/bff/health

# Test 2: Ingrese directo tratando de ver datos sensibles simulando un cliente malicioso sin TOKEN
curl https://api.sereni.dad/bff/api/iam/whoami 
# Deberías recibir 401 Unauthorized desde Cloudflare directamente, observando que ni si quiera hizo 'ping' a tu VPS.
```
