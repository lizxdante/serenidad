# HU-08.2 — Single Page Web (SPA) con Qwik v2.0 en Cloudflare Pages

## Descripción General
Llegó el turno de la visual del usuario final (Paciente o Doctor). Para ofrecer latencias menores a 100 milisegundos en el primer pintado visual ("Time To Interactive"), la directiva eligió el ultra-moderno entorno **Qwik v2.0**.
Esta aplicación alojará los formularios *Passwordless*, guardará localmente los JWT y enrutará la experiencia de usuario bajo el dominio `app.sereni.dad`.

---

## Ejecución Detallada

### T-08.2.1 — Andamiaje del Árbol de UI Web
Utilizaremos las más recientes dependencias inyectadas mediante el runtime `bun` e inicializaremos la estructura enfocada en Páginas Estáticas.

```bash
# Regresando a la raiz
mkdir -p apps/web
cd apps/web

# Inicialización Qwik, asegurándonos indicar el template adaptador de nuestro proveedor.
bun create qwik@latest . --template cloudflare-pages

# Para cumplir el mandato de V-16 (Decisiones Técnicas), forzamos TypeScript 6.0
bun add -D typescript@^6.0.0

# Verificamos que los paquetes apunten al dominio nuevo `@qwik.dev` (y no el antiguo @builder.io)
grep "@qwik.dev" package.json

# Testeamos compilación local agresiva. El output debe depositar el HTML y JavaScript en 'dist/' 
bun run build 
```

### T-08.2.2 — Configurar Entorno en Cloudflare Pages
Crearemos la reserva del sub-proyecto en tu cuenta Cloudflare para que conozca sobre `serenidad-web`.

```bash
# Instanciamos el proyecto sin tener que usar el Dashboard Gráfico
wrangler pages project create serenidad-web --production-branch main

# Proveerle variables sensibles para que el front end sepa dónde hacer fetch()
# 1. Apuntar a Kratos (Motor Auth):
wrangler pages secret put VITE_KRATOS_URL --project-name serenidad-web # Val= https://api.sereni.dad/auth

# 2. Apuntar al BFF (Edge Backend):
wrangler pages secret put VITE_API_BASE_URL --project-name serenidad-web # Val= https://api.sereni.dad/bff
```

### T-08.2.3 y T-08.2.4 — Implementaciones Específicas de SPA Core
Aunque esto atañe al lado de la ingeniería Frontend, definimos infraestructuralmente qué páginas se exigirán antes de pasar QA:

1. **Flujo Cero Contraseñas:** Páginas `/register` y `/login` deberán invocar los métodos asíncronos nativos `Kratos WebAuthn/Passkey JavaScript`.
2. **Ciclo Catch-Exchange:** Cuando Kratos responde afirmativamente a un login, redirige internamente a tu frontend; aquí el Interceptor debe apresar la sesión HTTP-only local y empujarla inmediatamente como `POST` a nuestro endpoint backend `/api/iam/token/exchange` descrito en EP-07. Luego almacenar el Token JWT crudo provisto en `sessionStorage`.
3. **Escudos a Rutas Sensibles (Guards):** El `/dashboard` o `/settings` deben contener Hooks que detecten si el `sessionStorage` carece del Token Ed25519 de sesión, y forzar la re-navegación directa a `/login`.

### T-08.2.5 — Despliegue Manual y Promoción
Envío al CDN Global. En Sprints subsecuentes (EP-09) esto se automatizará ante cada Commit (CI/CD GitOps), pero validaremos manualmente para asegurar que los engranes giran sanos.

```bash
# Estar situado en /apps/web, correr compilador
bun run build

# Subir los crudos 'dist/' hacia tu proyecto productivo 
wrangler pages deploy dist/ --project-name serenidad-web --branch main

# Cloudflare arrojará un alias genérico (ej. serenidad-web.pages.dev). 
# Puedes enlazar manualmente app.sereni.dad a través del Panel DNS de Cloudflare a este alias.
```
