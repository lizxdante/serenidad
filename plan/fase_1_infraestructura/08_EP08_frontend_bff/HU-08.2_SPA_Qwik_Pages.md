# HU-08.2 — SPA con Qwik v2.0 en Cloudflare Pages

## Descripción General

La interfaz de usuario de la plataforma es una **Single Page Application** construida con **Qwik v2.0**, desplegada en Cloudflare Pages. Qwik 2 introduce el paradigma de **resumability** — el servidor serializa el estado completo de la aplicación en el HTML, y el navegador "reanuda" donde el servidor dejó, sin necesidad de re-ejecutar o re-hidratar el JavaScript.

Esto resulta en:
- **Time to Interactive (TTI) ≈ 0ms** — sin hidratación completa
- **Lazy loading radical** — solo el JavaScript del componente visible se descarga
- **Score de Lighthouse ≥ 95** en Performance

**Ejemplo de componente de login con Qwik v2:**

```typescript
// src/routes/login/index.tsx
import { component$, useSignal, $ } from '@qwik.dev/qwik'
import { routeLoader$, Form, useNavigate } from '@qwik.dev/router'
import type { DocumentHead } from '@qwik.dev/router'

// routeLoader$: se ejecuta en el servidor, los datos están disponibles antes
// de que se renderice el componente (sin waterfalls)
export const useLoginFlow = routeLoader$(async (requestEvent) => {
  const kratosUrl = requestEvent.env.get('VITE_KRATOS_URL')
  if (!kratosUrl) throw requestEvent.error(500, 'VITE_KRATOS_URL not configured')

  const res = await fetch(`${kratosUrl}/self-service/login/browser`, {
    redirect: 'manual',
    headers: { Cookie: requestEvent.request.headers.get('cookie') ?? '' },
  })

  if (res.status === 302 || res.status === 303) {
    // Usuario ya autenticado — redirigir al dashboard
    throw requestEvent.redirect(302, '/dashboard')
  }

  if (!res.ok) throw requestEvent.error(500, 'Failed to fetch login flow')
  return res.json() as Promise<KratosLoginFlow>
})

export default component$(() => {
  const flow = useLoginFlow()
  const error = useSignal('')
  const nav = useNavigate()

  // Qwik 2: useSignal para estado reactivo local
  // Diferencia de Qwik 1: las señales son más eficientes y tienen mejor tree-shaking

  const handlePasskeyLogin = $(async () => {
    // La API WebAuthn de Ory se maneja a través de su JavaScript SDK
    // Este código se ejecuta solo cuando el usuario hace click (Qwik lazy loading)
    const { default: OryInit } = await import('@ory/client-fetch')
    // ... lógica de Passkey
  })

  return (
    <div class="min-h-screen flex items-center justify-center">
      <div class="max-w-md w-full space-y-8 p-8">
        <h1 class="text-3xl font-bold text-center">Iniciar Sesión</h1>
        {error.value && (
          <div class="bg-red-50 text-red-700 p-3 rounded">{error.value}</div>
        )}
        {/* Renderizar nodos del flow de Kratos dinámicamente */}
        {flow.value.ui.nodes.map((node) => (
          <div key={node.attributes.name}>
            {/* Renderizado condicional de botones de Passkey */}
          </div>
        ))}
        <button
          onClick$={handlePasskeyLogin}
          class="w-full btn-primary"
        >
          Iniciar con Passkey / Biometría
        </button>
      </div>
    </div>
  )
})

export const head: DocumentHead = {
  title: 'Iniciar Sesión — serenidad',
```

### T-08.2.5 — Gestión de sesión y JWT

```typescript
// src/lib/session.ts
// Gestión del JWT tras el token exchange con el IAM Service

export const SESSION_KEY = 'serenidad_jwt' as const

export function getJWT(): string | null {
  if (typeof sessionStorage === 'undefined') return null
  return sessionStorage.getItem(SESSION_KEY)
}

export function setJWT(token: string): void {
  sessionStorage.setItem(SESSION_KEY, token)
}

export function clearJWT(): void {
  sessionStorage.removeItem(SESSION_KEY)
}

// Guard para rutas protegidas: se usa en routeLoader$ del dashboard
export async function requireAuth(requestEvent: RequestEventBase) {
  const token = getJWT()
  if (!token) {
    throw requestEvent.redirect(302, '/login')
  }
  return token
}
```

**Flujo de autenticación completo:**

1. Usuario va a `/login` → Qwik Router llama a Kratos para obtener el flow
2. Usuario se autentica con Passkey → Kratos crea sesión (cookie httpOnly)
3. Kratos redirige al frontend con la sesión → Frontend llama a `POST /bff/api/iam/token/exchange`
4. El BFF autentica la cookie con Kratos Admin API → IAM Service emite JWT Ed25519
5. Frontend almacena el JWT en `sessionStorage` → Usa el JWT en cada request al BFF
6. Al navegar a `/dashboard`, el routeLoader verifica el JWT → Si inválido, redirect a `/login`
