# HU-11.2 — Acciones de Operación (Día-2)

## Descripción General
Llamamos "Día 2" a todas las metodologías del ciclo de vida posterior al aprovisionamiento fundacional. Al existir un componente de `GitOps` con reconciliaciones agresivas, las reglas del juego cambian para desplegar e incrustrar secretos. Utiliza bajo tu propio riesgo las soluciones "Hotfix".

---

## Ejecución Detallada

### T-11.2.1 — El Ciclo Normal de Software (Paz)
Para lanzar una nueva actualización natural:
1. Pruebo en local: `go test ./... -v -race`
2. Si me convence, hago push a la rama `main` en mi origin de Gitlab.
3. El *Pipeline de Ci/CD de GitLab* se encarga de compilar y armar una versión nueva del manifiesto (Tarda 5 minutos).
4. `FluxCD` jala el commit y lo envía limpiamente a `Kubernetes` sin intervención (Tarda 1-3 minutos máximo).

### T-11.2.2 — El Ciclo HOTFIX de Emergencia Crítica (Guerra)
> [!CAUTION]
> ¡SOLO EN EMERGENCIAS EXTREMAS DE PRODUCCIÓN CAÍDA! FluxCD "matará" tu parche en menos de 10 minutos cuando sincronice Git, esto es solo para que el servicio no muera *mientras* subes un commit correcto y compilas normal.

1. Corrijo rápido el error o revierto.
2. Compilo contenedor Docker en local con un tag nuevo `docker build -t registry.gitlab.com/xyz/iam-service:hotfix-xyz ... `.
3. Me autentico y lo lanzo `docker push registry.gitlab.com/xyz/iam-service:hotfix-xyz`.
4. Ordeno tajantemente un reemplazo de imagen forzado manual en K8s para que aplique INMEDIATAMENTE:
   `kubectl set image deployment/iam-service iam-service=registry.gitlab.com/xyz/iam-service:hotfix-xyz -n serenidad-core`

### T-11.2.3 — Anexar Nuevos Secretos
Jamás mandes contraseñas sin cifrar por Git. Así las insertas productivamente:
```bash
# ./scripts/encrypt-secret.sh [NAMESPACE] [NOMBRE-DEL-ARCHIVO] KEY=Valor
./scripts/encrypt-secret.sh serenidad-core api-secreta NUEVA_KEY_SENSIBLE="A1B2C3D4"

# Luego empujalo por git
git add infra/secrets/api-secreta.yaml
git commit -m "chore: adding new external API key"
git push origin main
# (Kustomize Controller en Flux usando SOPS lo descifrará e inyectará de facto al Kubernetes).
```

### T-11.2.4 — Rotación de Claves Criptográficas Maestras (`age`)
Si sospechas que un ex-empleado tomó la llave maestra desencriptadora de `SOPS`, estás en peligro absoluto.
1. Genera nueva llave local: `age-keygen -o ~/.config/sops/age/keys-new.txt`
2. Toma la llave pública y reemplazala en nuestro `infra/secrets/.sops.yaml`.
3. Haz un bucle para reescribir con base a la nueva llave, todo lo viejo del repo local:
   ```bash
   for f in infra/secrets/*.yaml; do sops --rotate --in-place "$f"; done
   ```
4. Sube la actualización del Token Asimétrico al cluster K8s usando la de la clave (Aplica un `kubectl delete/replace` del `sops-age` con los nuevos datos).
5. Commitea los Yamls recifrados a `main`. Destruye la llave `age` anticuada.

### T-11.2.5 — Actualización del ISO del Sistema Operativo base (Talos Linux)
No manejamos parches Ubuntu con APT. Todo el FileSystem base se reemplaza de forma atómica en caliente. Las caidas son menores a unos segundos.
```bash
# Verifica que posees la versión a renovar
talosctl version --nodes ${FLOATING_IP}

# Ordena invocar y sustituir el SO con la imagen compilada inmodificable (Immutable OS)
talosctl upgrade --nodes ${FLOATING_IP} --image ghcr.io/siderolabs/installer:<NUEVA_VERSION_EJ_v1.7.5>

# Tu terminal perderá conexión al nodo durante aproximádamente 45-60 Segundos.
# Después de esto, repite 'talosctl version' para confirmar el impacto exitoso.
```
