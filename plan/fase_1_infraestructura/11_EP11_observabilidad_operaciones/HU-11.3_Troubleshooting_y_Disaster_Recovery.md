# HU-11.3 — Plan de Catástrofes (Troubleshooting & Disaster Recovery)

## Descripción General
Esta guía provee las heurísticas tácticas y los "libros de jugadas" (Playbooks) aprobados en caso de incidentes graves para todas las infraestructuras integradas durante las Fases 1 a la 10. Además, postula un escenario fatídico de destrucción total y el RTO (Target de Tiempo de Restauración) aceptado mediante un ejercicio iterativo.

---

## 1. Guía de Solución de Problemas (Troubleshooting)

### A) El Servidor arroja `NotReady` o desaparece
Tu comando `kubectl get nodes` retorna solo 1 nodo y dice `NotReady`.
- Revisa `kubectl describe node serenidad-prod-01 | grep -A20 "Conditions:"` buscando si dice `DiskPressure` o si está fuera de red.
- O revisa desde afuera con el API de nivel profundo por si el "agente" se trabó: `talosctl service kubelet restart --nodes ${FLOATING_IP}`.

### B) GitOps/FluxCD no escucha mi repositorio de Git
Hiciste push a GitLab pero los cambios no suceden hace más de 10 minutos.
- Mira qué detiene el flujo: `flux get all`
- Forza reconciliación bruta manual sin esperar el ciclo: `flux reconcile source git flux-system` y `flux reconcile kustomization flux-system`.

### C) Cert-Manager falla en renovar TLS (Let's Encrypt)
La API rechaza entrar por error de Certificados.
- Valida si lanzó peticiones de reto ACME: `kubectl get challenges -A`
- Si están "Pending", significa que Hetzner Firewall está bloqueando el puerto TCP `80`, el cual *Let's Encrypt* requirío contactar externamente para verificar que tú eres dueño del DNS.
- O describe el error interno: `kubectl describe certificate api-sereni-dad-tls -n traefik`

### D) CloudNativePG "Base de Datos" no levanta
- Haz inspección interna de los Volumenes montados en local para ver si se corrompió el almacenamiento de la base de datos `local-path`: `kubectl get pvc -n serenidad-data`

### E) Kratos o IAM arrojan "Failure" en su Liveness 
Kratos falla al iniciar o en responder.
- Extrae logs crudos ignorando lo bueno y apuntando a las desconexiones: `kubectl logs deployment/kratos -n serenidad-core | grep -E "error|database|dsn"`
- Lo mismo aplica si el IAM da error `500`: `kubectl logs deployment/iam-service -n serenidad-core --since=5m`.

### F) Traefik Ingress causa que rutas como `/api/loquesea` den 404
- Abre un tunel seguro al panel super-hacker de Traefik y verifícalo en tu navegador web en vez de estar matándote en la terminal:
  `kubectl port-forward -n traefik daemonset/traefik 9000:9000`
- Ya puedes entrar a `http://localhost:9000` y diagnosticar por qué la ruta falló el ruteo.

## 2. Archivos Sensibles y su Disposición
Si pierdes el almacenamiento local de tu laptop (Desarrollador) esto sucede:

| Archivo | Está en Internet (Git)? | Sufrió Cifrado? | Impacto |
|---------|----------|-----------|-------|
| `talos/secrets.yaml` | **NO** | N/A | **Cataclismo**. Contiene llave magna del SO. Mantener solo copias físicas/Gestor Contraseñas. |
| `talos/talosconfig` | **NO** | N/A | Pérdida de login al SO. Generable de nuevo teniendo el secret arriba. |
| `kubeconfig` | **NO** | N/A | Pérdida de login. Re-creable. |
| `infra/secrets/.sops.yaml` | SÍ | NO | Inofensivo conocerlo, solo es llave pública para poder cifrar y empujar al repo. |
| `infra/secrets/*.yaml` | SÍ | **SÍ (AES-Alg)** | Todos nuestros secretos conviven felizmente empacados matemáticamente ante la vista pública de todos. |
| `~/.config/sops/age/keys.txt` | **NO** | N/A | **Cataclismo**. Si la pierdes, no hay manera humana de descifrar todos los secrets que subiste por Git. Requieres respaldo Obligatorio a bóveda externa. |

## 3. Playbook de Catástrofes Total (Cluster Destruction)
Surgió un incendio en los Datacenters de Hetzner y el nodo de 32GB RAM se fundió hasta los cimientos. Tienes una crisis.
**RPO Previsto:** Se quemaron hasta ~5 min de base de datos no empujada a B2 (Manejo de WAL Batch).
**RTO Previsto:** El ambiente se reconstruirá en unos 45~60 Minutos sin tocar código y sin programar nada.

**Paso a Paso de Resurrección:**
1. Crear una nueva instancia de Hetzner idéntica vía interfaz.
2. Inyectar imagen de Talos (V-02 Fase 1 Básica).
3. Entregar secretos nativos `talos/secrets.yaml` aplicando el OS de un tirón.
4. Talos Linux levantará un Kubernetes inoperante o vacío.
5. Inyectas la llave maestra `SOPS` para `age` vía kubernetes (V-03). A partir de aquí no tocas contraseñas jamás.
6. Aplicar un FluxCD Bootstrap base, forzando y atándolo a nuestro Repositorio GitLab. (V-03).
7. Flux detectará los manifiestos YAML y empezará a enloquecer en modo constructivo, instalando todos los ingress, Kratos (Motor Auth), y la base Postgres por cuenta propia en unos 12 minutos.
8. Entras a la BD instanciada y le exiges descargar la capa de Backblaze: `kubectl cnpg restore serenidad-pg --backup <latest>`.
9. En un lapso de 15 minutos más (Asumiendo 4 GB de base de datos) Todo terminará.
