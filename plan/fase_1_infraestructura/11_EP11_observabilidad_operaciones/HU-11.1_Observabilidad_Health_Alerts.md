# HU-11.1 — Observabilidad Inicial y Monitorización

## Descripción General
Antes de declarar el sistema en "Producción", debemos garantizar la capacidad de observar su salud. En esta iteración definiremos las políticas de sondeo (HealthChecks) que Kubernetes usará internamente para decidir si matar y reiniciar un servicio que se quedó congelado, así como las alertas físicas del hipervisor (Hetzner Cloud) y un glosario de comandos de consola "Día-2" para diagnosticar velozmente el cluster.

---

## Ejecución Detallada

### T-11.1.1 — Implementación del Estándar de Salud Go 
Los desarrolladores Backend deben exponer obligatoriamente 3 rutas web en *todos* los microservicios sin excepción:

| Método | Endpoint | Propósito | Respuesta Esperada |
|--------|----------|-----------|--------------------|
| `GET`  | `/health` | **Liveness:** Si el programa respondió. Si falla 3 veces, K8s destruye el pod. | `{"status":"ok","service":"iam-service","version":"1.0"}` (HTTP 200) |
| `GET`  | `/ready`  | **Readiness:** Si el programa está listo para recibir tráfico (Ej: La conexión a DB fue exitosa). Evita que Traefik envíe usuarios a un backend apagado. | `{"status":"ok","db":"connected","kratos":"reachable"}` (HTTP 200 o 503) |
| `GET`  | `/metrics`| Exportar telemetría. | Retorna data cruda en formato `Prometheus/OpenMetrics` |

```bash
# Ejemplo visual de validación manual una vez que IAM-service esté up:
curl https://api.sereni.dad/api/iam/health
```

### T-11.1.2 — Alentas de Servidor Físico (Hetzner Monitoring)
Ingresa al [Panel de Hetzner Cloud Console](https://console.hetzner.cloud/). 
Diriígete a `serenidad-prod-01 -> Monitoring (Gráficas)`. Configura estas 3 alarmas a tu correo de devops:

1. **CPU Usage:** Umbral `90%` sostenido por más de `5 minutos`. 
2. **Network Traffic:** Un pico que exceda los `1000 Mbps` inusualmente (Posible ataque DDoS no purgado por Traefik/Cloudflare).
3. **Availability:** Alerta directa estilo "Ping Check" si el VPS de plano no responde al Hypervisor.

### T-11.1.3 — Glosario de Reacción Rapida por Consola
Añade estos alias a tu archivo `~/.bashrc` o `~/.zshrc` si manejas la infrestructura muy seguido:
```bash
alias kp="kubectl get pods -A | grep -v 'Running\|Completed'" # VerPods: Solo me muestra lo Roto o trabado
alias fp="flux get all --status-selector ready=false"        # VerFlux: Solo me muestra lo que falla en GitOps
alias tp="kubectl top pods -A --sort-by=memory"              # TopPods: Qué consume demasiada RAM
```

**Comandos Comunes Esenciales:**
- ¿Hay algún evento general reciente de error en Kubernetes?
  `kubectl get events -A --sort-by='.lastTimestamp' | tail -20`
- Quiero seguir los logs en vivo del backend porque tiró un Bug:
  `kubectl logs -f deployment/iam-service -n serenidad-core`
- ¿Mi base de datos PostgreSQL está bien y sus cron de Backup en tiempo?
  `kubectl get cluster,backup,scheduledbackup -n serenidad-data`
