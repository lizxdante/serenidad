# HU-02.2 — Instalación de Talos Linux

## Descripción General

Ubuntu 24.04 es el sistema operativo temporal del servidor. Para la infraestructura de producción se reemplaza con **Talos Linux**, un sistema operativo inmutable diseñado exclusivamente para ejecutar Kubernetes. Sus ventajas sobre un Linux tradicional son:

- **Sin SSH:** La superficie de ataque se reduce eliminando el acceso shell directo. La API de Talos usa mTLS sobre el puerto 50000.
- **Filesystem de solo lectura:** No es posible instalar paquetes, modificar binarios del sistema ni introducir cambios no declarativos.
- **Actualizaciones atómicas:** La actualización del OS es una sustitución completa del sistema (A/B updates), sin riesgo de corrupción parcial.
- **Declarativo:** Toda la configuración se aplica mediante YAML enviado por `talosctl`.

El proceso consiste en: (1) compilar una imagen personalizada con el driver QEMU requerido por Hetzner, (2) activar el modo rescue del servidor y flashear la imagen al disco, (3) verificar que Talos arrancó en modo mantenimiento.

---

## Ejecución Detallada

### T-02.2.1 — Compilar imagen personalizada con Talos Image Factory

Talos requiere una extensión del sistema (`qemu-guest-agent`) para que Hetzner Cloud pueda reportar métricas del servidor correctamente.

```bash
source .envrc

# Obtener la versión estable más reciente de Talos
TALOS_VERSION=$(curl -s https://api.github.com/repos/siderolabs/talos/releases/latest | jq -r '.tag_name')
echo "Versión de Talos a instalar: ${TALOS_VERSION}"

# Crear el esquema de personalización
cat > /tmp/talos-hetzner-schematic.yaml << EOF
customization:
  systemExtensions:
    officialExtensions:
      - siderolabs/qemu-guest-agent
EOF

# Enviar el esquema a la Image Factory de Sidero Labs
SCHEMATIC_RESPONSE=$(curl -s -X POST \
  --data-binary @/tmp/talos-hetzner-schematic.yaml \
  https://factory.talos.dev/schematics)

SCHEMATIC_ID=$(echo "${SCHEMATIC_RESPONSE}" | jq -r '.id')
echo "Schematic ID: ${SCHEMATIC_ID}"

# Verificar que el ID es válido (debe ser un hash hexadecimal de 64 caracteres)
if [[ ${#SCHEMATIC_ID} -ne 64 ]]; then
  echo "ERROR: Schematic ID inválido. Respuesta: ${SCHEMATIC_RESPONSE}"
  exit 1
fi

# Construir la URL de la imagen
IMAGE_URL="https://factory.talos.dev/image/${SCHEMATIC_ID}/${TALOS_VERSION}/hcloud-amd64.raw.xz"
echo "URL de imagen: ${IMAGE_URL}"

# Almacenar en .envrc para referencia futura
echo "# Talos Image (generado automáticamente)" >> .envrc
echo "export TALOS_VERSION=\"${TALOS_VERSION}\"" >> .envrc
echo "export TALOS_SCHEMATIC_ID=\"${SCHEMATIC_ID}\"" >> .envrc
```

### T-02.2.2 — Activar modo rescue y flashear la imagen

El modo rescue de Hetzner inicia el servidor desde una imagen de Linux en RAM, permitiendo el acceso SSH temporal para escribir en el disco principal.

```bash
# 1. Activar el modo rescue (retorna una contraseña temporal)
RESCUE_OUTPUT=$(hcloud server enable-rescue \
  --type linux64 \
  serenidad-prod-01 2>&1)
echo "${RESCUE_OUTPUT}"
# Guardar la contraseña root de rescue mostrada — expira cuando el servidor reinicia

# 2. Reiniciar el servidor para que arranque en modo rescue
hcloud server reset serenidad-prod-01
echo "Esperando que el servidor arranque en modo rescue (60s)..."
sleep 60

# 3. Verificar que el servidor respondió (status running)
hcloud server describe serenidad-prod-01 -o json | jq '.status'
# Debe retornar: "running"
```

**Conectar al servidor en modo rescue y flashear:**

```bash
# Conectar vía SSH con la contraseña temporal mostrada por enable-rescue
ssh root@${VPS_IP}
# Ingresar la contraseña de rescue cuando se solicite
```

Una vez dentro del servidor (modo rescue), ejecutar:

```bash
# Verificar que se está en el sistema de rescate (no en Ubuntu)
uname -a  # Debe mostrar un kernel de rescue, no el de Ubuntu

# Identificar el disco principal (ignorar el tmpfs del rescue)
lsblk
# Normalmente es /dev/sda (~80 GB)

# Descargar y flashear la imagen de Talos directamente al disco
# ADVERTENCIA: Este comando DESTRUYE irrecuperablemente todos los datos de /dev/sda
curl -L "https://factory.talos.dev/image/${TALOS_SCHEMATIC_ID}/${TALOS_VERSION}/hcloud-amd64.raw.xz" \
  | xz -d \
  | dd of=/dev/sda bs=4M status=progress

# Asegurar que todos los buffers de escritura se han vaciado al disco
sync

# Reiniciar el servidor (se desconectará automáticamente del SSH)
reboot
```

### T-02.2.3 — Verificar que Talos arrancó en modo mantenimiento

Tras el reboot, Talos inicia en **modo mantenimiento**: el kernel cargó, el agente de la API está escuchando en el puerto 50000, pero el cluster K8s aún no está configurado.

```bash
# Desde la máquina local, esperar ~90 segundos y verificar
sleep 90

# Verificar que el servidor responde en el puerto 50000 (API de Talos)
# El flag --insecure es necesario porque aún no tenemos certificados configurados
talosctl version --insecure --nodes ${VPS_IP}
```

**Salida esperada:**
```
Client:
        Tag:         v1.10.x
        SHA:         ...
        Built:       ...
        Go version:  go1.25.x
        OS/Arch:     linux/amd64

Server:
        NODE:        <VPS_IP>
        Tag:         v1.10.x    ← Este es el indicador clave
        SHA:         ...
        ...
```

Si Talos retorna su versión en "Server", el sistema está en modo mantenimiento y listo para recibir la configuración del cluster.

**Troubleshooting:**
- Si `talosctl version --insecure` no responde: verificar que el firewall de Hetzner permite el puerto 50000 desde la IP de trabajo. Usar `scripts/update-firewall.sh` si la IP cambió (ver HU-10.1B).
- Si el servidor no reinicia correctamente: usar la consola VNC de Hetzner (`hcloud server console serenidad-prod-01`) para ver la pantalla del servidor y diagnosticar el bootloader.
- Si la descarga de la imagen falla a mitad: el `dd` puede haber dejado el disco en un estado inconsistente. Repetir el proceso de rescue desde T-02.2.2.

## Criterios de Aceptación

| ID | Criterio | Verificación |
|----|----------|--------------|
| CA-02.2.1 | Schematic ID generado con extensión `qemu-guest-agent` | `echo $TALOS_SCHEMATIC_ID` muestra un hash de 64 caracteres |
| CA-02.2.2 | Imagen Talos flasheada exitosamente al disco `/dev/sda` | `dd` completó sin errores, `sync` ejecutado |
| CA-02.2.3 | Servidor reiniciado y en estado `running` tras el flash | `hcloud server describe serenidad-prod-01 -o json \| jq '.status'` → `"running"` |
| CA-02.2.4 | Talos responde en modo mantenimiento en el puerto 50000 | `talosctl version --insecure --nodes ${VPS_IP}` retorna Server Tag: v1.10.x |
| CA-02.2.5 | El servidor **NO** responde en el puerto 22 (SSH eliminado) | `ssh root@${VPS_IP}` devuelve `Connection refused` |
