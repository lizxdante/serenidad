# HU-02.1 — Aprovisionamiento del VPS Hetzner CX32

## Descripción General

Esta historia aprovisiona el servidor físico virtualizado que albergará el cluster Kubernetes de la plataforma. Se elige el tipo CX32 (4 vCPU, 8 GB RAM, 80 GB NVMe SSD) en la región Nuremberg (nbg1) por su proximidad geográfica al target de usuarios europeos y la excelente relación cómputo/precio.

Adicionalmente, se asigna una **Floating IP** (dirección IP fija independiente del servidor) que garantiza que los registros DNS de Cloudflare no necesiten actualizarse si el hardware subyacente es reemplazado. Finalmente, se configura un Firewall perimetral a nivel de hipervisor como primera capa de defensa.

### Topología de red resultante

```
Internet → Cloudflare Proxy → Floating IP → Firewall Hetzner → VPS CX32
                                                                    ↓
                                                              Talos Linux
                                                                    ↓
                                                           Kubernetes (K8s)
                                                                    ↓
                                                    Traefik DaemonSet → Pods
```

## Ejecución Detallada

### T-02.1.1 — Verificar disponibilidad y crear el servidor

```bash
# Cargar variables de entorno
source .envrc
hcloud context use serenidad-production

# Verificar especificaciones del tipo CX32 antes de provisionar
hcloud server-type describe cx32
# Confirmar: 4 vCPU, 8 GB RAM, 80 GB NVMe, precio ~$8.5/mes (2026)

# Verificar que la clave SSH fue registrada en HU-01.4
hcloud ssh-key list | grep serenidad-admin-key

# Crear el servidor con Ubuntu 24.04 (será reemplazado por Talos en HU-02.2)
hcloud server create \
  --name serenidad-prod-01 \
  --type cx32 \
  --location nbg1 \
  --image ubuntu-24.04 \
  --ssh-key serenidad-admin-key

# Capturar la IP dinámica asignada
VPS_IP=$(hcloud server describe serenidad-prod-01 -o json | jq -r '.public_net.ipv4.ip')
echo "VPS IP dinámica: ${VPS_IP}"

# Actualizar .envrc con la IP
sed -i "s|^export VPS_IP=.*|export VPS_IP=\"${VPS_IP}\"|" .envrc
source .envrc
```

**Verificación del servidor:**
```bash
hcloud server describe serenidad-prod-01 -o json | jq '{
  name: .name,
  status: .status,
  type: .server_type.name,
  location: .datacenter.location.name,
  ip: .public_net.ipv4.ip
}'
# Debe mostrar status: "running" y location: "nbg1"
```

### T-02.1.2 — Asignar Floating IP

La Floating IP persiste aunque el servidor sea eliminado o reemplazado, garantizando estabilidad de los registros DNS.

```bash
# Crear la IP flotante en la misma región
hcloud floating-ip create \
  --type ipv4 \
  --home-location nbg1 \
  --name serenidad-prod-fip

# Asignar la IP flotante al servidor
hcloud floating-ip assign serenidad-prod-fip serenidad-prod-01

# Capturar la IP flotante
FLOATING_IP=$(hcloud floating-ip describe serenidad-prod-fip -o json | jq -r '.ip')
echo "Floating IP: ${FLOATING_IP}"

# Actualizar .envrc con la Floating IP
sed -i "s|^export FLOATING_IP=.*|export FLOATING_IP=\"${FLOATING_IP}\"|" .envrc
source .envrc

# Verificar la asignación
hcloud floating-ip describe serenidad-prod-fip -o json | jq '{
  ip: .ip,
  assigned_to: .server.name,
  location: .home_location.name
}'
```

### T-02.1.3 — Configurar Firewall perimetral

El Firewall de Hetzner opera a nivel de hipervisor (antes de que el tráfico llegue al kernel del servidor) y complementa las K8s NetworkPolicies configuradas en EP-10.

> **Nota de seguridad:** Los puertos de administración 50000 (Talos API) y 6443 (Kubernetes API) se restringen exclusivamente a la IP de trabajo actual. Si la IP cambia (red diferente, ISP dinámico), usar `scripts/update-firewall.sh` (ver HU-10.1B).

```bash
# Obtener la IP pública de trabajo actual
MY_IP=$(curl -s -4 https://ifconfig.me)
echo "Restringiendo acceso admin a: ${MY_IP}/32"

# Crear el firewall
hcloud firewall create --name serenidad-prod-fw

# Regla 1: HTTP (necesario para Let's Encrypt ACME HTTP-01 challenge)
hcloud firewall add-rule serenidad-prod-fw \
  --description "HTTP Let's Encrypt ACME" \
  --direction in \
  --port 80 \
  --protocol tcp \
  --source-ips 0.0.0.0/0 \
  --source-ips ::/0

# Regla 2: HTTPS (tráfico de producción via Cloudflare)
hcloud firewall add-rule serenidad-prod-fw \
  --description "HTTPS produccion" \
  --direction in \
  --port 443 \
  --protocol tcp \
  --source-ips 0.0.0.0/0 \
  --source-ips ::/0

# Regla 3: Talos API — restringida a IP de trabajo
hcloud firewall add-rule serenidad-prod-fw \
  --description "Talos API (solo IP de trabajo)" \
  --direction in \
  --port 50000 \
  --protocol tcp \
  --source-ips "${MY_IP}/32"

# Regla 4: Kubernetes API — restringida a IP de trabajo
hcloud firewall add-rule serenidad-prod-fw \
  --description "Kubernetes API (solo IP de trabajo)" \
  --direction in \
  --port 6443 \
  --protocol tcp \
  --source-ips "${MY_IP}/32"

# Aplicar el firewall al servidor
hcloud firewall apply-to-resource serenidad-prod-fw \
  --type server \
  --server serenidad-prod-01

# Verificar las reglas aplicadas
hcloud firewall describe serenidad-prod-fw -o json | jq '.rules[] | {port: .port, source_ips: .source_ips, description: .description}'
```

### T-02.1.4 — Verificar acceso SSH temporal

Este paso confirma que el hardware está funcional antes de instalar Talos. Se realizará solo esta vez; después de instalar Talos, el puerto SSH 22 ya no estará disponible.

```bash
# Conectar via SSH (Ubuntu 24.04)
ssh -i ~/.ssh/hetzner_serenidad_ed25519 root@${VPS_IP}

# Dentro del servidor, verificar recursos
nproc           # Debe mostrar: 4
free -h         # Debe mostrar: ~7.7G disponible
df -h /         # Debe mostrar: ~75G disponible en /dev/sda
lsblk           # Identificar el disco principal (probablemente /dev/sda, ~80G)

exit
```

**Troubleshooting:**
- Si la conexión SSH falla: verificar que el firewall no tiene bloqueado el puerto 22 temporalmente. El firewall creado arriba no tiene regla para 22, pero Ubuntu 24.04 tiene SSH habilitado por defecto solo si se proveyó clave SSH en el paso de creación.
- Si `hcloud server create` falla con error de cuota: verificar que la cuenta Hetzner tiene saldo suficiente o límites de proyecto aumentados.
