# HU-02.3 — Bootstrap de Talos + Kubernetes

## Descripción General
Llevaremos el sistema operativo inmutable desde su estado de "mantenimiento en blanco" hacia un nodo de control plane de Kubernetes funcional mediante un parche declarativo (Yaml). Iniciaremos el almacén de valores de K8s (`etcd`) habilitando el enrutamiento general del cluster.

### ¿Qué infraestructura tocamos?
- **Sistema Operativo Remoto (Talos)**: Procesará nuestro archivo "machineconfig" (YAML) y aplicará redes (con IP Flotante virtual) y configuraciones de disco.
- **KubeApiServer / Etcd**: Levantaremos el cerebro nativo de Kubernetes. Se generarán decenas de certificados SSL y contraseñas localmente en nuestra máquina, que luego se inyectarán empaquetadas al servidor.

---

## Ejecución Detallada

*(Asegúrate de estar en el directorio de `serenidad-platform`)*

### T-02.3.1 y T-02.3.2 — Modificar el parche de red y emitir credenciales

Crea el archivo del nodo para informarle de su entorno físico:
```bash
cat <<EOF > infra/clusters/hetzner-prod/talos/patches/hetzner-cx32.yaml
machine:
  network:
    hostname: serenidad-prod-01
    interfaces:
      - interface: eth0
        dhcp: true
        vip:
          ip: ${FLOATING_IP} # Añadir la IP flotante al adaptador real
  kubelet:
    nodeIP:
      validSubnets:
        - ${VPS_IP}/32 # Evita que agarre IPs privadas erróneas de Hetzner
    extraArgs:
      provider-id: "hcloud://serenidad-prod-01"
  features:
    kubePrism:
      enabled: true
      port: 7445
  sysctlsConfig:
    # Tunings obligatorios para bases de datos (ElasticSearch / Postgres)
    vm.max_map_count: "262144"
    fs.inotify.max_user_watches: "524288"
    fs.inotify.max_user_instances: "8192"
cluster:
  allowSchedulingOnControlPlanes: true # Es vital porque solo hay un nodo
  apiServer:
    certSANs:
      - ${VPS_IP}
      - ${FLOATING_IP}
  network:
    cni:
      name: flannel
EOF
```

**Generamos el material criptográfico.** `talosctl` funciona como entidad certificadora local (CA Root) construyendo las llaves del cluster:
```bash
cd infra/clusters/hetzner-prod/talos/
talosctl gen secrets 
# IMPORTANTE: Copia el contenido de "secrets.yaml" en tu PM. Sin esto pierdes el cluster si formateas tu PC accidentalmente.
talosctl gen config serenidad-prod https://${FLOATING_IP}:6443 \
  --with-secrets secrets.yaml \
  --config-patch @patches/hetzner-cx32.yaml
```

### T-02.3.3 y T-02.3.4 — Inyección de arranque y chequeo (Bootstrap)

Mandamos toda la configuración hacia el servidor a través de la API en el puerto 50000:
```bash
talosctl apply-config --insecure --nodes ${VPS_IP} --file controlplane.yaml
```
*Espera 90 segundos que la computadora aplique perfiles y modifique particiones*.

**INICIO ABSOLUTO DEL CEREBRO DE BASE DE DATOS (Solo hacerlo 1 vez por clúster en la vida)**:
```bash
export TALOSCONFIG="$(pwd)/talosconfig"
talosctl bootstrap --nodes ${VPS_IP}
```

*Espera 2 minutos adicionales a que los contenedores core docker arranquen*. Extraemos las configuraciones formales de K8s (`kubeconfig`) hacia nuestra máquina.
```bash
talosctl kubeconfig ../../../../
export KUBECONFIG="$(pwd)/../../../../kubeconfig"
kubectl get nodes -o wide
# Deberías ver: serenidad-prod-01 Ready control-plane
```

### T-02.3.5 — Segmentación Limpia de Namespaces
El grupo de recursos lógicos `namespaces` separa carpetas.
```bash
kubectl create ns traefik
kubectl create ns cert-manager
kubectl create ns serenidad-secrets
kubectl create ns cnpg-system
kubectl create ns serenidad-data
kubectl create ns serenidad-core
kubectl create ns serenidad-ops

kubectl label ns serenidad-data environment=production app.kubernetes.io/managed-by=flux
kubectl label ns serenidad-core environment=production app.kubernetes.io/managed-by=flux
```
