# HU-02.3 — Bootstrap de Talos Linux y Kubernetes

## Descripción General

En esta historia de usuario se transforma el servidor Talos en modo mantenimiento en un nodo de control plane de Kubernetes completamente funcional. El proceso consta de tres fases: (1) generar la configuración declarativa del nodo con su material criptográfico, (2) aplicar la configuración al servidor vía API de Talos, y (3) inicializar el almacén de estado de Kubernetes (`etcd`) mediante el comando de bootstrap.

> **Advertencia crítica:** El comando `talosctl bootstrap` solo debe ejecutarse **una única vez** en la vida del cluster. Ejecutarlo múltiples veces destruye el estado de `etcd` y corrompe el cluster irrecuperablemente.

## Ejecución Detallada

### T-02.3.1 — Crear el parche de configuración del nodo

El parche personaliza el comportamiento de red, del kubelet y del cluster para el hardware específico de Hetzner CX32.

```bash
source .envrc

mkdir -p infra/clusters/hetzner-prod/talos/patches

# Crear el parche de configuración con sustitución de variables
# IMPORTANTE: Las variables ${FLOATING_IP} y ${VPS_IP} deben estar cargadas desde .envrc
# Validar que las variables críticas están cargadas antes de sustituir
if [[ -z "${VPS_IP}" ]] || [[ -z "${FLOATING_IP}" ]]; then
  echo "ERROR: VPS_IP y/o FLOATING_IP no están definidas en .envrc"
  echo "Ejecutar: source .envrc y verificar que ambas variables tienen valor"
  exit 1
fi
echo "VPS_IP=${VPS_IP}, FLOATING_IP=${FLOATING_IP}"

envsubst > infra/clusters/hetzner-prod/talos/patches/hetzner-cx32.yaml << 'EOF'
machine:
  network:
    hostname: serenidad-prod-01
    interfaces:
      - interface: eth0
        dhcp: true
        vip:
          # La Floating IP se configura como VIP sobre la interfaz real
          # Talos anuncia esta IP adicional y mantiene sincronización automática
          ip: ${FLOATING_IP}
  kubelet:
    nodeIP:
      # Limitar el kubelet a usar solo la IP real del VPS,
      # evitando que seleccione IPs privadas internas de Hetzner
      validSubnets:
        - ${VPS_IP}/32
    extraArgs:
      # Permite al CCM de Hetzner identificar este nodo en la API de la nube
      provider-id: "hcloud://serenidad-prod-01"
  features:
    # KubePrism: balanceador de carga interno para la API de Kubernetes
    # Mejora la disponibilidad del control plane cuando hay múltiples nodos
    kubePrism:
      enabled: true
      port: 7445
  sysctls:
    # Requeridos para bases de datos (CloudNativePG/PostgreSQL)
    vm.max_map_count: "262144"
    fs.inotify.max_user_watches: "524288"
    fs.inotify.max_user_instances: "8192"
    kernel.pid_max: "65536"
    # Requeridos para networking de Kubernetes
    net.ipv4.ip_forward: "1"
    net.bridge.bridge-nf-call-iptables: "1"
    net.bridge.bridge-nf-call-ip6tables: "1"
cluster:
  # Permitir pods en el control plane (necesario en single-node cluster)
  allowSchedulingOnControlPlanes: true
  apiServer:
    certSANs:
      - ${VPS_IP}
      - ${FLOATING_IP}
      - "127.0.0.1"
  network:
    # Subredes internas del cluster
    podSubnets:
      - "10.244.0.0/16"
    serviceSubnets:
      - "10.96.0.0/12"
    cni:
      name: flannel
  etcd:
    # etcd solo anuncia la IP real del VPS (no la VIP flotante)
    advertisedSubnets:
      - "${VPS_IP}/32"
EOF

# Validar que envsubst sustituyó correctamente (sin placeholders residuales)
if grep -q '\${' infra/clusters/hetzner-prod/talos/patches/hetzner-cx32.yaml; then
  echo "ERROR: Variables sin sustituir detectadas en el patch:"
  grep -o '\${[^}]*}' infra/clusters/hetzner-prod/talos/patches/hetzner-cx32.yaml | sort -u
  exit 1
fi
echo "Patch generado correctamente con IPs sustituidas."
```

### T-02.3.2 — Generar material criptográfico y configuración del cluster

`talosctl gen secrets` actúa como CA local, generando todas las PKI del cluster.

```bash
cd infra/clusters/hetzner-prod/talos/

# Generar el material criptográfico del cluster (solo se hace UNA VEZ)
talosctl gen secrets -o secrets.yaml

# ══════════════════════════════════════════════════════════════════════
# BACKUP CRÍTICO — Checklist de verificación de backups en Password Manager
# ══════════════════════════════════════════════════════════════════════
#
# 1. Copiar secrets.yaml al PM con label "serenidad-prod-talos-secrets.yaml"
# 2. Verificar que la entrada existe abriendo el PM desde otro navegador/incognito
# 3. Confirmar que el contenido copiado es idéntico: diff <(pbpaste) secrets.yaml
#
# INVENTARIO DE BACKUPS ACUMULADOS (actualizar conforme se ejecuta el plan):
#   [ ] secrets.yaml (Talos PKI) — PM: "serenidad-prod-talos-secrets.yaml"
#   [ ] age private key (SOPS) — PM: "serenidad-prod-age-private-key" (EP-03)
#   [ ] SSH key hetzner — PM: "hetzner_serenidad_ed25519" (EP-02 HU-02.1)
#   [ ] PG admin password — PM: "serenidad-prod-pg-admin-password" (EP-05)
#   [ ] JWT Ed25519 private key — PM: "serenidad-prod-jwt-private-key" (EP-07)
#
# PROCEDIMIENTO DE RECOVERY si PM no es accesible:
#   - Los secrets cifrados con SOPS están en el repo Git (recuperables con age key)
#   - Si se pierde el age key Y el PM: cluster irrecuperable, rebuild from scratch
#   - Mantener copia redundante del age key en un segundo PM o medio offline seguro
# ══════════════════════════════════════════════════════════════════════

echo "⚠️  IMPORTANTE: Hacer backup de secrets.yaml en el Password Manager AHORA"
cat secrets.yaml  # Copiar este contenido al PM

# Generar la configuración del cluster usando el patch personalizado
talosctl gen config serenidad-prod "https://${FLOATING_IP}:6443" \
  --with-secrets secrets.yaml \
  --config-patch @patches/hetzner-cx32.yaml \
  --output-dir .

# La generación produce:
# - controlplane.yaml: configuración para el nodo de control plane
# - worker.yaml: configuración para nodos worker (no se usa en single-node)
# - talosconfig: configuración de cliente para talosctl

# Verificar que los archivos fueron generados
ls -la controlplane.yaml worker.yaml talosconfig secrets.yaml

# Confirmar que estos archivos NO están siendo versionados en git
git check-ignore -v controlplane.yaml worker.yaml talosconfig secrets.yaml
# Deben aparecer como ignorados por .gitignore

cd ../../../..  # Volver a la raíz del monorepo
```

### T-02.3.3 — Aplicar la configuración al servidor

```bash
# El TALOSCONFIG debe apuntar al archivo generado
export TALOSCONFIG="${PWD}/infra/clusters/hetzner-prod/talos/talosconfig"

# Aplicar la configuración al servidor en modo mantenimiento
# --insecure: necesario en la primera aplicación (sin certificados aún)
# --nodes: IP del servidor (NO la Floating IP aún, pues la VIP no está configurada)
talosctl apply-config \
  --insecure \
  --nodes ${VPS_IP} \
  --file infra/clusters/hetzner-prod/talos/controlplane.yaml

echo "Configuración aplicada. Esperando que Talos aplique los cambios (90s)..."
sleep 90

# Verificar que el servidor responde con las nuevas credenciales (ya no --insecure)
talosctl version --nodes ${FLOATING_IP}
# Ahora debe responder usando las credenciales del talosconfig generado
```

---

### T-02.3.4 — Inicializar etcd (Bootstrap del cluster)

> **ADVERTENCIA:** Este es el punto de no retorno. Ejecutar EXACTAMENTE UNA VEZ.

```bash
# Bootstrap de etcd: inicializa el almacén de estado de Kubernetes
# Este comando le indica a Talos que este nodo es el primer miembro de etcd
talosctl bootstrap --nodes ${FLOATING_IP}

echo "Bootstrap iniciado. Esperando que el control plane de Kubernetes levante (3 minutos)..."
sleep 180

# Monitorear el progreso del arranque
talosctl health --nodes ${FLOATING_IP}
# Esperar hasta que todos los checks estén OK
```

### T-02.3.5 — Obtener el kubeconfig y verificar el cluster

```bash
# Extraer el kubeconfig del cluster recién inicializado
talosctl kubeconfig \
  infra/clusters/hetzner-prod/ \
  --nodes ${FLOATING_IP}

# Configurar KUBECONFIG para apuntar al archivo generado
# Verificar que estamos en la raíz del monorepo
if [[ ! -f ".envrc" ]]; then
  echo "ERROR: No estás en la raíz del monorepo. Navega al directorio correcto."
  exit 1
fi
export KUBECONFIG="${PWD}/infra/clusters/hetzner-prod/kubeconfig"

# Verificar la salud del nodo
kubectl get nodes -o wide
# Salida esperada:
# NAME                STATUS   ROLES           AGE   VERSION   INTERNAL-IP
# serenidad-prod-01   Ready    control-plane   Xm    v1.33.x (o la versión bundled con Talos v1.10.x)   <VPS_IP>

# Verificar pods del sistema
kubectl get pods -A
# Todos los pods en kube-system deben estar Running o Completed

# Verificar que la Floating IP está configurada como VIP en la interfaz de red de Talos
talosctl get addresses --nodes ${VPS_IP} | grep ${FLOATING_IP}
# Debe mostrar la Floating IP como dirección asignada en eth0
# Si no aparece, la VIP no se configuró correctamente — revisar el patch hetzner-cx32.yaml

# Verificar que la Floating IP es accesible como endpoint del API
kubectl cluster-info
# Debe mostrar: https://FLOATING_IP:6443
```

## Rollback / Recovery

| Escenario de fallo | Procedimiento de recuperación |
|---------------------|-------------------------------|
| `envsubst` no sustituye variables | Verificar `source .envrc`; regenerar patch; las validaciones pre/post-envsubst detectan este caso |
| `talosctl apply-config` falla | Verificar conectividad al puerto 50000; verificar que el servidor está en modo mantenimiento |
| `talosctl bootstrap` ejecutado dos veces | **IRRECUPERABLE sin re-flashear.** Repetir desde HU-02.2 (flash Talos) + generar nuevos secrets + bootstrap |
| Nodo no alcanza estado Ready | Ejecutar `talosctl health --nodes ${FLOATING_IP}` para diagnosticar; revisar logs con `talosctl logs --nodes ${FLOATING_IP}` |
| Floating IP no responde | Verificar asignación en Hetzner Cloud console; verificar patch VIP; re-aplicar config si necesario |

> **ADVERTENCIA CRITICA:** Si `talosctl bootstrap` se ejecutó más de una vez, el único recovery es re-flashear Talos (HU-02.2) y repetir todo el proceso de bootstrap con nuevos secrets.
