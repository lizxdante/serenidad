# HU-04.2 — Traefik v3.x Ingress Controller

## Descripción General

Traefik es el punto de entrada de todo el tráfico HTTP/HTTPS al cluster. Se despliega como **DaemonSet** (no como Deployment con Service LoadBalancer) porque en Hetzner con un single-node cluster, usar `hostPort` directamente en los puertos 80 y 443 del nodo es más eficiente y evita la necesidad de un Load Balancer externo.

Traefik actúa como:
- **Proxy reverso:** recibe tráfico y lo enruta al servicio correcto según el hostname y path
- **Terminador TLS:** gestiona certificados Let's Encrypt junto con cert-manager
- **Middleware engine:** aplica transformaciones (redirección HTTPS, headers de seguridad, ForwardAuth)

### Middlewares configurados

| Middleware | Función |
|---|---|
| `iam-forward-auth` | Delega la autenticación al `iam-service` para rutas protegidas |
| `redirect-to-https` | Redirección permanente (308) de HTTP a HTTPS |
| `security-headers` | Headers OWASP: HSTS, X-Frame-Options, CSP, Referrer-Policy |

### T-04.2.2 — HelmRelease de Traefik

```bash
cat > infra/infrastructure/traefik/helmrelease.yaml << 'EOF'
apiVersion: helm.toolkit.fluxcd.io/v2
kind: HelmRelease
metadata:
  name: traefik
  namespace: traefik
spec:
  interval: 10m
  # Esperar a que cert-manager esté listo antes de desplegar Traefik
  dependsOn:
    - name: cert-manager
      namespace: cert-manager
  chart:
    spec:
      chart: traefik
      version: ">=30.0.0 <31.0.0"
      sourceRef:
        kind: HelmRepository
        name: traefik
        namespace: flux-system
      interval: 1h
  install:
    createNamespace: true
    remediation:
      retries: 3
  upgrade:
    remediation:
      retries: 3
  values:
    # DaemonSet: un pod por nodo (en single-node, equivale a un pod)
    deployment:
      kind: DaemonSet

    # ClusterIP evita crear un LoadBalancer externo (usamos hostPort en su lugar)
    service:
      type: ClusterIP

    # IngressClass: registrar traefik como el IngressClass por defecto
    ingressClass:
      enabled: true
      isDefaultClass: true

    # Puertos y configuración de red
    ports:
      web:
        port: 8000
        exposedPort: 80
        # hostPort vincula el puerto directamente al nodo
        hostPort: 80
        # Redirigir todo el tráfico HTTP a HTTPS
        redirectTo:
          port: websecure
      websecure:
        port: 8443
        exposedPort: 443
        hostPort: 443
        tls:
          enabled: true
      # Puerto interno para el Dashboard de Traefik (no expuesto externamente)
      traefik:
        port: 9000
        expose:
          default: false

    # Proveedores: Kubernetes CRD y Kubernetes Ingress nativo
    providers:
      kubernetesCRD:
        enabled: true
        # Permitir referencias cross-namespace en IngressRoutes
        allowCrossNamespace: true
        allowEmptyServices: false
      kubernetesIngress:
        enabled: true
        allowEmptyServices: false

    # Dashboard: disponible internamente via port-forward (no accesible externamente)
    api:
      dashboard: true
      insecure: false  # Requiere IngressRoute para acceder

    # Logging
    logs:
      general:
        level: INFO
      access:
        enabled: true
        format: json

    # Configuración de TLS via cert-manager
    additionalArguments:
      - "--certificatesresolvers.letsencrypt.acme.email=admin@sereni.dad"
      - "--certificatesresolvers.letsencrypt.acme.storage=/data/acme.json"
      - "--certificatesresolvers.letsencrypt.acme.httpchallenge.entrypoint=web"
      - "--certificatesresolvers.letsencrypt-staging.acme.email=admin@sereni.dad"
      - "--certificatesresolvers.letsencrypt-staging.acme.storage=/data/acme-staging.json"
      - "--certificatesresolvers.letsencrypt-staging.acme.caserver=https://acme-staging-v02.api.letsencrypt.org/directory"
      - "--certificatesresolvers.letsencrypt-staging.acme.httpchallenge.entrypoint=web"
      - "--global.sendanonymoususage=false"
      - "--serversTransport.insecureSkipVerify=false"

    # Persistencia para almacenar acme.json (certificados ACME)
    persistence:
      enabled: true
      storageClass: local-path
      size: 128Mi
      path: /data

    # Recursos: ajustados para Hetzner CX32
    resources:
      requests:
        cpu: 50m
        memory: 64Mi
      limits:
        cpu: 500m
        memory: 256Mi
EOF
```

### T-04.2.3 — Middlewares de Traefik

```bash
cat > infra/infrastructure/traefik/middlewares.yaml << 'EOF'
# Middleware 1: ForwardAuth hacia el IAM Service
# Todas las rutas protegidas deben pasar por este middleware
# El IAM Service valida el JWT y extrae los claims al header
apiVersion: traefik.io/v1alpha1
kind: Middleware
metadata:
  name: iam-forward-auth
  namespace: traefik
spec:
  forwardAuth:
    address: "http://iam-service.serenidad-core.svc.cluster.local:8080/internal/validate-token"
    trustForwardHeader: true
    authResponseHeaders:
      - X-User-ID
      - X-User-Role
      - X-Tenant-ID
      - X-User-DID
    authRequestHeaders:
      - Authorization
      - Cookie
---
# Middleware 2: Redirección HTTP → HTTPS
apiVersion: traefik.io/v1alpha1
kind: Middleware
metadata:
  name: redirect-to-https
  namespace: traefik
spec:
  redirectScheme:
    scheme: https
    permanent: true
---
# Middleware 3: Headers de seguridad OWASP
apiVersion: traefik.io/v1alpha1
kind: Middleware
metadata:
  name: security-headers
  namespace: traefik
spec:
  headers:
    # Prevenir clickjacking
    frameDeny: true
    # Prevenir MIME sniffing
    contentTypeNosniff: true
    # Habilitar XSS protection en navegadores legacy
    browserXssFilter: true
    # HSTS: forzar HTTPS por 1 año, incluir subdominios
    stsSeconds: 31536000
    stsIncludeSubdomains: true
    stsPreload: true
    # Política de referrer
    referrerPolicy: "strict-origin-when-cross-origin"
    # Remover headers que revelan tecnología
    customResponseHeaders:
      X-Powered-By: ""
      Server: ""
    # Permissions Policy (reemplaza Feature-Policy)
    permissionsPolicy: "camera=(), microphone=(), geolocation=(), payment=()"
EOF
```

### T-04.2.5 — Verificar el despliegue

```bash
source .envrc

# 1. Pod del DaemonSet en Running (1 pod en single-node cluster)
kubectl get pods -n traefik
# traefik-xxx   1/1   Running

# 2. IngressClass registrada como default
kubectl get ingressclass
# NAME      CONTROLLER                      PARAMETERS   AGE
# traefik   traefik.io/ingress-controller   <none>       Xm  (default)

# 3. Middlewares creados
kubectl get middlewares -A
# NAMESPACE   NAME                AGE
# traefik     iam-forward-auth    Xm
# traefik     redirect-to-https   Xm
# traefik     security-headers    Xm

# 4. Traefik responde en los puertos del VPS
# HTTP debe retornar 308 (redirect a HTTPS)
curl -I "http://${FLOATING_IP}"
# HTTP/1.1 308 Permanent Redirect
# Location: https://...

# HTTPS debe retornar 404 (Traefik funciona pero no hay rutas configuradas aún)
curl -k -I "https://${FLOATING_IP}"
# HTTP/1.1 404 Not Found (o 200 según la configuración)

# 5. Dashboard disponible via port-forward
kubectl port-forward -n traefik daemonset/traefik 9000:9000 &
sleep 2
curl -s http://localhost:9000/api/overview | jq '.http.routers.total'
kill %1  # Cerrar el port-forward
```

**Troubleshooting:**
- Si el pod está en `Pending`: puede haber conflicto con otro proceso que use los puertos 80/443 en el nodo. Verificar con `talosctl netstat --nodes ${FLOATING_IP} | grep -E ':80|:443'`.
- Si el pod crashea: revisar los logs con `kubectl logs daemonset/traefik -n traefik --previous`.
