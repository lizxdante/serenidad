# HU-04.2 — Traefik v3.x Ingress Controller

## Descripción General
Traefik es el enrutador inteligente de nuestra plataforma. Recibe la petición desde el internet y sabe a qué servicio interno (un Pod) debe entregarla, al mismo tiempo actuando de proxy inverso y balanceador de carga. Lo instalaremos en formato *DaemonSet* escuchando directamente en los puertos 80 y 443 del sistema operativo del VPS, con redirecciones obligatorias a HTTPS. Además, instalaremos herramientas (Middlewares) que obligarán a pasar controles de autenticación central.

---

## Ejecución Detallada

### T-04.2.1 — El Origen (HelmRepository)
Declaramos dónde obtener Traefik, del mismo modo que hicimos con cert-manager.

```bash
cat <<EOF > infra/infrastructure/traefik/helmrepository.yaml
apiVersion: source.toolkit.fluxcd.io/v1
kind: HelmRepository
metadata:
  name: traefik
  namespace: flux-system
spec:
  interval: 1h
  url: https://helm.traefik.io/traefik
EOF
```

### T-04.2.2 — Estableciendo las Reglas de Negocio (HelmRelease)
El componente más complejo de esta HU, donde instruiremos explícitamente habilitar el modo Host Port (conectado directo al servidor físico virtualizado) y la conexión con Jetstack/Let's Encrypt.

```bash
cat <<EOF > infra/infrastructure/traefik/helmrelease.yaml
apiVersion: helm.toolkit.fluxcd.io/v2
kind: HelmRelease
metadata:
  name: traefik
  namespace: traefik
spec:
  interval: 10m
  # Esperamos a que los CRD de cert-manager existan para no fallar en el arranque
  dependsOn:
    - name: cert-manager
      namespace: cert-manager
  chart:
    spec:
      chart: traefik
      version: '>=30.0.0 <31.0.0'
      sourceRef:
        kind: HelmRepository
        name: traefik
        namespace: flux-system
  install:
    createNamespace: true
  values:
    deployment:
      kind: DaemonSet
    service:
      type: ClusterIP
    ingressClass:
      enabled: true
      isDefaultClass: true
    ports:
      web:
        port: 8000
        exposedPort: 80
        hostPort: 80
        redirectTo: websecure
      websecure:
        port: 8443
        exposedPort: 443
        hostPort: 443
        tls:
          enabled: true
    providers:
      kubernetesCRD:
        allowCrossNamespace: true
      kubernetesIngress:
        enabled: true
    logs:
      general:
        level: INFO
      access:
        enabled: true
    api:
      dashboard: true
      insecure: false
    additionalArguments:
      - --certificatesresolvers.letsencrypt.acme.email=admin@sereni.dad
      - --certificatesresolvers.letsencrypt.acme.storage=/data/acme.json
      - --certificatesresolvers.letsencrypt.acme.httpchallenge.entrypoint=web
    persistence:
      enabled: true
      storageClass: local-path
      size: 128Mi
    resources:
      requests:
        cpu: 50m
        memory: 64Mi
      limits:
        cpu: 300m
        memory: 256Mi
EOF
```

### T-04.2.3 — Capa de Seguridad de Enrutamiento (Middlewares)
Los *Middlewares* son filtros que el tráfico debe superar para seguir adelante. Crearemos tres: uno para delegar la autenticación al `iam-service`, uno estricto para esquemas HSTS y enmascaramiento, y uno genérico para obligar el uso de HTTPS.

```bash
cat <<EOF > infra/infrastructure/traefik/middlewares.yaml
apiVersion: traefik.io/v1alpha1
kind: Middleware
metadata:
  name: iam-forward-auth
  namespace: traefik
spec:
  forwardAuth:
    address: "http://iam-service.serenidad-core.svc.cluster.local:8080/internal/validate-token"
    trustForwardHeader: true
    authResponseHeaders:
      - X-User-ID
      - X-User-Role
      - X-Tenant-ID
      - X-User-DID
    authRequestHeaders:
      - Authorization
      - Cookie
---
apiVersion: traefik.io/v1alpha1
kind: Middleware
metadata:
  name: redirect-to-https
  namespace: traefik
spec:
  redirectScheme:
    scheme: https
    permanent: true
---
apiVersion: traefik.io/v1alpha1
kind: Middleware
metadata:
  name: security-headers
  namespace: traefik
spec:
  headers:
    frameDeny: true
    contentTypeNosniff: true
    browserXssFilter: true
    referrerPolicy: "strict-origin-when-cross-origin"
    customResponseHeaders:
      X-Powered-By: ""
    stsSeconds: 31536000
    stsIncludeSubdomains: true
    stsPreload: true
EOF
```

### T-04.2.5 — Consolidación vía GitOps
Añadimos todo al archivo kustomization y lo entregamos al clúster por Flux.

```bash
# Escribimos el índice local para Traefik
cat <<EOF > infra/infrastructure/traefik/kustomization.yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
resources:
  - helmrepository.yaml
  - helmrelease.yaml
  - middlewares.yaml
EOF

git add infra/infrastructure/traefik/
git commit -m "feat(infra): deploy traefik ingress controller daemonset and security middlewares"
git push origin main
flux reconcile kustomization flux-system --with-source
```

### T-04.2.4 — Validaciones Post-Despliegue
Verificar que Traefik ha interceptado correctamente nuestra IP.

```bash
# 1. Aseguramos que Traefik está corriendo (Como es DaemonSet en Single Node, debe haber 1 Pod)
kubectl get pods -n traefik

# 2. Vamos a simular tráfico Web HTTP puro (puerto 80) hacia nuestra IP flotante.
# Carga la variable de tu servidor en tu terminal
source .envrc

# Verificamos si Traefik responde devolviendo un "308 Permanent Redirect"
curl -I http://${FLOATING_IP}

# 3. Y ahora hacia el puerto encriptado directo evadiendo certificación local (-k). 
# Debería devolver un error 404 (puesto que el router sirve, pero no le hemos dado rutas aún para procesar)
curl -k -I https://${FLOATING_IP}

# 4. Validar existencia de Middlewares
kubectl get middlewares -A
```
