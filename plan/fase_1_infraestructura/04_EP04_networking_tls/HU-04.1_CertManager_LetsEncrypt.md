# HU-04.1 — cert-manager v1.x + Let's Encrypt

## Descripción General
Para que todos los servicios de la plataforma operen exclusivamente de manera encriptada sin la intervención humana, requerimos de un administrador de certificados. `cert-manager` actuará dentro del clúster comunicándose en segundo plano con *Let's Encrypt* para verificar nuestra propiedad del dominio, generar certificados de seguridad y, sobre todo, renovarlos antes de que expiren automáticamente. En esta historia de usuario, se desplegará el gestor utilizando GitOps (a través de FluxCD) para mantener la inmutabilidad de la configuración.

---

## Ejecución Detallada

### T-04.1.1 — Declarar la Fuente del Instalador (HelmRepository)
Le enseñaremos a FluxCD dónde encontrar las recetas de instalación oficiales del creador original de *cert-manager* (Jetstack).

```bash
# Asegúrate de estar en la raíz de tu monorepo ('serenidad-platform')
# La carpeta "cert-manager" fue creada en el esqueleto de la Épica 3.

cat <<EOF > infra/infrastructure/cert-manager/helmrepository.yaml
apiVersion: source.toolkit.fluxcd.io/v1
kind: HelmRepository
metadata:
  name: jetstack
  namespace: flux-system
spec:
  interval: 1h
  url: https://charts.jetstack.io
EOF
```

### T-04.1.2 — Configurar el Despliegue de cert-manager (HelmRelease)
Crearemos el archivo que orquesta qué versión instalar y qué configuraciones se habilitarán (como la inyección de la definición de los Custom Resources o CRDs).

```bash
cat <<EOF > infra/infrastructure/cert-manager/helmrelease.yaml
apiVersion: helm.toolkit.fluxcd.io/v2
kind: HelmRelease
metadata:
  name: cert-manager
  namespace: cert-manager
spec:
  interval: 10m
  chart:
    spec:
      chart: cert-manager
      version: '>=1.15.0 <2.0.0'
      sourceRef:
        kind: HelmRepository
        name: jetstack
        namespace: flux-system
  install:
    createNamespace: true
  values:
    crds:
      enabled: true
    webhook:
      enabled: true
    resources:
      requests:
        cpu: 20m
        memory: 64Mi
      limits:
        cpu: 200m
        memory: 128Mi
EOF
```

### T-04.1.4 — Crear Emitidores a Nivel Clúster (ClusterIssuers)
Los "Issuers" son la entidad de Kubernetes que *hablan* con Let's Encrypt. Cerraremos el trato creando uno para el entorno Staging (de pruebas, para no agotar la cuota de Let's Encrypt si nos equivocamos repetidamente) y uno para Producción.

```bash
# Cambia 'admin@sereni.dad' por tu correo real de administración.
cat <<EOF > infra/infrastructure/cert-manager/clusterissuers.yaml
apiVersion: cert-manager.io/v1
kind: ClusterIssuer
metadata:
  name: letsencrypt-staging
spec:
  acme:
    email: admin@sereni.dad
    server: https://acme-staging-v02.api.letsencrypt.org/directory
    privateKeySecretRef:
      name: issuer-account-key-staging
    solvers:
      - http01:
          ingress:
            class: traefik
---
apiVersion: cert-manager.io/v1
kind: ClusterIssuer
metadata:
  name: letsencrypt-prod
spec:
  acme:
    email: admin@sereni.dad
    server: https://acme-v02.api.letsencrypt.org/directory
    privateKeySecretRef:
      name: issuer-account-key-prod
    solvers:
      - http01:
          ingress:
            class: traefik
EOF
```

### T-04.1.6 — Integración de Directorio y Comprobación Final 
Integrar todo el bloque dentro del maestro Kustomize de componentes, commitearlo e instruir a FluxCD que ejecute la subida.

```bash
# Escribimos el índice local para cert-manager
cat <<EOF > infra/infrastructure/cert-manager/kustomization.yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
resources:
  - helmrepository.yaml
  - helmrelease.yaml
  - clusterissuers.yaml
EOF

# Subir cambios al repositorio de Git
git add infra/infrastructure/cert-manager/
git commit -m "feat(infra): add cert-manager deployment and letsencrypt cluster issuers"
git push origin main

# Obligamos a FluxCD a procesar el nuevo código
flux reconcile kustomization flux-system --with-source
```

### T-04.1.3 y T-04.1.5 — Verificando el Despliegue en Vivo
Asegurémonos de que Kubernetes ha aceptado todas nuestras reglas.

```bash
# 1. Comprobamos la salud de los pods de Cert-Manager
kubectl get pods -n cert-manager
# Debes ver tres pods corriendo (cert-manager, cainjector, webhook)

# 2. Revisamos si Let's Encrypt nos aceptó
kubectl get clusterissuers
# 'letsencrypt-staging' y 'letsencrypt-prod' deberían arrojar STATUS True o Ready.

# 3. Comprobamos instalaciones en contexto ampliado
kubectl get crd | grep cert-manager
```
