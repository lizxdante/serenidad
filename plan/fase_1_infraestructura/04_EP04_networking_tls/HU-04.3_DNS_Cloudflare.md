# HU-04.3 — DNS y Proxy Cloudflare

## Descripción General

Cloudflare actúa como capa de protección y optimización entre el internet y el servidor Hetzner. Al activar el proxy (modo naranja), Cloudflare oculta la IP real de Hetzner del mundo y provee:

- **DDoS Protection:** Filtrado de tráfico malicioso antes de que llegue al VPS
- **TLS Edge Termination:** Certificado SSL entre el usuario final y Cloudflare
- **Caching:** Para contenido estático (futuras fases)

La configuración **TLS Full Strict** garantiza que la comunicación entre Cloudflare y el servidor Hetzner también esté cifrada con un certificado válido emitido por cert-manager, logrando encriptación end-to-end real.

### Flujo de una solicitud HTTPS

```
Usuario → [TLS] → Cloudflare Edge → [TLS Full Strict] → Traefik (Hetzner) → Pod
```

## Ejecución Detallada

### T-04.3.1 — Crear registros DNS apuntando al servidor

```bash
source .envrc

# Registro A para api.sereni.dad → Floating IP de Hetzner (con proxy Cloudflare activado)
RESPONSE=$(curl -s -X POST \
  "https://api.cloudflare.com/client/v4/zones/${CF_ZONE_ID}/dns_records" \
  -H "Authorization: Bearer ${CF_API_TOKEN}" \
  -H "Content-Type: application/json" \
  --data "{
    \"type\": \"A\",
    \"name\": \"api\",
    \"content\": \"${FLOATING_IP}\",
    \"ttl\": 1,
    \"proxied\": true,
    \"comment\": \"Hetzner CX32 - Traefik Ingress\"
  }")

echo "${RESPONSE}" | jq '{success: .success, id: .result.id, name: .result.name}'
# success: true confirma la creación

# Guardar el ID del registro para futuras modificaciones
DNS_RECORD_ID=$(echo "${RESPONSE}" | jq -r '.result.id')
echo "DNS Record ID (guardar): ${DNS_RECORD_ID}"

# Registro CNAME para app.sereni.dad → Cloudflare Pages (se configura en EP-08)
# Este registro se puede crear ahora como placeholder
curl -s -X POST \
  "https://api.cloudflare.com/client/v4/zones/${CF_ZONE_ID}/dns_records" \
  -H "Authorization: Bearer ${CF_API_TOKEN}" \
  -H "Content-Type: application/json" \
  --data "{
    \"type\": \"CNAME\",
    \"name\": \"app\",
    \"content\": \"serenidad-web.pages.dev\",
    \"ttl\": 1,
    \"proxied\": true,
    \"comment\": \"Cloudflare Pages - SPA Qwik\"
  }" | jq '.success'

# Verificar propagación DNS (puede tardar 1-5 minutos)
sleep 60
dig api.sereni.dad @1.1.1.1 +short
# Debe mostrar IPs de Cloudflare (104.21.x.x o 172.67.x.x), NO la IP de Hetzner
```

### T-04.3.2 — Configurar SSL/TLS Full Strict y HSTS

```bash
# Configurar TLS en modo Full Strict
# Full Strict: Cloudflare valida el certificado del servidor de origen
# (cert-manager debe haber emitido un certificado válido para que esto funcione)
curl -s -X PATCH \
  "https://api.cloudflare.com/client/v4/zones/${CF_ZONE_ID}/settings/ssl" \
  -H "Authorization: Bearer ${CF_API_TOKEN}" \
  -H "Content-Type: application/json" \
  --data '{"value": "strict"}' \
  | jq '{success: .success, value: .result.value}'
# success: true, value: "strict"

# Activar TLS 1.3 (deshabilitar TLS 1.0 y 1.1)
curl -s -X PATCH \
  "https://api.cloudflare.com/client/v4/zones/${CF_ZONE_ID}/settings/tls_1_3" \
  -H "Authorization: Bearer ${CF_API_TOKEN}" \
  -H "Content-Type: application/json" \
  --data '{"value": "on"}' \
  | jq '{success: .success, value: .result.value}'

# Activar Always Use HTTPS (redirigir HTTP a HTTPS a nivel de Cloudflare)
curl -s -X PATCH \
  "https://api.cloudflare.com/client/v4/zones/${CF_ZONE_ID}/settings/always_use_https" \
  -H "Authorization: Bearer ${CF_API_TOKEN}" \
  -H "Content-Type: application/json" \
  --data '{"value": "on"}' \
  | jq '{success: .success, value: .result.value}'

# Configurar HSTS (HTTP Strict Transport Security) en el edge de Cloudflare
curl -s -X PATCH \
  "https://api.cloudflare.com/client/v4/zones/${CF_ZONE_ID}/settings/security_header" \
  -H "Authorization: Bearer ${CF_API_TOKEN}" \
  -H "Content-Type: application/json" \
  --data '{
    "value": {
      "strict_transport_security": {
        "enabled": true,
        "max_age": 31536000,
        "include_subdomains": true,
        "preload": true,
        "nosniff": true
      }
    }
  }' \
  | jq '{success: .success}'
```

### T-04.3.3 — Verificar el cifrado end-to-end

```bash
source .envrc

# 1. Verificar que la resolución DNS pasa por Cloudflare (IPs de CF, no de Hetzner)
dig api.sereni.dad @1.1.1.1 +short
# Debe mostrar: 104.21.x.x o 172.67.x.x (NO ${FLOATING_IP})

# 2. Verificar que HTTPS responde sin errores de certificado
# El código 404 es esperado (Traefik responde pero aún no hay rutas configuradas)
curl -s -o /dev/null -w "%{http_code}" https://api.sereni.dad
# Esperado: 404 (Traefik responde, sin rutas) — NO debe ser 000 (conexión rechazada)

# 3. Verificar la cadena de certificados
openssl s_client \
  -connect api.sereni.dad:443 \
  -servername api.sereni.dad \
  </dev/null 2>/dev/null \
  | grep -E "Verify return code|subject=|issuer="
# Verify return code: 0 (ok) — Sin errores de certificado
# subject=: debe mostrar sereni.dad
# issuer=: debe ser Let's Encrypt (cuando cert-manager haya emitido el certificado)
# En el proceso inicial, puede mostrar el certificado de borde de Cloudflare

# 4. Verificar el header HSTS
curl -sI https://api.sereni.dad | grep -i "strict-transport-security"
# Debe mostrar: strict-transport-security: max-age=31536000; includeSubDomains; preload

# 5. Verificar el header CF-Ray (confirma que el tráfico pasa por Cloudflare)
curl -sI https://api.sereni.dad | grep -i "cf-ray"
# Debe mostrar: CF-Ray: xxxxxxxxxxxx-MAD o similar

# 6. Verificar que la IP real de Hetzner no se filtra en los headers
curl -sI https://api.sereni.dad | grep -i "x-forwarded-for"
# No debe aparecer la FLOATING_IP directamente (Cloudflare la oculta)
```

**Troubleshooting:**
- Si `curl -s -o /dev/null -w "%{http_code}" https://api.sereni.dad` retorna `000`: verificar que el puerto 443 del nodo está abierto en el firewall de Hetzner.
- Si el certificado falla con "self signed": el modo TLS Full Strict requiere un certificado válido en el servidor. Verificar que cert-manager emitió el certificado correctamente (ver HU-04.1 T-04.1.6).
- Si la IP sigue mostrando la de Hetzner en `dig`: el registro DNS no tiene el proxy de Cloudflare activado (ícono naranja). Verificar en la consola de Cloudflare.
