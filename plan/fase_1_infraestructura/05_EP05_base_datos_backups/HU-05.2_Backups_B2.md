# HU-05.2 — Backups Continuos a Backblaze B2 (WAL Archiving + Snapshots)

## Descripción General

CloudNativePG usa **Barman** (Backup and Recovery Manager) para implementar una estrategia de backup de dos niveles:

1. **WAL Archiving continuo:** Cada archivo WAL (Write-Ahead Log) generado por PostgreSQL se sube automáticamente a B2 en tiempo real. Esto habilita **Point-In-Time Recovery (PITR)** — restaurar la base de datos a cualquier segundo exacto dentro del período de retención.

2. **Base Backups diarios (ScheduledBackup):** Un snapshot completo de toda la base de datos a las 02:00 UTC. Estos son la base para restauraciones completas o PITR desde un punto distante.

### Parámetros de recovery

| Métrica | Valor |
|---|---|
| **RPO (Recovery Point Objective)** | ≤ 5 minutos (WAL batch máximo antes de upload) |
| **RTO (Recovery Time Objective)** | 30–60 minutos (restore + replay WAL) |
| **Retención** | 30 días para base backups; WAL implícitamente 90 días |

## Ejecución Detallada

### T-05.2.1 — Cifrar y registrar las credenciales de Backblaze B2

```bash
source .envrc

# Verificar que las credenciales están cargadas desde .envrc
echo "B2_KEY_ID: ${B2_KEY_ID:0:8}..."
echo "B2_APPLICATION_KEY: ${B2_APPLICATION_KEY:0:8}..."
echo "B2_ENDPOINT: ${B2_ENDPOINT}"
echo "B2_BUCKET: ${B2_BUCKET}"

# Cifrar y almacenar en el repositorio
./scripts/encrypt-secret.sh serenidad-data cnpg-b2-credentials \
  "B2_KEY_ID=${B2_KEY_ID}" \
  "B2_APPLICATION_KEY=${B2_APPLICATION_KEY}"

# Verificar cifrado
cat infra/secrets/cnpg-b2-credentials.yaml
# El campo data/ debe mostrar contenido cifrado SOPS

# Habilitar la referencia al secret en el kustomization de CNPG
# Editar infra/infrastructure/cnpg/kustomization.yaml para descomentar la línea:
# - ../../secrets/cnpg-b2-credentials.yaml
sed -i 's|# - ../../secrets/cnpg-b2-credentials.yaml|- ../../secrets/cnpg-b2-credentials.yaml|' \
  infra/infrastructure/cnpg/kustomization.yaml

# Commitear
git add infra/secrets/cnpg-b2-credentials.yaml infra/infrastructure/cnpg/kustomization.yaml
git commit -m "feat(database): add encrypted B2 credentials for WAL archiving"
git push origin main

flux reconcile kustomization flux-system --with-source

# Verificar que FluxCD aplicó el secret
sleep 30
kubectl get secret cnpg-b2-credentials -n serenidad-data
# Debe existir con las claves B2_KEY_ID y B2_APPLICATION_KEY
```

### T-05.2.2 — Verificar el WAL archiving

Una vez que las credenciales están disponibles, CNPG/Barman comenzará a subir archivos WAL a B2 automáticamente.

```bash
# Esperar ~2 minutos y verificar los logs del pod PostgreSQL
kubectl logs serenidad-pg-1 -n serenidad-data --tail=100 \
  | grep -iE "wal|archive|barman|s3|backup"

# Salida esperada (líneas de INFO):
# ... INFO barman: wal_backup: archived WAL file ...
# ... INFO barman: uploading file to s3://serenidad-pg-backups/wal/wals/...

# Si aparecen errores de autenticación (403, 401), las credenciales B2 son incorrectas
# Si aparecen errores de conectividad, verificar resolución DNS desde el cluster

# Forzar un checkpoint para generar actividad WAL y verificar el upload
kubectl exec -it serenidad-pg-1 -n serenidad-data -- \
  psql -U serenidad_admin -c "CHECKPOINT;"

# Verificar en la consola web de Backblaze B2 que aparecen archivos en:
# serenidad-pg-backups/wal/wals/
```

### T-05.2.3 — Configurar el ScheduledBackup diario

```bash
cat > infra/infrastructure/cnpg/scheduled-backup.yaml << 'EOF'
apiVersion: postgresql.cnpg.io/v1
kind: ScheduledBackup
metadata:
  name: serenidad-pg-daily
  namespace: serenidad-data
spec:
  # Ejecutar a las 02:00 UTC (hora de menor carga)
  schedule: "0 2 * * *"
  # immediate: true fuerza la ejecución del primer backup inmediatamente al crear el recurso
  # Esto establece el baseline del que partirá el PITR
  immediate: true
  backupOwnerReference: self
  cluster:
    name: serenidad-pg
  # Método de backup (volumeSnapshot requiere CSI compatible; preferir barmanObjectStore)
  method: barmanObjectStore
EOF

# Commitear el ScheduledBackup
git add infra/infrastructure/cnpg/scheduled-backup.yaml
git commit -m "feat(database): configure daily base backups to Backblaze B2 with immediate first backup"
git push origin main

flux reconcile kustomization flux-system --with-source
```

### T-05.2.4 — Verificar el backup inicial

```bash
# Listar todos los backups del cluster
kubectl get backup -n serenidad-data

# Esperar a que el backup esté en fase Completed (~5-10 minutos según el tamaño inicial)
kubectl wait backup \
  -n serenidad-data \
  --for=jsonpath='{.status.phase}'=completed \
  --timeout=600s \
  --selector=cnpg.io/cluster=serenidad-pg

# Describir el backup para ver el destino en B2
kubectl describe backup -n serenidad-data | grep -E "Destination|Phase|Started|Stopped"
# Destination debe mostrar: s3://serenidad-pg-backups/wal/base/...
# Phase debe mostrar: completed

# Verificar el ScheduledBackup
kubectl get scheduledbackup -n serenidad-data
# NAME                    CLUSTER          LAST BACKUP             STATUS
# serenidad-pg-daily      serenidad-pg     2026-04-07T02:00:00Z    Completed

# Estado completo del sistema de backups
kubectl get cluster serenidad-pg -n serenidad-data \
  -o jsonpath='{.status.conditions}' | jq '.[] | select(.type=="Backup")'
```

### T-05.2.5 — Probar el proceso de restore (PITR simulado)

> **Nota:** Ejecutar este paso solo en un entorno de desarrollo o de validación, no en producción. Un restore de PITR crea un **nuevo** cluster PostgreSQL, no sobrescribe el existente.

```bash
# Obtener el nombre del backup más reciente
LATEST_BACKUP=$(kubectl get backup -n serenidad-data \
  -o jsonpath='{.items[-1].metadata.name}')
echo "Último backup: ${LATEST_BACKUP}"

# Verificar la disponibilidad del backup en B2
kubectl get backup ${LATEST_BACKUP} -n serenidad-data \
  -o jsonpath='{.status.s3Credentials}' 2>/dev/null || \
kubectl describe backup ${LATEST_BACKUP} -n serenidad-data | grep "Destination:"
```

| ID | Criterio | Verificación |

| CA-05.2.7 | Proceso de restore PITR simulado documentado | T-05.2.5 ejecutado: backup identificado, disponibilidad en B2 verificada, procedimiento de `kubectl cnpg restore` documentado |
