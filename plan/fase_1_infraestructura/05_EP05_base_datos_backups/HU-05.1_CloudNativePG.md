# HU-05.1 — CloudNativePG y PostgreSQL 17.4

## Descripción General

CloudNativePG (CNPG) es el operador oficial de PostgreSQL para Kubernetes, mantenido por EDB. Gestiona el ciclo de vida completo de una instancia PostgreSQL — aprovisionamiento, configuración, failover, backups WAL continuos, y restore — mediante Custom Resources de Kubernetes.

Se despliega PostgreSQL 17.4 por su soporte nativo de `UUIDv7` via `gen_random_uuid()`, `pg_stat_statements` mejorado, y mejoras en performance para workloads OLTP. El cluster se configura con una sola instancia en Fase 1 (apropiado para el hardware CX32), con todos los parámetros optimizados para el hardware NVMe de Hetzner.

### Bases de datos creadas en el bootstrap

| Base de datos | Microservicio propietario | Fase |
|---|---|---|
| `iam_db` | IAM Domain Service | 1 |
| `kratos_db` | Ory Kratos | 1 |
| `openfga_db` | OpenFGA (ReBAC) | 3 |
| `scheduling_db` | Scheduling Service | 2 |
| `clinical_db` | Clinical Service | 2 |
| `billing_db` | Billing Service | 3 |

### T-05.1.4 — Cluster PostgreSQL 17.4

> **Nota sobre postInitSQL:** CloudNativePG ejecuta `postInitSQL` en la base de datos especificada en `bootstrap.initdb.database`. Los metacomandos de psql como `\c` no son SQL válido y no funcionan en este contexto. Las extensiones en bases de datos adicionales deben aplicarse manualmente después del bootstrap.

```bash
cat > infra/infrastructure/cnpg/cluster.yaml << 'EOF'
apiVersion: postgresql.cnpg.io/v1
kind: Cluster
metadata:
  name: serenidad-pg
  namespace: serenidad-data
spec:
  instances: 1
  imageName: ghcr.io/cloudnative-pg/postgresql:17.4

  # Parámetros PostgreSQL calibrados para Hetzner CX32 (8 GB RAM, NVMe SSD)
  postgresql:
    shared_preload_libraries:
      - "pg_stat_statements"
    parameters:
      # Memoria: ~25% de 8GB para shared_buffers
      shared_buffers: "512MB"
      # Memoria efectiva de caché: ~75% de 8GB
      effective_cache_size: "1536MB"
      maintenance_work_mem: "128MB"
      # work_mem: 16MB × max_connections (100) = 1.6GB máximo teórico
      work_mem: "16MB"
      max_connections: "100"
      wal_buffers: "16MB"
      # Optimizado para NVMe SSD de Hetzner
      checkpoint_completion_target: "0.9"
      random_page_cost: "1.1"
      effective_io_concurrency: "200"
      min_wal_size: "256MB"
      max_wal_size: "2GB"
      # Logging de queries lentas (>1s) para diagnóstico
      log_min_duration_statement: "1000"
      log_checkpoints: "on"
      log_lock_waits: "on"
      log_temp_files: "0"
      # Soporte para UUID v7 nativo
      enable_partitionwise_join: "on"
      enable_partitionwise_aggregate: "on"

  # Bootstrap: crear las 6 bases de datos
  bootstrap:
    initdb:
      database: postgres
      owner: serenidad_admin
      secret:
        name: cnpg-serenidad-admin-creds
      # IMPORTANTE: postInitSQL solo ejecuta SQL puro, no metacomandos de psql (\c)
      # Las extensiones en DBs específicas se instalan en T-05.1.6
      postInitSQL:
        - "CREATE DATABASE iam_db OWNER serenidad_admin ENCODING 'UTF8' LC_COLLATE 'C' LC_CTYPE 'C' TEMPLATE template0;"
        - "CREATE DATABASE kratos_db OWNER serenidad_admin ENCODING 'UTF8' LC_COLLATE 'C' LC_CTYPE 'C' TEMPLATE template0;"
        - "CREATE DATABASE openfga_db OWNER serenidad_admin ENCODING 'UTF8' LC_COLLATE 'C' LC_CTYPE 'C' TEMPLATE template0;"
        - "CREATE DATABASE scheduling_db OWNER serenidad_admin ENCODING 'UTF8' LC_COLLATE 'C' LC_CTYPE 'C' TEMPLATE template0;"
        - "CREATE DATABASE clinical_db OWNER serenidad_admin ENCODING 'UTF8' LC_COLLATE 'C' LC_CTYPE 'C' TEMPLATE template0;"
        - "CREATE DATABASE billing_db OWNER serenidad_admin ENCODING 'UTF8' LC_COLLATE 'C' LC_CTYPE 'C' TEMPLATE template0;"

  # Backup: configurado con placeholder — las credenciales B2 se añaden en HU-05.2
  backup:
    barmanObjectStore:
      destinationPath: "s3://serenidad-pg-backups/wal"
      # REEMPLAZAR con el endpoint S3 real de tu región B2 (ej: s3.eu-central-003.backblazeb2.com)
      endpointURL: "https://${B2_ENDPOINT}"
      s3Credentials:
        accessKeyId:
          name: cnpg-b2-credentials
          key: B2_KEY_ID
        secretAccessKey:
          name: cnpg-b2-credentials
          key: B2_APPLICATION_KEY
      wal:
        compression: gzip
        maxParallel: 2
      data:
        compression: gzip
        jobs: 2
    retentionPolicy: "30d"

  # Almacenamiento persistente en el NVMe del nodo
  storage:
    size: 20Gi
    storageClass: local-path

  # Recursos del pod
  resources:
    requests:
      cpu: "100m"
      memory: "256Mi"
    limits:
      cpu: "1000m"
      memory: "512Mi"

  # Habilitar SSL/TLS para conexiones a la base de datos
  enableSuperuserAccess: false
EOF

# Resolver la variable B2_ENDPOINT en el archivo
envsubst < infra/infrastructure/cnpg/cluster.yaml > /tmp/cluster-resolved.yaml
mv /tmp/cluster-resolved.yaml infra/infrastructure/cnpg/cluster.yaml
```

### T-05.1.6 — Instalar extensiones en cada base de datos (post-bootstrap)

```bash
# Una vez que el cluster está en estado Ready, instalar extensiones en cada DB
# (no se puede hacer en postInitSQL porque no admite metacomandos \c)

# iam_db: estadísticas de queries y soporte para exclusion constraints de tiempo
kubectl exec -it serenidad-pg-1 -n serenidad-data -- \
  psql -U serenidad_admin -d iam_db -c \
  "CREATE EXTENSION IF NOT EXISTS pg_stat_statements;
   CREATE EXTENSION IF NOT EXISTS btree_gist;"

# kratos_db
kubectl exec -it serenidad-pg-1 -n serenidad-data -- \
  psql -U serenidad_admin -d kratos_db -c \
  "CREATE EXTENSION IF NOT EXISTS pg_stat_statements;"

# scheduling_db: btree_gist para exclusion constraints en rangos de tiempo
kubectl exec -it serenidad-pg-1 -n serenidad-data -- \
  psql -U serenidad_admin -d scheduling_db -c \
  "CREATE EXTENSION IF NOT EXISTS pg_stat_statements;
   CREATE EXTENSION IF NOT EXISTS btree_gist;"

# clinical_db
kubectl exec -it serenidad-pg-1 -n serenidad-data -- \
  psql -U serenidad_admin -d clinical_db -c \
  "CREATE EXTENSION IF NOT EXISTS pg_stat_statements;"

# billing_db
kubectl exec -it serenidad-pg-1 -n serenidad-data -- \
  psql -U serenidad_admin -d billing_db -c \
  "CREATE EXTENSION IF NOT EXISTS pg_stat_statements;"
```

### T-05.1.7 — Verificar el despliegue completo

```bash
# 1. Estado del cluster CNPG
kubectl get cluster serenidad-pg -n serenidad-data
# STATUS: Cluster in healthy state

# 2. Pod del cluster en Running
kubectl get pods -n serenidad-data
# serenidad-pg-1   1/1   Running

# 3. Listar las 6 bases de datos creadas
kubectl exec -it serenidad-pg-1 -n serenidad-data -- \
  psql -U serenidad_admin -c "\l"
# Debe mostrar: iam_db, kratos_db, openfga_db, scheduling_db, clinical_db, billing_db

# 4. Verificar soporte UUIDv7 (nativo en PostgreSQL 17)
kubectl exec -it serenidad-pg-1 -n serenidad-data -- \
  psql -U serenidad_admin -c "SELECT gen_random_uuid();"
# Retorna un UUID v4 (la función gen_random_uuid en PG17 genera UUIDv4 por defecto)
# UUIDv7 requiere pg_uuidv7 extension o generación desde la aplicación

# 5. Verificar parámetros de memoria
kubectl exec -it serenidad-pg-1 -n serenidad-data -- \
  psql -U serenidad_admin -c "SHOW shared_buffers;"
# Debe mostrar: 512MB

# 6. Verificar que los secrets de CNPG fueron creados automáticamente
kubectl get secrets -n serenidad-data | grep cnpg
# serenidad-pg-app         kubernetes.io/basic-auth
# serenidad-pg-superuser   kubernetes.io/basic-auth
# serenidad-pg-ca          Opaque
# serenidad-pg-server      kubernetes.io/tls
```
