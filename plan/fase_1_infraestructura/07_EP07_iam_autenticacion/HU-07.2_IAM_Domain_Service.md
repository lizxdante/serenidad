# HU-07.2 — IAM Domain Service Go (JWT & Outbox Pattern)

## Descripción General
Ory Kratos maneja de maravilla sesiones (Sesión UUID en cookies), sin embargo los microservicios sin estado que diseñaremos (`Scheduling`, `Clinical`, etc.) rinden mejor verificando **Tokens JWT Ed25519** (que contienen el Rol, ID y datos verificables asimétricamente) de forma descentralizada. 

Este servicio en Go actuará de puente. Atrapará la sesión local, consultará a Kratos, la intercambiará por un Token JWT ultra-veloz, creará un perfil local en su base de datos `iam_db`, y además empujará ordenadamente un evento (`UserRegistered` y `DoctorOnboarded`) usando el patrón At-Least-Once-Outbox hacia un bus de datos para el resto del sistema.

---

### T-07.2.2 — Definir Migraciones SQL (Usuarios y Outbox)
Usando lenguaje SQL nativo, prevemos la base sobre la cual el código operará, integrando los principios Row Level Security (RLS) dictados.

```bash
# Tabla primaria "user_profiles"
cat <<EOF > services/iam/internal/db/migrations/000001_create_users.up.sql
CREATE TABLE user_profiles (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    kratos_id UUID NOT NULL UNIQUE,
    tenant_id UUID NOT NULL,
    role TEXT NOT NULL CHECK (role IN ('patient', 'doctor', 'admin')),
    email_hash TEXT NOT NULL,
    did TEXT NOT NULL UNIQUE,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- Indices orientados a búsquedas críticas de autenticación profunda e identidad
CREATE INDEX idx_user_profiles_kratos_id ON user_profiles(kratos_id);
CREATE INDEX idx_user_profiles_tenant_id ON user_profiles(tenant_id);
CREATE INDEX idx_user_profiles_role_tenant ON user_profiles(role, tenant_id);

-- Reglas RLS para garantizar que select solo se exponga si coinciden roles
ALTER TABLE user_profiles ENABLE ROW LEVEL SECURITY;
CREATE POLICY user_own_profile ON user_profiles FOR SELECT USING (true); -- Implementación dummy extendible 
EOF

# Reversiones atadas
cat <<EOF > services/iam/internal/db/migrations/000001_create_users.down.sql
DROP TABLE IF EXISTS user_profiles CASCADE;
EOF

# Tabla Garantizada de Eventos (Outbox)
cat <<EOF > services/iam/internal/db/migrations/000002_create_outbox.up.sql
CREATE TABLE outbox_events (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    aggregate_id UUID NOT NULL,
    aggregate_type TEXT NOT NULL,
    event_type TEXT NOT NULL CHECK (event_type IN ('UserRegistered', 'DoctorOnboarded')),
    payload BYTEA NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    published_at TIMESTAMPTZ,
    retry_count INT NOT NULL DEFAULT 0,
    last_error TEXT
);

-- Crucial: Índice Parcial exclusivo sobre aquellos que no han sido publicados
CREATE INDEX idx_outbox_pending ON outbox_events(created_at) WHERE published_at IS NULL;
EOF

cat <<EOF > services/iam/internal/db/migrations/000002_create_outbox.down.sql
DROP TABLE IF EXISTS outbox_events CASCADE;
EOF
```

### T-07.2.5 — Definir Dockerfile y Entorno Distroless de Ejecución
Aunque el equipo de Go desarrollará el contenido, requeriremos compilar de forma "containerizada". Construiremos en dos fases para minimizar el peso y cerrar el acceso al bash y exploits. (Distroless nonroot).

```bash
cat <<EOF > services/iam/Dockerfile
# Etapa 1: Compilador super veloz
FROM golang:1.25-alpine AS builder
WORKDIR /app
COPY go.mod ./ # A futuro go.sum
RUN go mod download
COPY . .
# Trimpath esconde los metadatos de donde se compliló, ldflags compacta.
RUN CGO_ENABLED=0 go build -trimpath -ldflags="-w -s" -o iam-service ./cmd/server

# Etapa 2: Distroless. Cero dependencias adicionales ni capas innecesarias
FROM gcr.io/distroless/static-debian12:nonroot
WORKDIR /app
COPY --from=builder /app/iam-service .
COPY --from=builder /app/internal/db/migrations ./migrations

EXPOSE 8080
USER nonroot:nonroot
ENTRYPOINT ["/app/iam-service"]
EOF

# Comando visual que correrá CI/CD pero que sirve localmente (Opcional)
# docker build -t registry.gitlab.com/serenidad/serenidad-platform/iam-service:latest -f services/iam/Dockerfile services/iam/
```

### T-07.2.6 — Generación de Claves Criptográficas Ed25519 (EdDSA) para Tokens
Los JWT requieren firmas imborrables e infalsificables. Las llaves *EdDSA* son las más ultra rápidas y recomendadas para entornos microservicio según los más recientes RFCs. 

```bash
# Usamos tmp por seguridad local
openssl genpkey -algorithm ed25519 -out /tmp/jwt_private_key.pem
openssl pkey -in /tmp/jwt_private_key.pem -pubout -out /tmp/jwt_public_key.pem

# Inyectamos al cluster usando SOPS y Age
./scripts/encrypt-secret.sh serenidad-core iam-service-secrets \
  JWT_PRIVATE_KEY_ED25519="$(cat /tmp/jwt_private_key.pem)" \
  JWT_PUBLIC_KEY_ED25519="$(cat /tmp/jwt_public_key.pem)"

# Borramos rastros físicos (extremadamente crítico limpiar esto)
rm -f /tmp/jwt_private_key.pem /tmp/jwt_public_key.pem
```

*(Asumimos `T-07.2.7`: `infra/secrets/gitlab-registry-secret.yaml` configurado usando tu PAT).*

### T-07.2.8 — Aprovisionamiento en Kubernetes (Deployment & Service)
Este componente requiere un InitContainer que corra las migraciones SQL que incrustamos en la imagen de Docker, y aplicar Security Context que deniega escalados.

```bash
mkdir -p infra/apps/iam-service

cat <<EOF > infra/apps/iam-service/deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: iam-service
  namespace: serenidad-core
spec:
  replicas: 1
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxUnavailable: 0
      maxSurge: 1
  selector:
    matchLabels:
      app: iam-service
  template:
    metadata:
      labels:
        app: iam-service
    spec:
      imagePullSecrets:
        - name: gitlab-registry-secret
      initContainers:
        - name: migrate
          image: registry.gitlab.com/serenidad/serenidad-platform/iam-service:latest
          command: ["/app/iam-service", "migrate"]
          env:
            - name: DATABASE_URL
              value: "postgres://serenidad_admin:\${PG_ADMIN_PASSWORD}@serenidad-pg-rw.serenidad-data.svc.cluster.local:5432/iam_db?sslmode=require"
      containers:
        - name: iam-service
          image: registry.gitlab.com/serenidad/serenidad-platform/iam-service:latest
          ports:
            - containerPort: 8080
          env:
            - name: ENVIRONMENT
              value: "production"
            - name: PORT
              value: "8080"
            - name: KRATOS_ADMIN_URL
              value: "http://kratos-admin.serenidad-core.svc.cluster.local:4434"
            - name: DATABASE_URL
              value: "postgres://serenidad_admin:\${PG_ADMIN_PASSWORD}@serenidad-pg-rw.serenidad-data.svc.cluster.local:5432/iam_db?sslmode=require"
            - name: JWT_ISSUER
              value: "iam-service.sereni.dad"
            - name: JWT_AUDIENCE
              value: "sereni.dad-services"
            - name: JWT_TTL_SECONDS
              value: "900"
            - name: JWT_PRIVATE_KEY_ED25519
              valueFrom:
                secretKeyRef:
                  name: iam-service-secrets
                  key: JWT_PRIVATE_KEY_ED25519
            - name: JWT_PUBLIC_KEY_ED25519
              valueFrom:
                secretKeyRef:
                  name: iam-service-secrets
                  key: JWT_PUBLIC_KEY_ED25519
          livenessProbe:
            httpGet:
              path: /health
              port: 8080
            initialDelaySeconds: 10
            periodSeconds: 30
          readinessProbe:
            httpGet:
              path: /ready
              port: 8080
            initialDelaySeconds: 5
            periodSeconds: 10
          resources:
            requests:
              memory: "40Mi"
              cpu: "20m"
            limits:
              memory: "128Mi"
              cpu: "500m"
          securityContext:
            runAsNonRoot: true
            runAsUser: 65534
            readOnlyRootFilesystem: true
            allowPrivilegeEscalation: false
            capabilities:
              drop: ["ALL"]
---
apiVersion: v1
kind: Service
metadata:
  name: iam-service
  namespace: serenidad-core
spec:
  type: ClusterIP
  selector:
    app: iam-service
  ports:
    - protocol: TCP
      port: 8080
      targetPort: 8080
EOF
```

### T-07.2.9 y T-07.2.10 — Ingress y Sincronización
La exposición del IAM y su integración con Kustomize.

```bash
cat <<EOF > infra/apps/iam-service/ingressroute.yaml
apiVersion: traefik.io/v1alpha1
kind: IngressRoute
metadata:
  name: iam-service-public
  namespace: serenidad-core
spec:
  entryPoints:
    - websecure
  routes:
    # Nota: El endpoint vital '/internal/validate-token' NO se expone aquí para evitar que usuarios externos ataquen la puerta.
    - match: Host(\`api.sereni.dad\`) && PathPrefix(\`/api/iam/\`)
      kind: Rule
      services:
        - name: iam-service
          port: 8080
      middlewares:
        - name: security-headers
          namespace: traefik
  tls:
    certResolver: letsencrypt
EOF

# Empaqueta Todo Kustomize
cat <<EOF > infra/apps/iam-service/kustomization.yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
namespace: serenidad-core
resources:
  - deployment.yaml
  - ingressroute.yaml
  - ../../secrets/iam-service-secrets.yaml
  - ../../secrets/gitlab-registry-secret.yaml
  - ../../secrets/cnpg-serenidad-admin-creds.yaml
EOF

git add services/iam infra/apps/iam-service infra/secrets/iam-service-secrets.yaml
git commit -m "feat(iam): deploy core IAM bridging service built in Go with strict EDDSA tokens"
git push origin main
flux reconcile kustomization flux-system --with-source
```
