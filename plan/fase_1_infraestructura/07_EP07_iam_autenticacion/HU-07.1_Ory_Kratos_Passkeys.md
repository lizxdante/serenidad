# HU-07.1 — Ory Kratos v1.3.1 (Identidad y Passkeys)

## Descripción General
Para gestionar la identidad sin depender de contraseñas (que son inherentemente inseguras y generan alta fricción), confiaremos en **Ory Kratos**, el motor de identidad nativo de la nube por excelencia. Desactivaremos la autenticación tradicional e impulsaremos *Passkeys/WebAuthn* (reconocimiento facial, huella en el dispositivo) o el envío de códigos mágicos al correo (vía Resend) como método de reserva.

### ¿Qué configuraremos?
1. **Modelos (Schemas):** Kratos permite tener múltiples perfiles. Tendremos uno de `Paciente` con requerimientos flexibles y uno de `Doctor` con requerimientos estrictos (licencia médica).
2. **Criptografía de Sesión:** Proveeremos y aseguraremos cifrados de galletas (cookies) usando SOPS.
3. **Flujos (Flows):** Instruiremos redirecciones y controles entre la base de datos PostgreSQL y la red K8s Traefik.

### T-07.1.2 — Proveer Modelos y Arquitecturas de Identidad (Schemas)

```bash
mkdir -p infra/apps/kratos/schemas

  "properties": {
    "traits": {
      "type": "object",
      "properties": {
        "email": {
          "type": "string",
          "format": "email",
          "title": "E-Mail",
          "ory.sh/kratos": {
            "credentials": {
              "password": { "identifier": true },
              "webauthn": { "identifier": true },
              "code": { "identifier": true }
            },
            "recovery": { "via": "email" },
            "verification": { "via": "email" }
          }
        },
        "name": {
          "type": "object",
          "properties": {
            "first": { "type": "string" },
            "last": { "type": "string" }
          }
```

### T-07.1.3 — Sellado Analítico y Cifrado de las Llaves de Sesión
Kratos depende de cadenas largas de tokens para encriptar internamente los cookies del usuario final y evitar secuestros. Aprovecharemos SOPS y OpenSSL para emitirlas directamente en la terminal.

```bash
# Variables crudas temporales
export KRATOS_COOKIE_SECRET=$(openssl rand -hex 32)
export KRATOS_CIPHER_SECRET=$(openssl rand -hex 32)

echo "Tus Secretos Temporales en este Shell generados."
echo "IMPORTANTE: Asegúrate de guardar KRATOS_COOKIE_SECRET y KRATOS_CIPHER_SECRET en Bitwarden u otro Gestor."
# Recordatorio: RESEND_API_KEY se asume obtenido en EP-01 T-01.1.5

# Llamamos al compendio script cifrador para almacenar sin exponer
./scripts/encrypt-secret.sh serenidad-core kratos-secrets \
  KRATOS_COOKIE_SECRET=${KRATOS_COOKIE_SECRET} \
  KRATOS_CIPHER_SECRET=${KRATOS_CIPHER_SECRET} \
  RESEND_API_KEY=${RESEND_API_KEY}

unset KRATOS_COOKIE_SECRET KRATOS_CIPHER_SECRET
```

### T-07.1.4 y T-07.1.5 — Configurar HelmRelease e IngressRoute Kratos
En esta declaración conectaremos a la Base de Datos aprovisionada en la Fase Anterior (`kratos_db`) y dictaremos las políticas de URL Front/API.

```bash
# Definiremos el Release inyectando todo el archivo maestro
cat <<EOF > infra/apps/kratos/helmrelease.yaml
apiVersion: helm.toolkit.fluxcd.io/v2
kind: HelmRelease
metadata:
  name: kratos
  namespace: serenidad-core
spec:
  interval: 10m
  dependsOn:
    - name: cnpg
      namespace: cnpg-system
    - name: traefik
      namespace: traefik
  chart:
    spec:
      chart: kratos
      version: '0.50.x'
      sourceRef:
        kind: HelmRepository
        name: ory
        namespace: flux-system
  install:
    createNamespace: true
  values:
    kratos:
      config:
        # Cadena de conexión hacia Postgres
        dsn: "postgres://serenidad_admin:\${PG_ADMIN_PASSWORD}@serenidad-pg-rw.serenidad-data.svc.cluster.local:5432/kratos_db?sslmode=require"
        serve:
          public:
            base_url: https://api.sereni.dad/auth/
            cors:
              enabled: true
              allowed_origins: 
                - https://app.sereni.dad
          admin:
            base_url: http://kratos-admin.serenidad-core.svc.cluster.local:4434/
        selfservice:
          default_browser_return_url: https://app.sereni.dad/
          methods:
            password:
              enabled: false # Filosofía Passwordless
            webauthn: # Passkeys Biometria Web
              enabled: true
              config:
                passwordless: true
                rp:
                  display_name: "Serenidad Clínica Digital"
                  id: "sereni.dad"
                  origins:
                    - https://app.sereni.dad
            code:
              enabled: true
          flows:
            login:
              ui_url: /login
              lifespan: 1h
            registration:
              ui_url: /register
              lifespan: 30m
            verification:
              enabled: true
              use: code
        identity:
          default_schema_id: patient
          schemas:
            - id: patient
              url: file:///etc/config/schemas/patient.json
            - id: doctor
              url: file:///etc/config/schemas/doctor.json
        courier:
          smtp:
            connection_uri: smtps://resend:\${RESEND_API_KEY}@smtp.resend.com:465/
            from_address: noreply@sereni.dad
      # Inyectar las referencias del secreto creado SOPS
      secret:
        cookie:
          - \${KRATOS_COOKIE_SECRET}
        cipher:
          - \${KRATOS_CIPHER_SECRET}
    
    # Recursos para la BD al correr migraciones o ejecución
    job:
      shareProcessNamespace: true
    resources:
      requests:
        memory: "128Mi"
        cpu: "50m"
      limits:
        memory: "256Mi"
        cpu: "500m"
EOF

# Y ahora enlazamos la ruta publica HTTP hacia el mundo
cat <<EOF > infra/apps/kratos/ingressroute.yaml
apiVersion: traefik.io/v1alpha1
kind: IngressRoute
metadata:
  name: kratos-public
  namespace: serenidad-core
spec:
  entryPoints:
    - websecure
  routes:
    - match: Host(\`api.sereni.dad\`) && PathPrefix(\`/auth/\`)
      kind: Rule
      services:
        - name: kratos-public
          port: 4433
      middlewares:
        - name: security-headers
          namespace: traefik
  tls:
    certResolver: letsencrypt
    domains:
      - main: api.sereni.dad
EOF
```

### T-07.1.6 y T-07.1.7 — Commitear y Validadar
Cerramos integrando todo a Kustomize y evaluando la respuesta directa del motor.

```bash

apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
namespace: serenidad-core
resources:
  - helmrepository.yaml
  - helmrelease.yaml

  - ../../secrets/kratos-secrets.yaml

git commit -m "feat(iam): deploy ory kratos with passwordless configuration and passkeys"
git push origin main
flux reconcile kustomization flux-system --with-source

# T-07.1.7: Probar que está operando en la IP y la BD migrada.
```
