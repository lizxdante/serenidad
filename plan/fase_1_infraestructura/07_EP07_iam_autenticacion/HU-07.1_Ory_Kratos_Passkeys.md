# HU-07.1 — Ory Kratos v1.3.x: Gestión de Identidades con Passkeys

## Descripción General

Ory Kratos es el motor de identidad cloud-native de la plataforma. Reemplaza la gestión de autenticación de capa de aplicación por un sistema dedicado que implementa los flujos OAuth2/OIDC, Passkey/WebAuthn (FIDO2), y magic codes por email.

Las decisiones arquitectónicas clave son:
- **Passwords deshabilitadas:** Se eliminan contraseñas para reducir la superficie de ataque (phishing, credential stuffing)
- **Passkeys como método principal (WebAuthn/FIDO2):** Autenticación biométrica o PIN del dispositivo, resistente a phishing
- **Magic codes por email como fallback:** Codes OTP de 6 dígitos via Resend cuando el dispositivo no soporta Passkeys
- **Dos identity schemas:** `patient` (requisitos flexibles) y `doctor` (requiere licencia médica y especialidad)

### T-07.1.3 — Generar y cifrar secrets de Kratos

```bash
source .envrc

# Generar secrets criptográficamente seguros
KRATOS_COOKIE_SECRET=$(openssl rand -hex 32)
KRATOS_CIPHER_SECRET=$(openssl rand -hex 32)

echo "================================================================"
echo "SECRETS DE KRATOS — GUARDAR EN PASSWORD MANAGER"
echo "Cookie Secret: ${KRATOS_COOKIE_SECRET}"
echo "Cipher Secret: ${KRATOS_CIPHER_SECRET}"
echo "================================================================"

# Cifrar con SOPS
./scripts/encrypt-secret.sh serenidad-core kratos-secrets \
  "KRATOS_COOKIE_SECRET=${KRATOS_COOKIE_SECRET}" \
  "KRATOS_CIPHER_SECRET=${KRATOS_CIPHER_SECRET}" \
  "RESEND_API_KEY=${RESEND_API_KEY}"

# Limpiar rastro en shell
unset KRATOS_COOKIE_SECRET KRATOS_CIPHER_SECRET
```

### T-07.1.4 — HelmRelease de Kratos

```bash
cat > infra/apps/kratos/helmrelease.yaml << 'EOF'
apiVersion: helm.toolkit.fluxcd.io/v2
kind: HelmRelease
metadata:
  name: kratos
  namespace: serenidad-core
spec:
  interval: 10m
  dependsOn:
    - name: cnpg
      namespace: cnpg-system
    - name: traefik
      namespace: traefik
  chart:
    spec:
      chart: kratos
      version: ">=0.50.0 <1.0.0"
      sourceRef:
        kind: HelmRepository
        name: ory
        namespace: flux-system
      interval: 1h
  install:
    createNamespace: true
    remediation:
      retries: 3
  valuesFrom:
    - kind: Secret
      name: kratos-secrets
      valuesKey: KRATOS_COOKIE_SECRET
      targetPath: kratos.config.secrets.cookie[0]
    - kind: Secret
      name: kratos-secrets
      valuesKey: KRATOS_CIPHER_SECRET
      targetPath: kratos.config.secrets.cipher[0]
    - kind: Secret
      name: kratos-secrets
      valuesKey: RESEND_API_KEY
      targetPath: kratos.config.courier.smtp.connection_uri
  values:
    kratos:
      automigration:
        enabled: true
      config:
        dsn: "postgres://serenidad_admin@serenidad-pg-rw.serenidad-data.svc.cluster.local:5432/kratos_db?sslmode=require&password=$(CNPG_ADMIN_PASS)"
        serve:
          public:
            base_url: "https://api.sereni.dad/auth/"
            cors:
              enabled: true
              allowed_origins:
                - "https://app.sereni.dad"
              allowed_methods: ["POST", "GET", "PUT", "PATCH", "DELETE", "OPTIONS"]
              allowed_headers: ["Authorization", "Cookie", "Content-Type", "X-Session-Token"]
              exposed_headers: ["Content-Type", "Set-Cookie"]
              allow_credentials: true
          admin:
            base_url: "http://kratos-admin.serenidad-core.svc.cluster.local:4434/"
        selfservice:
          default_browser_return_url: "https://app.sereni.dad/"
          allowed_return_urls:
            - "https://app.sereni.dad"
          flows:
            login:
              ui_url: "https://app.sereni.dad/login"
              lifespan: 1h
            registration:
              ui_url: "https://app.sereni.dad/register"
              lifespan: 30m
            verification:
              enabled: true
              use: code
              ui_url: "https://app.sereni.dad/verification"
              lifespan: 15m
            recovery:
              enabled: true
              use: code
              ui_url: "https://app.sereni.dad/recovery"
              lifespan: 15m
            settings:
              ui_url: "https://app.sereni.dad/settings"
              privileged_session_max_age: 15m
            logout:
              default_browser_return_url: "https://app.sereni.dad/"
          methods:
            passkey:
              enabled: true
              config:
                rp:
                  display_name: "serenidad — Clínica Digital"
                  id: "sereni.dad"
                  origins:
                    - "https://app.sereni.dad"
            webauthn:
              enabled: false
            password:
              enabled: false
            code:
              enabled: true
              config:
                lifespan: 15m
        identity:
          default_schema_id: patient
          schemas:
            - id: patient
              url: "file:///etc/config/identity.patient.schema.json"
            - id: doctor
              url: "file:///etc/config/identity.doctor.schema.json"
        courier:
          smtp:
            # La connection_uri se inyecta desde el secret kratos-secrets
            from_address: "noreply@sereni.dad"
            from_name: "serenidad"
          templates:
            verification:
              valid:
                email:
                  subject: "Verifica tu correo — serenidad"
            recovery:
              valid:
                email:
                  subject: "Recupera tu acceso — serenidad"
      identitySchemas:
        "identity.patient.schema.json": |
          (contenido de patient.json — leer desde archivo)
        "identity.doctor.schema.json": |
          (contenido de doctor.json — leer desde archivo)
      resources:
        requests:
          memory: "128Mi"
          cpu: "50m"
        limits:
          memory: "256Mi"
          cpu: "500m"
EOF
```

> **Nota de implementación:** Para inyectar los schemas JSON como `identitySchemas` en el HelmRelease, la forma más limpia es usar un ConfigMap referenciado por `valuesFrom`, o incluir el contenido JSON inline. El ejemplo anterior usa placeholders — en la implementación real, incluir el JSON completo de los archivos `schemas/patient.json` y `schemas/doctor.json`.

### T-07.1.5 — IngressRoute para el endpoint público de Kratos

```bash
cat > infra/apps/kratos/ingressroute.yaml << 'EOF'
apiVersion: traefik.io/v1alpha1
kind: IngressRoute
metadata:
  name: kratos-public
  namespace: serenidad-core
spec:
  entryPoints:
    - websecure
  routes:
    - match: "Host(`api.sereni.dad`) && PathPrefix(`/auth/`)"
      kind: Rule
      middlewares:
        - name: security-headers
          namespace: traefik
      services:
        - name: kratos-public
          port: 4433
  tls:
    certResolver: letsencrypt
    domains:
      - main: api.sereni.dad
EOF
```

```bash
kubectl exec -it serenidad-pg-1 -n serenidad-data -- \
  psql -U serenidad_admin -d kratos_db -c "\dt" | head -20
# Debe mostrar las tablas internas de Kratos (identities, sessions, etc.)

# 5. Verificar que el método Passkey está habilitado en el flow de registro
curl -s "https://api.sereni.dad/auth/self-service/registration/browser" | \
  jq '.ui.nodes[] | select(.group == "passkey") | .type'
# Debe retornar "input" (el nodo del formulario de Passkey está presente)
```
