# HU-06.1 — Schemas de Eventos Protobuf (Buf CLI y Golang)

## Descripción General
En las arquitecturas de microservicios guiadas por eventos (Event-Driven), o al utilizar un patrón de envío diferido (Outbox Pattern), el contrato entre quien emite la información y quien la procesa debe ser de hierro. Utilizaremos **Protocol Buffers (Protobuf)**, un lenguaje neutro de Google, para definir las estructuras exactas de nuestros eventos de dominio. 

Para gestionar su validación (Linting) y la generación del código a nuestro lenguaje principal (Golang), nos apoyaremos en `buf.build`, una herramienta estandarizada más moderna y amigable que el viejo compilador `protoc`.

---

## Ejecución Detallada

### T-06.1.1 — Inicializar Workspace del Compilador (Buf)
Requeriremos un área común en nuestro monorepo donde los publicadores y los subscriptores puedan extraer el código Go seguro de los eventos.

```bash
# 1. Navegar a la carpeta designada para los esquemas compartidos en el monorepo
mkdir -p packages/events
cd packages/events

# 2. Inicializar el workspace (esto crea un archivo buf.yaml predeterminado)
buf config init

# 3. Sobre-escribir el buf.yaml con las estrictas reglas del proyecto
cat <<EOF > buf.yaml
version: v2
modules:
  - path: proto
    name: buf.build/serenidad/events
lint:
  use:
    - STANDARD
breaking:
  use:
    - FILE
EOF

# 4. Proveer las reglas de generación hacia nuestro compilador Golang (buf.gen.yaml)
cat <<EOF > buf.gen.yaml
version: v2
managed:
  enabled: true
  override:
    - file_option: go_package_prefix
      value: gitlab.com/serenidad/serenidad-platform/packages/events/gen
plugins:
  # Plugin estándar de Golang para la serialización binaria protobuf
  - plugin: buf.build/protocolbuffers/go
    out: gen/go
    opt: paths=source_relative
  # Plugin para la capa de servicios gRPC
  - plugin: buf.build/grpc/go
    out: gen/go
    opt: 
      - paths=source_relative
      - require_unimplemented_servers=false
EOF
```

### T-06.1.2 — Definir el Contrato de Identidad (IAM v1)
Declararemos los esquemas vitales del alta de pacientes y doctores. Se incluyen identificadores `UUIDv7`, `hash` y marcas de tiempo nativas.

```bash
mkdir -p proto/iam/v1/

cat <<EOF > proto/iam/v1/events.proto
syntax = "proto3";

package iam.v1;

option go_package = "gitlab.com/serenidad/serenidad-platform/packages/events/gen/iam/v1;iamv1";

import "google/protobuf/timestamp.proto";

message UserRegistered {
  string event_id = 1;
  string user_id = 2;
  string tenant_id = 3;
  string email = 4;
  string role = 5;
  string did = 6;
  google.protobuf.Timestamp occurred_at = 7;
  google.protobuf.Timestamp emitted_at = 8;
}

message DoctorOnboarded {
  string event_id = 1;
  string doctor_id = 2;
  string tenant_id = 3;
  string specialty = 4;
  string license_number = 5;
  string country_code = 6;
  google.protobuf.Timestamp occurred_at = 7;
  google.protobuf.Timestamp emitted_at = 8;
}
EOF
```

### T-06.1.5 y T-06.1.6 — Lint, Compilación y Consumo en Golang
La estructura está definida humanamente. Deberemos auditar semánticamente para asegurar las reglas internas del estándar protobuf, y luego invocar la compilación a nuestro lenguaje nativo para que un programa pueda importar el código.

```bash
# Estando dentro de packages/events/
# 1. Ejecutar análisis sintáctico (linter)
buf lint
# Si tu salida es limpia (no arroja textos de error de espacios o nombres en mayúscula/minúscula), estamos perfectos.

# 2. Generar el código Go nativo
buf generate

# Verás que ha aparecido una carpeta llamada 'gen' repletas de código Golang puro (*.pb.go) a partir 
# de los schemas definidos. Cada microservicio descargará esta carpeta completa y auto-generada por nosotros.

# 3. Dar de alta esto como un módulo publico/privado de Golang
cd gen/go
go mod init gitlab.com/serenidad/serenidad-platform/packages/events/gen
go mod tidy   # Se traerá dependencias oficiales protobuf y gRPC de Google 

# 4. Prueba rápida de compilación: Garantizar que el modulo autogenerado carece de errores internos
go build ./...
```

### T-06.1.7 y T-06.1.8 — Establecer Baseline de Retro-Compatibilidad y Commit General
Las reglas de los mensajes dictan que nunca podemos eliminar campos ni alterar su tipo de dato original una vez que hayan ido a producción. Usaremos la auditoría temporal de buf para esto.

```bash
# Estando dentro de packages/events/
# Revisa que no has quebrado tu código versus lo que está en git. 
# Siendo la primera vez que enviamos el código, esto no reportará cambios rompientes.
buf breaking --against ".git#branch=main"

# Empujar el motor de contratos entero a nuestro source of truth.
cd ../../
git add packages/events/
git commit -m "feat(events): add protobuf event schemas and autogenerated module for IAM, Scheduling, and Clinical phases"
git push origin main
```
