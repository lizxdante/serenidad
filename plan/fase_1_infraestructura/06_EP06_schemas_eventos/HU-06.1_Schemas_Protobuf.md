# HU-06.1 — Schemas de Eventos con Protocol Buffers y Buf CLI

## Descripción General

Los eventos de dominio son el contrato de comunicación entre microservicios. Al usar **Protocol Buffers** (protobuf), se garantiza que el contrato sea:

- **Fuertemente tipado:** Los compiladores de cada lenguaje generan código con tipos nativos
- **Eficiente:** Serialización binaria ~10x más compacta que JSON
- **Versionable:** `buf breaking` detecta automáticamente cambios que rompen la compatibilidad

**Buf CLI v2** moderniza el toolchain de protobuf eliminando la necesidad de gestionar el compilador `protoc` y sus plugins manualmente. Se usa como workspace con el protocolo `buf.build/` para gestión de dependencias.

### Dominios y eventos cubiertos en Fase 1

| Dominio | Eventos |

| **Scheduling v1** | `AppointmentBooked`, `AppointmentCancelled` |

## Ejecución Detallada

### T-06.1.1 — Inicializar el workspace de Buf

```bash
mkdir -p packages/events/proto
cd packages/events

# Crear la configuración del módulo Buf v2
cat > buf.yaml << 'EOF'
version: v2
modules:
  - path: proto
    name: buf.build/serenidad/events
lint:
  use:
    - STANDARD
  except:
    - PACKAGE_VERSION_SUFFIX  # Permitir versioning manual en nombres de paquete
breaking:
  use:
    - FILE
EOF

# Configuración de generación de código Go
cat > buf.gen.yaml << 'EOF'
version: v2
managed:
  enabled: true
  override:
    - file_option: go_package_prefix
      value: gitlab.com/serenidad/serenidad-platform/packages/events/gen
plugins:
  # Plugin estándar de Go para serialización protobuf
  - plugin: buf.build/protocolbuffers/go
    out: gen/go
    opt: paths=source_relative
  # Plugin para servicios gRPC en Go
  - plugin: buf.build/grpc/go
    out: gen/go
    opt:
      - paths=source_relative
      - require_unimplemented_servers=false
EOF
```

### T-06.1.2 — Schema IAM v1

```bash
mkdir -p proto/iam/v1

cat > proto/iam/v1/events.proto << 'EOF'
syntax = "proto3";

package iam.v1;

option go_package = "gitlab.com/serenidad/serenidad-platform/packages/events/gen/iam/v1;iamv1";

import "google/protobuf/timestamp.proto";

// UserRegistered: emitido cuando un nuevo usuario completa el registro en Kratos
// y el IAM Domain Service crea su perfil local.
message UserRegistered {
  // event_id: UUIDv7 — identificador único del evento (incluye timestamp)
  string event_id = 1;
  // user_id: UUIDv7 — identificador del perfil en user_profiles
  string user_id = 2;
  // tenant_id: UUIDv7 — organización o clínica propietaria
  string tenant_id = 3;
  // email: SHA-256 hash del email en hexadecimal — nunca texto plano en eventos
  string email_hash = 4;
  // role: patient | doctor | admin
  string role = 5;
  // did: Decentralized Identifier en formato did:web:sereni.dad:<user_id>
  string did = 6;
  google.protobuf.Timestamp occurred_at = 7;
  google.protobuf.Timestamp emitted_at = 8;
}

// DoctorOnboarded: emitido cuando un médico completa el proceso de alta
// incluyendo la validación de su número de licencia.
message DoctorOnboarded {
  string event_id = 1;
  // doctor_id: UUIDv7 — coincide con user_id del UserRegistered correspondiente
  string doctor_id = 2;
  string tenant_id = 3;
  // specialty: psychiatry | psychology | general_medicine | ...
  string specialty = 4;
  string license_number = 5;
  // country_code: ISO 3166-1 alpha-2 (ej: MX, CO, PE)
  string country_code = 6;
  google.protobuf.Timestamp occurred_at = 7;
  google.protobuf.Timestamp emitted_at = 8;
}
EOF
```

  string event_id = 1;
  string appointment_id = 2;

### T-06.1.5 — Lint, generación y validación del código

```bash
# Desde packages/events/

# 1. Lint: verificar que los schemas cumplen el estándar protobuf
buf lint
# Sin output = sin errores de lint
# Si hay errores: seguir las sugerencias del output para corregir los schemas

# 2. Verificar que no hay cambios breaking respecto a la rama main
buf breaking --against ".git#branch=main"
# Primera vez: no reporta cambios (no hay baseline previo)

# 3. Generar el código Go
buf generate
# Crea la estructura:
# gen/go/iam/v1/events.pb.go
# gen/go/iam/v1/events_grpc.pb.go
# gen/go/scheduling/v1/events.pb.go
# gen/go/scheduling/v1/events_grpc.pb.go
# gen/go/clinical/v1/events.pb.go
# gen/go/clinical/v1/events_grpc.pb.go

# Verificar la estructura generada
find gen/go -name "*.pb.go" | sort

# 4. Inicializar el módulo Go del paquete generado
cd gen/go
go mod init gitlab.com/serenidad/serenidad-platform/packages/events/gen
go mod tidy  # Descargar dependencias: google.golang.org/protobuf, google.golang.org/grpc

# 5. Compilar para verificar que el código generado es válido
go build ./...
# Sin errores = código válido

cd ../../../  # Volver a la raíz del monorepo
```

### Nota sobre versionado y compatibilidad hacia el futuro

Los schemas de protobuf siguen las reglas de compatibilidad del protocolo:

- **Permitido:** Añadir nuevos campos con nuevos field numbers al final
- **Permitido:** Añadir nuevos tipos de mensajes
- **Prohibido:** Eliminar campos existentes, cambiar su tipo, o reusar su field number
- **Prohibido:** Cambiar el nombre del paquete o del tipo Go sin deprecar el anterior

`buf breaking` en el pipeline de CI (EP-09) detectará automáticamente cualquier violación de estas reglas antes de que llegue a producción.
