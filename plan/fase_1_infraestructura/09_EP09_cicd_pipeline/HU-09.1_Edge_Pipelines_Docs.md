# HU-09.1 (Parte B): Pipelines del Edge (BFF, Web) y Variables Entorno

## Descripción General
Nuestras utilidades de interfaz (La Web SPA y el Endrutador BFF) tienen que someterse al mismo tratamiento automático que nuestro microservicio Go.
A diferencia de *FluxCD* (el cual "hala" los cambios), para el borde confiaremos de un modelo de *Envío Directo* (Push), donde los runners de GitLab ejecutarán `wrangler` pasándole los Tokens de Autorización de la cuenta Cloudflare proveída mediante las variables de entorno para compilar el sitio instantáneamente contra la CDN.

---

## Ejecución Detallada

### T-09.1.3 — Pipeline de Deploy del BFF a Cloudflare Workers
Para esto se requieren las variables CI/CD `CF_API_TOKEN` y `CF_ACCOUNT_ID` ya precargadas en Settings -> CI/CD -> Variables de tu GitLab. 

```bash
cat <<'EOF' > .gitlab/ci/deploy-bff.yml
deploy-bff:
  stage: deploy
  image: node:22-alpine
  rules:
    - if: $CI_COMMIT_BRANCH == "main"
      changes:
        - apps/bff/**/*
        - .gitlab/ci/deploy-bff.yml
  before_script:
    - npm install -g bun wrangler --silent
    - cd apps/bff 
    - bun install --frozen-lockfile
  script:
    - bun run tsc --noEmit
    - wrangler deploy
  variables:
    # Se enlazan los secretos cargados en Gitlab
    CLOUDFLARE_API_TOKEN: $CF_API_TOKEN
    CLOUDFLARE_ACCOUNT_ID: $CF_ACCOUNT_ID
EOF
```

### T-09.1.4 — Pipeline de Deploy de Qwik SPA a Cloudflare Pages
El proceso es muy parecido, con la única variación requiriendo cargar antes aquellas rutas amarradas al compilador del frontend (El ruteo duro Vite hacia Kratos y BFF).

```bash
cat <<'EOF' > .gitlab/ci/deploy-web.yml
deploy-web:
  stage: deploy
  image: node:22-alpine
  rules:
    - if: $CI_COMMIT_BRANCH == "main"
      changes:
        - apps/web/**/*
        - .gitlab/ci/deploy-web.yml
  before_script:
    - npm install -g bun wrangler --silent
    - cd apps/web
    - bun install --frozen-lockfile
  script:
    - bun run build
    - wrangler pages deploy dist/ --project-name=serenidad-web --branch=main
  variables:
    # Inyectadas al momento de build por Vite
    VITE_API_BASE_URL: "https://api.sereni.dad/bff"
    VITE_KRATOS_URL: "https://api.sereni.dad/auth"
    CLOUDFLARE_API_TOKEN: $CF_API_TOKEN
    CLOUDFLARE_ACCOUNT_ID: $CF_ACCOUNT_ID
EOF
```

### Commit y Sincronización Final
Aplica estos cambios a tu control de versiones:

```bash
git add .gitlab-ci.yml .gitlab/ci/
git commit -m "feat(ci): configure selective edge pipelines for bff and web modules"
git push origin main
```

### T-09.1.8 — Demostraciones de Activación Selectiva
Para verificar que nuestras directriz `rules.changes` actúa según el mandato económico (para no derrochar minutos CI/CD):
1. **Prueba Irrelevante**: Modifica o agrega `README.md` a la subcarpeta `/docs` o `/plans`. Da commit. Al verificar GitLab no debe haberse lanzado ni un solo runner de build ni deploy.
2. **Prueba Aislada**: Cambia una coma al index de la APP. Debería dispararse sólo `.gitlab/ci/deploy-web.yml` sin afectar al IAM service.

### T-09.1.9 — Diccionario de Variables Automáticas Documentadas
Estas variables son inyectadas en tu sesión Runner cada vez que se ejecute la canalización. Resultan sumamente importantes de comprender ya que nuestro flujo de `iam-service.yml` se sostiene puramente de su magia paramétrica:

| Variable Interna                   | Valor Documentado y Explicado |
| ---------------------------------- | --------- |
| **`$CI_REGISTRY`**                 | Por defecto será `registry.gitlab.com`. |
| **`$CI_REGISTRY_USER`** / **`PASSWORD`** | GitLab genera usuarios sintéticos de base de vida efímera que expiran post-pipeline. Perfectos para Logins programáticos. |
| **`$CI_REGISTRY_IMAGE`**           | Tu namespace asignado para tus contenedores (Ej: `registry.gitlab.com/serenidad/serenidad-platform`). |
| **`$CI_COMMIT_SHORT_SHA`**         | Firma algorítmica y única truncada de 8 dígitos de tu modificación (commit base). Es el ADN de la versión desplegada en el Kubernetes. |
| **`$CI_JOB_TOKEN`**                | Token supersecretillo que viaja interno permitiendo al bot clonar/pushear evadiendo restricciones HTTP básicas. Evita crear SSH keys manualmente. |
| **`$CI_PROJECT_PATH`**             | El nombre del proyecto y grupo relativo `serenidad/serenidad-platform`. |
