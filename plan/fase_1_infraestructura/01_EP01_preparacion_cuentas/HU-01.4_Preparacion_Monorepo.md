# HU-01.4 — Preparación del Monorepo y Bootstrap Inicial

## Descripción General
Lanzaremos la arquitectura de trabajo unificada ("Monorepo"). Todos los manifiestos de Kubernetes (Yaml), el código backend y el frontend vivirán lado a lado. Asimismo, vincularemos localmente el repositorio mediante SSH con GitLab y crearemos una llave especial que residirá dentro de nuestro futuro sistema operativo en Hetzner para recuperación crítica en caso de desastres severos.

### ¿Qué infraestructura tocamos?
- **Sistema Local de Archivos**: Directorios y el gestor de control de versiones `Git`.
- **Hetzner Cloud Identity**: Registraremos una llave criptográfica.
- **GitLab CI/CD Environment Variables**: Inyectamos secretos al sistema de pipelines en su nube para que GitLab pueda correr automatizaciones que mofiquen nuestra web y desplieguen cosas a la nube sin requerirnos de forma local.

## Ejecución Detallada por Tareas

### T-01.4.1 — Estructura de Directorios

Dirígete a tu terminal de trabajo de ciencia de datos/ingeniería y ejecuta el andamio.

```bash
# Clonar y Entrar (Remplaza con tu url correcta)
git clone git@gitlab.com:serenidad/serenidad-platform.git
cd serenidad-platform

# Creación de árbol completo
mkdir -p infra/clusters/hetzner-prod/talos/patches
mkdir -p infra/clusters/hetzner-prod/flux-system
mkdir -p infra/infrastructure/{cert-manager,traefik,cnpg,nats}
mkdir -p infra/apps/{iam-service,kratos,scheduling-service,clinical-service,billing-service,openfga}
mkdir -p infra/secrets
mkdir -p services/{iam,scheduling,clinical,billing}
mkdir -p packages/events/proto
mkdir -p apps/{web,bff}
mkdir -p scripts

# Creación del .gitignore con las exclusiones críticas definidas:
cat <<EOF > .gitignore
# Ambientes locales y variables
.envrc
*.env
*.env.local
.env.*

# Secretos Cluster (Nunca subirlos)
*.talosconfig
secrets.yaml
kubeconfig

# Dependencias lenguaje y builds
node_modules/
dist/
.wrangler/
*.wasm
bin/
vendor/

# Archivos de SO
.DS_Store
Thumbs.db
EOF

# Validación de commit
git add .
git commit -m "chore: initial monorepo structure and gitignore"
git push origin main
```

### T-01.4.2 — Configurar SSH Key "Rescue" para Hetzner

Nos servirá cuando la VM esté mal de configuración o si necesitamos conectarnos "por debajo" del sistema de Kubernetes desde la consola de rescate de Hetzner.

```bash
# Generamos una llave Ed25519 (muy segura y moderna). Almacena sus datos en ~/.ssh
# Agrega un passphrase si lo crees necesario pero deberás guardarlo en tu PM
ssh-keygen -t ed25519 -C "admin-hetzner-serenidad" -f ~/.ssh/hetzner_serenidad_ed25519

# (Requiere de tu HU-01.3 haber hecho source de tu .envrc con token de Hetzner)
hcloud context use serenidad-production

# Subimos la clave publica hacia nuestra consola de Hetzner (para poder insertarla automáticamente cuando creemos la máquina virtual futuramente)
hcloud ssh-key create --name "serenidad-admin-key" --public-key-from-file ~/.ssh/hetzner_serenidad_ed25519.pub

# Verificamos
hcloud ssh-key list
```

> **Critico:** Ve a tu archivo `~/.ssh/hetzner_serenidad_ed25519` (la clave privada sin `.pub` al final), ábrelo con un editor (`cat`), cópialo entero y mételo en una "Nota Segura" de tu Password Manager. Si cambias de pc, necesitarás esta llave para revivir el servidor subyacente.

### T-01.4.3 — Configurar variables CI/CD en GitLab

Haremos que GitLab conozca nuestros tokens remotos. En lugar de ir por la interfaz gráfica dando clics incontables veces y marcando el `checkbox` de "*Mask variable*" a mano (que evita que las passwords se lean en los logs de la consola en internet), lo haremos como programadores ágiles utilizando CLI oficial.

Usaremos tu token de autenticación (generado en HU-01.1):
```bash
# Autenticar glab
glab auth login
# Sigue las instrucciones, elige GitLab.com, HTTPs, y pega tu GITLAB_TOKEN cuando te lo pida.

# Asegurate de que estás parado dentro de la carpeta del reporsitorio en la terminal.
# Injectamos las variables a GitLab y nos aseguraremos que esten masked (enmascaradas) para no filtrarlas.

# (Las leemos desde nuestra sesion actual que cargó .envrc)
glab variable set HCLOUD_TOKEN $HCLOUD_TOKEN --masked
glab variable set CF_API_TOKEN $CF_API_TOKEN --masked
glab variable set CF_ACCOUNT_ID $CF_ACCOUNT_ID --masked
glab variable set B2_KEY_ID $B2_KEY_ID --masked
glab variable set B2_APPLICATION_KEY $B2_APPLICATION_KEY --masked
glab variable set RESEND_API_KEY $RESEND_API_KEY --masked

# Verificación
glab variable list
```
