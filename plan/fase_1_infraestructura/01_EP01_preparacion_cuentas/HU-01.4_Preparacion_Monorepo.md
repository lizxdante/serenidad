# HU-01.4 — Preparación del Monorepo y Bootstrap Inicial

## Descripción General

Esta historia establece la estructura de directorios del monorepo, la llave SSH de rescate para acceso de emergencia al VPS, y las variables CI/CD en GitLab que permiten a los pipelines operar con los secretos de la plataforma sin exponerlos en el código.

El monorepo adopta una arquitectura de "todo bajo un mismo repositorio": manifiestos de Kubernetes, código de microservicios Go, aplicaciones TypeScript (BFF y SPA), y schemas de Protobuf conviven con separación clara por directorio.

---

### T-01.4.3 — Commit inicial

```bash
git add .gitignore
git add infra/ services/ packages/ apps/ scripts/ .gitlab/

# Verificar que .envrc NO está incluido
git status --porcelain | grep ".envrc"
# No debe aparecer nada

git commit -m "chore: initial monorepo structure and gitignore"
git push origin main

# Verificar en GitLab que la estructura de carpetas es visible
echo "Repositorio inicializado: https://gitlab.com/${GITLAB_GROUP}/${GITLAB_REPO}"
```

### T-01.4.4 — Generar y registrar SSH Key de rescate para Hetzner

Esta llave permite el acceso de emergencia al servidor desde la consola de rescate de Hetzner cuando el cluster Kubernetes no está disponible. Solo se usa en situaciones críticas.

```bash
# Generar llave Ed25519 (más eficiente y segura que RSA 4096)
ssh-keygen -t ed25519 \
  -C "serenidad-admin-hetzner" \
  -f ~/.ssh/hetzner_serenidad_ed25519

# No usar passphrase si se requiere acceso automatizado, o usar una almacenada en PM

# Verificar la llave generada
ssh-keygen -l -f ~/.ssh/hetzner_serenidad_ed25519.pub
# Muestra: 256 SHA256:... serenidad-admin-hetzner (ED25519)

# Registrar la clave pública en el proyecto de Hetzner
hcloud context create serenidad-production --token "${HCLOUD_TOKEN}"
hcloud context use serenidad-production

hcloud ssh-key create \
  --name "serenidad-admin-key" \
  --public-key-from-file ~/.ssh/hetzner_serenidad_ed25519.pub

# Verificar que la clave fue registrada
hcloud ssh-key list
# Debe aparecer: serenidad-admin-key
```

> **CRÍTICO:** Abrir el archivo `~/.ssh/hetzner_serenidad_ed25519` (clave **privada**, sin `.pub`), copiar su contenido completo (incluyendo `-----BEGIN OPENSSH PRIVATE KEY-----` y `-----END OPENSSH PRIVATE KEY-----`) y almacenarlo como una nota segura en el Password Manager bajo el nombre `hetzner_serenidad_ed25519 (PRIVATE KEY)`.

### T-01.4.5 — Configurar variables CI/CD en GitLab

GitLab necesita conocer los tokens de los servicios externos para que los pipelines puedan operar de forma autónoma. Se configuran como variables enmascaradas (masked) para que no aparezcan en los logs de CI.

**Instalar y autenticar `glab` CLI:**
```bash
# Instalar glab (GitLab CLI)
GLAB_VERSION=$(curl -s https://api.github.com/repos/gitlab-org/cli/releases/latest | jq -r '.tag_name')
curl -sLO "https://gitlab.com/gitlab-org/cli/-/releases/${GLAB_VERSION}/downloads/glab_${GLAB_VERSION#v}_Linux_x86_64.tar.gz"
tar -xzf "glab_${GLAB_VERSION#v}_Linux_x86_64.tar.gz"
sudo mv bin/glab /usr/local/bin/
rm -rf bin/ "glab_${GLAB_VERSION#v}_Linux_x86_64.tar.gz"

# Autenticar con el PAT de GitLab
glab auth login --hostname gitlab.com --token "${GITLAB_TOKEN}"

# Verificar autenticación
glab auth status
```

**Registrar las 6 variables CI/CD como masked:**
```bash
# Posicionarse en el directorio del repositorio
cd serenidad-platform

# Registrar cada variable como masked (no visible en logs de pipeline)
glab variable set HCLOUD_TOKEN       --value "${HCLOUD_TOKEN}"       --masked --type env_var
glab variable set CF_API_TOKEN       --value "${CF_API_TOKEN}"       --masked --type env_var
glab variable set CF_ACCOUNT_ID      --value "${CF_ACCOUNT_ID}"      --masked --type env_var
glab variable set B2_KEY_ID          --value "${B2_KEY_ID}"          --masked --type env_var
glab variable set B2_APPLICATION_KEY --value "${B2_APPLICATION_KEY}" --masked --type env_var
glab variable set RESEND_API_KEY     --value "${RESEND_API_KEY}"     --masked --type env_var

# Verificar que las 6 variables están registradas
glab variable list
# Debe listar las 6 variables con tipo "env_var" y masked=true
```
