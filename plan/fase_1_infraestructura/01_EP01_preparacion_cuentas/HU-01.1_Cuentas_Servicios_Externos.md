# HU-01.1 — Creación de Cuentas en Servicios Externos

## Descripción General
Esta historia de usuario abarca la creación de cuentas "fundacionales". Al ser servicios gestionados en la nube (SaaS), la interacción requerida será primordialmente gráfica e iterativa en las plataformas de los proveedores. 

### ¿Qué infraestructura tocamos y para qué?
1. **GitLab:** Será nuestra fuente de verdad (Source of Truth). Almacenará el código (Monorepo), ejecutará pipelines (CI) y guardará imágenes de contenedores (Container Registry, que será jalado directamente por Kubernetes).
2. **Hetzner Cloud:** Proveedor del hardware "Bare Metal" virtualizado (VPS) donde instalaremos el sistema operativo inmutable (Talos Linux) y encima nuestro cluster de Kubernetes.
3. **Cloudflare:** Gestionará la zona DNS y será necesario para el desafío `DNS-01` que usará `cert-manager` para asegurar que todo tráfico sea HTTPS (certificados Let's Encrypt automáticos). Además, en fases posteriores, los *Workers* manejarán funciones al borde o el BFF de UI.
4. **Backblaze B2:** Object Storage compatible con S3. El operador de bases de datos `CloudNativePG` lo utilizará para volcar todos los backups (WAL files) periódicamente (disaster recovery).
5. **Resend:** Nuestro servicio SMTP para envíos de correo transaccionales.

## Ejecución Detallada por Tareas

### T-01.1.1 — Crear y configurar cuenta de GitLab
**Interacción:** Consola web de GitLab.
1. Dirígete a [gitlab.com](https://gitlab.com) y crea tu cuenta si no tienes una. Crea un grupo o workspace llamado `serenidad`.
2. Crea un nuevo proyecto en blanco (privado) llamado `serenidad-platform`. **No lo inicialices con un README aún.**
3. Verifica Runners: En el menú lateral -> **Settings -> CI/CD -> Runners**. Asegúrate de que los "Shared runners" están habilitados. (Estos corren los jobs de CI usando minutos gratuitos).
4. **Generar PAT (Personal Access Token):**
   - Ve a tus Preferencias de usuario (Perfil -> Edit Profile -> Access Tokens).
   - Genera uno nuevo con los scopes: `api`, `read_repository`, `write_repository`, `read_registry`, `write_registry`.
   - **IMPORTANTE:** Guarda este valor en tu Password Manager (ej. Bitwarden, 1Password) como `GITLAB_TOKEN`. Solo se muestra una vez.
5. **Generar Deploy Token:**
   - En el repositorio `serenidad-platform` ve a **Settings -> Repository -> Deploy tokens**.
   - Nombre: `k8s-registry-puller` (ejemplo).
   - Scopes: `read_repository`, `read_registry`.
   - Guarda el *Username* y el *Token* generados en tu Password Manager. Esto lo usará Kubernetes para identificarse ante GitLab y descargar las imágenes Docker.

### T-01.1.2 — Crear y configurar cuenta de Hetzner Cloud
**Interacción:** Consola web de Hetzner Cloud (`console.hetzner.cloud`).
1. Regístrate y verifica tu identidad (Hetzner puede requerir validación manual, ten paciencia).
2. Crea un nuevo proyecto y llámalo `serenidad-production`. Este proyecto agrupará tus servidores, IPs, volúmenes de almacenamiento y redes.
3. **Generar API Token:**
   - Dentro de tu proyecto, ve a **Security -> API Tokens**.
   - Genera un token nuevo con permisos **Read & Write**.
   - Guárdalo en tu Password Manager como `HCLOUD_TOKEN`. Las herramientas de consola e infraestructura como código usarán este token para crear las VMs automáticamente.

### T-01.1.3 — Crear y configurar cuenta de Cloudflare
**Interacción:** Consola web de Cloudflare.
1. Crea una cuenta en [cloudflare.com](https://cloudflare.com).
2. Agrega tu dominio (`sereni.dad`) como un "Sitio". Elige el plan gratuito ("Free").
3. Cloudflare te dará dos "Nameservers" (ej: `carl.ns.cloudflare.com`). Ve al registrador donde compraste el dominio (Namecheap, GoDaddy, etc.) y reemplaza los Nameservers por los de Cloudflare. Espera a que los cambios se propaguen.
4. **Obtención de IDs:** 
   - Ve al panel "Overview" de tu dominio en Cloudflare. 
   - A la derecha abajo, encontrarás tu **Zone ID** y **Account ID**. Guárdalos en tu PM.
5. **Generar API Token de DNS:**
   - Ve a **Mi Perfil -> API Tokens -> Create Token**. Usa el template "Edit zone DNS" o custom. Necesitas:
     - Permisos: `Zone -> DNS -> Edit`, `Account -> Cloudflare Pages -> Edit`, `Account -> Workers Scripts -> Edit`.
     - Zone Resources: Include -> Specific Zone -> `sereni.dad`.
   - Guarda el token en tu PM como `CF_API_TOKEN`. `cert-manager` en Kubernetes lo usará para verificar la propiedad del dominio y pedir certificados TLS.

### T-01.1.4 — Crear y configurar cuenta de Backblaze B2
**Interacción:** Consola B2 (`backblaze.com/b2/cloud-storage`).
1. Crea una cuenta y actívala.
2. Ve a **Buckets** y dale a "Create a Bucket".
   - Nombre: `serenidad-pg-backups` (nota: los nombres B2 son globales para toda la región, puede requerir prefijo si colisiona; ej: `tudominio-pg-backups`).
   - Visibilidad: **Private**.
   - Default Encryption: Habilitado (Server-Side Encryption).
3. Ve a **Application Keys** y haz clic en "Add a New Application Key".
   - Nombre: `cnpg-barman-key`.
   - Permite acceso **exclusivo** al bucket `serenidad-pg-backups`.
   - Tipo de acceso: Read & Write.
   - Copia el `KeyID` y la `applicationKey` (secreto) e ingrésalos al Password Manager (`B2_KEY_ID` y `B2_APPLICATION_KEY`). El operador de Base de Datos de Kubernetes entrará por un canal encriptado enviando estos backups a Backblaze usando la compatibilidad con el API de Amazon S3.

### T-01.1.5 — Crear y configurar cuenta de Resend (SMTP)
**Interacción:** Consola de [resend.com](https://resend.com).
1. Crea tu cuenta.
2. Ve a **Domains** -> Add Domain (`sereni.dad`).
3. Resend te dará registros DNS (TXT para DKIM, SPF). Ve a Cloudflare -> "DNS -> Records" e inserta exactamente esos valores.
4. Una vez verificados en la consola de Resend, ve a **API Keys**.
   - Crea un "Sending API key" limitado al dominio `sereni.dad`.
   - Guarda tu clave en el PM como `RESEND_API_KEY`. Los microservicios utilizarán esta llave para disparar e-mails de notificaciones.
