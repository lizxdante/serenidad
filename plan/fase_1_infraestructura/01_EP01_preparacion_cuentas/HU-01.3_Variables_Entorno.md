# HU-01.3 — Configuración de Variables de Entorno de Trabajo

## Descripción General
Para evitar escribir tokens gigantescos en la consola o, peor aún, incrustarlos accidentalmente en archivos subidos al servidor remoto o a GitLab, usaremos un archivo oculto local llamado `.envrc`.

### ¿Qué infraestructura tocamos?
El entorno Shell Local. El archivo `.envrc` no se sincroniza al repositorio. Lo cargaremos temporalmente en memoria (RAM de la terminal) para inyectar estos secretos hacia utilitarios como `hcloud` (Hetzner CLI), `flux` o instaladores de infraestructura.

---

## Ejecución Detallada por Tareas

### T-01.3.1 — Crear archivo `.envrc`
Crea el archivo en la raíz del monorepo clonado o por clonarse en tu máquina (ej: `~/proyectos/serenidad-platform/.envrc`).

Edita o crea el archivo en bash, y complétalo basándote en los datos del Password Manager extraídos en la HU-01.1:

```bash
# ==============================================================
# .envrc - Variables de entorno locales (NO COMITEAR ESTE ARCHIVO)
# ==============================================================

# Hetzner Cloud
export HCLOUD_TOKEN="<TU_API_TOKEN_DE_HETZNER>"
export HETZNER_PROJECT="serenidad-production"
export VPS_IP="" # Se llenará luego, cuando Hetzner asigne una IP a nuestra VM

# GitLab Config
export GITLAB_TOKEN="<TU_PAT_PERSONAL>"
export GITLAB_USER="<TU_USUARIO_DE_GITLAB>"
export GITLAB_REPO="serenidad/serenidad-platform"
export GITLAB_DEPLOY_TOKEN_USER="k8s-registry-puller"
export GITLAB_DEPLOY_TOKEN="<TU_DEPLOY_TOKEN>"

# Cloudflare (DNS)
export CF_API_TOKEN="<TU_TOKEN_API_CLOUDFLARE>"
export CF_ZONE_ID="<TU_ZONE_ID>"
export CF_ACCOUNT_ID="<TU_ACCOUNT_ID>"
export CF_DOMAIN="sereni.dad"

# Backblaze B2 Storage (PostgreSQL Backups)
export B2_KEY_ID="<TU_B2_KEY_ID>"
export B2_APPLICATION_KEY="<TU_B2_APP_KEY>"
export B2_BUCKET="serenidad-pg-backups"
export B2_ENDPOINT="s3.eu-central-003.backblazeb2.com" # Cambiar dependiendo de la región que te haya asignado B2

# Resend Mail
export RESEND_API_KEY="<TU_RESEND_API_KEY>"

# Contextos de Cluster (Archivos que Kubernetes y Talos crearán localmente luego)
export KUBECONFIG="$(pwd)/kubeconfig"
export TALOSCONFIG="$(pwd)/infra/clusters/hetzner-prod/talos/talosconfig"
```

### Asegurar la privacidad del archivo

Ejecuta lo siguiente antes de hacer cualquier commit de git en tu monorepo:
```bash
echo ".envrc" >> .gitignore
git status # .envrc no debe salir en archivos modificados/sin rastrear
```

### Validar y cargar en shell actual

Siempre que trabajes en este proyecto, deberás cargarlo en tu pestaña de la terminal:
```bash
source .envrc
echo $HCLOUD_TOKEN # Debería imprimir tu token
```

### T-01.3.2 — Automatizar carga (Direnv)

Para evitar escribir `source .envrc` en cada pestaña de la terminal, los programadores suelen instalar una herramienta en background llamada `direnv`.

```bash
# Instalación Ubuntu/Debian/WSL
sudo apt install direnv
# O con bash
curl -sfL https://direnv.net/install.sh | bash

# Si usas BASH, agrega esto al final de tu `~/.bashrc`:
eval "$(direnv hook bash)"

# Si usas ZSH, agrégalo a tu `~/.zshrc`:
eval "$(direnv hook zsh)"
```

**Test:** Abre una nueva pestaña de la terminal, entra en la carpeta del repositorio. `direnv` preguntará si deseas autorizar el archivo. Escribes `direnv allow` la primera vez, y de ahí en adelante cargará todas las variables secretas mágicamente, aislando estas de otras carpetas.
