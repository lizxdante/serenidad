# HU-01.3 — Configuración de Variables de Entorno de Trabajo

## Descripción General

Para evitar escribir tokens en la terminal o incrustarlos en archivos que puedan llegar al repositorio Git, se centraliza el acceso a credenciales en un archivo `.envrc` local que jamás es versionado. Este archivo es la fuente de verdad de las variables de sesión para todas las herramientas CLI utilizadas durante el ciclo de desarrollo e infraestructura.

`direnv` cargará automáticamente este archivo al entrar al directorio del proyecto, aislando las variables de otras carpetas del sistema.

---

## Ejecución Detallada

### T-01.3.1 — Crear el archivo `.envrc`

Crear el archivo en la raíz del monorepo (se clonará o creará en HU-01.4). Completar con los valores del Password Manager obtenidos en HU-01.1:

```bash
# Crear o editar el archivo
cat > .envrc << 'EOF'
# ==============================================================
# .envrc — Variables de entorno locales del proyecto serenidad
# ESTE ARCHIVO NUNCA DEBE SER VERSIONADO EN GIT
# ==============================================================

# ── Hetzner Cloud ──────────────────────────────────────────────
export HCLOUD_TOKEN=""           # API Token Read&Write del proyecto serenidad-production
export HETZNER_PROJECT="serenidad-production"
export VPS_IP=""                 # IP dinámica asignada por Hetzner al servidor (se llena en EP-02)
export FLOATING_IP=""            # Floating IP (IP fija) del servidor (se llena en EP-02)

# ── GitLab ────────────────────────────────────────────────────
export GITLAB_TOKEN=""           # Personal Access Token (api, read/write_registry, read/write_repository)
export GITLAB_USER=""            # Username de GitLab (ej: miperfil)
export GITLAB_REPO="serenidad-platform"
export GITLAB_GROUP="serenidad"
export GITLAB_DEPLOY_TOKEN_USER="" # Username del Deploy Token (ej: gitlab+deploy-token-123)
export GITLAB_DEPLOY_TOKEN=""    # Token del Deploy Token para k8s-registry-puller

# ── Cloudflare ────────────────────────────────────────────────
export CF_API_TOKEN=""           # API Token con Zone DNS Edit, Pages Edit, Workers Edit
export CF_ZONE_ID=""             # Zone ID del dominio sereni.dad
export CF_ACCOUNT_ID=""          # Account ID de la cuenta de Cloudflare
export CF_DOMAIN="sereni.dad"

# ── Backblaze B2 (PostgreSQL Backups via S3-compatible API) ────
export B2_KEY_ID=""              # Application Key ID (cnpg-barman-key)
export B2_APPLICATION_KEY=""     # Application Key secreta
export B2_BUCKET="serenidad-pg-backups"
export B2_ENDPOINT=""            # Endpoint S3 de B2 (ej: s3.eu-central-003.backblazeb2.com)

# ── Resend (SMTP transaccional para Kratos) ────────────────────
export RESEND_API_KEY=""         # API Key con Sending access al dominio sereni.dad

# ── Talos Linux (se generan en EP-02 HU-02.2) ─────────────────
export TALOS_VERSION=""              # Versión de Talos (ej: v1.10.0) — se llena en HU-02.2
export TALOS_SCHEMATIC_ID=""         # Schematic ID de Image Factory — se llena en HU-02.2

# ── Configuración de Kubernetes (se generan en EP-02 y EP-03) ──
export KUBECONFIG="${PWD}/infra/clusters/hetzner-prod/kubeconfig"
export TALOSCONFIG="${PWD}/infra/clusters/hetzner-prod/talos/talosconfig"

# ── Age/SOPS (se genera en EP-03) ─────────────────────────────
export SOPS_AGE_KEY_FILE="${HOME}/.config/sops/age/keys.txt"
EOF
```

### T-01.3.2 — Proteger el archivo con `.gitignore`

El archivo `.envrc` no debe aparecer nunca en `git status` como untracked:

```bash
# Añadir al .gitignore del monorepo
echo ".envrc" >> .gitignore

# Verificar que git lo ignora correctamente
git check-ignore -v .envrc
# Debe mostrar: .gitignore:1:.envrc  .envrc

# Confirmar que no aparece en git status
git status --porcelain | grep ".envrc"
# No debe aparecer ninguna línea
```

### T-01.3.3 — Instalar y configurar `direnv`

`direnv` carga automáticamente el `.envrc` al entrar al directorio del proyecto:

```bash
# Instalación en Ubuntu/Debian/WSL
sudo apt-get update && sudo apt-get install -y direnv

# Configurar el hook según el shell utilizado:

# Para Bash — añadir al final de ~/.bashrc:
echo 'eval "$(direnv hook bash)"' >> ~/.bashrc
source ~/.bashrc

# Para Zsh — añadir al final de ~/.zshrc:
echo 'eval "$(direnv hook zsh)"' >> ~/.zshrc
source ~/.zshrc
```

**Autorizar el directorio:**
```bash
cd /ruta/al/monorepo/serenidad-platform
direnv allow .
# direnv: loading .envrc
# direnv: export +HCLOUD_TOKEN +CF_API_TOKEN ... (todas las variables)
```

A partir de este momento, al entrar al directorio del proyecto las variables se cargarán automáticamente. Al salir, se descargarán.

### T-01.3.4 — Validar que todas las variables tienen valor

Ejecutar el siguiente script de validación para detectar variables vacías:

```bash
#!/usr/bin/env bash
source .envrc

REQUIRED_VARS=(
  HCLOUD_TOKEN HETZNER_PROJECT
  GITLAB_TOKEN GITLAB_USER GITLAB_REPO GITLAB_DEPLOY_TOKEN_USER GITLAB_DEPLOY_TOKEN
  CF_API_TOKEN CF_ZONE_ID CF_ACCOUNT_ID CF_DOMAIN
  B2_KEY_ID B2_APPLICATION_KEY B2_BUCKET B2_ENDPOINT
  RESEND_API_KEY
)

MISSING=0
for var in "${REQUIRED_VARS[@]}"; do
  if [[ -z "${!var}" ]]; then
    echo "✗ Falta: $var"
    MISSING=$((MISSING + 1))
  else
    echo "✓ $var = ${!var:0:8}..."  # Muestra solo los primeros 8 caracteres
  fi
done

if [[ $MISSING -gt 0 ]]; then
  echo ""
  echo "ERROR: ${MISSING} variable(s) sin valor. Completar el .envrc con los datos del Password Manager."
  exit 1
fi
echo ""
echo "Todas las variables de entorno están configuradas correctamente."
```

## Criterios de Aceptación

| ID | Criterio | Verificación |
|----|----------|--------------|
| CA-01.3.1 | El archivo `.envrc` existe en la raíz del monorepo | `ls -la .envrc` |
| CA-01.3.2 | `.envrc` está en `.gitignore` y no aparece en `git status` | `git check-ignore -v .envrc` muestra match |
| CA-01.3.3 | `direnv` carga las variables al entrar al directorio | `echo $HCLOUD_TOKEN` muestra el token tras `cd` |
| CA-01.3.4 | Todas las variables tienen valor no vacío | Script de validación retorna 0 variables faltantes |
| CA-01.3.5 | `$KUBECONFIG` y `$TALOSCONFIG` apuntan a rutas relativas correctas | `echo $KUBECONFIG` muestra ruta con `/infra/clusters/` |

## Definition of Done

- [ ] El archivo `.envrc` existe con todas las variables declaradas
- [ ] `.envrc` está en `.gitignore` y confirmado con `git check-ignore`
- [ ] `direnv` está instalado con hook en el shell activo
- [ ] El script de validación retorna éxito (0 variables faltantes)
- [ ] Las variables de Kubernetes y SOPS apuntan a las rutas correctas del monorepo
