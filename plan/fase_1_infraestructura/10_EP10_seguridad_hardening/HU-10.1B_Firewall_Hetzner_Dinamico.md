# HU-10.1 (Parte B) — Firewall Dinámico de Hetzner Cloud

## Descripción General

El Hetzner Cloud Firewall aplicado en EP-02 restringió los puertos administrativos críticos (`50000/tcp` para el API de Talos y `6443/tcp` para el API de Kubernetes) a la IP fija del administrador durante el aprovisionamiento inicial. Sin embargo, los ISPs residenciales y de oficina asignan IPs dinámicas que cambian con cada reconexión o periódicamente.

Cuando la IP cambia, `talosctl` y `kubectl` dejan de responder, bloqueando cualquier operación de mantenimiento. Este script resuelve el problema detectando la IP pública actual y actualizando el Hetzner Firewall en segundos.

### Comportamiento correcto de `hcloud firewall replace-rules`

El CLI de `hcloud` **no tiene** un comando `remove-rule` ni `add-rule` para modificar reglas individuales. La forma correcta es **reemplazar la totalidad de las reglas** del firewall con `replace-rules`, que acepta un array JSON con el conjunto completo de reglas deseadas.

El script:
1. Descarga las reglas actuales del firewall via API REST de Hetzner
2. Identifica y filtra las reglas de los puertos 50000 y 6443
3. Construye el conjunto completo de reglas con la nueva IP
4. Llama a `replace-rules` con el conjunto completo

## Ejecución Detallada

### T-10.1.8 — Crear el script de actualización dinámica

```bash
mkdir -p scripts

cat > scripts/update-firewall.sh << 'SCRIPT'
#!/usr/bin/env bash
# =============================================================================
# update-firewall.sh — Actualiza las reglas del Hetzner Firewall con la IP
# pública actual del administrador.
#
# Uso: ./scripts/update-firewall.sh
# Requiere: curl, jq, HCLOUD_TOKEN en el entorno
# =============================================================================
set -euo pipefail

# ── Configuración ─────────────────────────────────────────────────────────────
FW_NAME="serenidad-prod-fw"
ADMIN_PORTS=(50000 6443)          # Puertos administrativos protegidos
PUBLIC_PORTS=(80 443)             # Puertos públicos abiertos a todos
HETZNER_API="https://api.hetzner.cloud/v1"

# ── Validaciones previas ──────────────────────────────────────────────────────
if [ -z "${HCLOUD_TOKEN:-}" ]; then
  echo "ERROR: La variable HCLOUD_TOKEN no está definida."
  echo "  Ejecuta 'source .envrc' o exporta HCLOUD_TOKEN manualmente."
  exit 1
fi

if ! command -v jq &> /dev/null; then
  echo "ERROR: 'jq' no está instalado. Instálalo con: brew install jq / apt install jq"
  exit 1
fi

# ── Detectar la IP pública actual ─────────────────────────────────────────────
echo "Detectando IP pública actual..."
CURRENT_IP=$(curl -s -4 --max-time 5 https://ifconfig.me)

if [[ ! "$CURRENT_IP" =~ ^[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+$ ]]; then
  echo "ERROR: No se pudo detectar una IPv4 válida. Respuesta obtenida: '${CURRENT_IP}'"
  exit 1
fi

echo "IP pública actual: ${CURRENT_IP}/32"

# ── Obtener el ID del firewall por nombre ─────────────────────────────────────
echo "Buscando firewall '${FW_NAME}'..."
FW_RESPONSE=$(curl -s \
  -H "Authorization: Bearer ${HCLOUD_TOKEN}" \
  "${HETZNER_API}/firewalls?name=${FW_NAME}")

FW_ID=$(echo "$FW_RESPONSE" | jq -r '.firewalls[0].id // empty')

if [ -z "$FW_ID" ]; then
  echo "ERROR: No se encontró el firewall con nombre '${FW_NAME}'."
  echo "  Verifica el nombre con: hcloud firewall list"
  exit 1
fi

echo "Firewall encontrado — ID: ${FW_ID}"

# ── Construir el conjunto completo de reglas ──────────────────────────────────
# Hetzner replace-rules reemplaza TODAS las reglas; debemos incluir las públicas.
# Estructura del JSON de reglas:
# {
#   "direction": "in",
#   "protocol": "tcp",
#   "port": "80",
#   "source_ips": ["0.0.0.0/0", "::/0"],
#   "description": "HTTP público"
# }

RULES_JSON=$(cat << RULES
[
  {
    "direction": "in",
    "protocol": "tcp",
    "port": "80",
    "source_ips": ["0.0.0.0/0", "::/0"],
    "description": "HTTP — acceso público para ACME HTTP-01 y redirects"
  },
  {
    "direction": "in",
    "protocol": "tcp",
    "port": "443",
    "source_ips": ["0.0.0.0/0", "::/0"],
    "description": "HTTPS — tráfico de aplicación (Traefik/Cloudflare)"
  },
  {
    "direction": "in",
    "protocol": "tcp",
    "port": "50000",
    "source_ips": ["${CURRENT_IP}/32"],
    "description": "Talos API — acceso restringido al administrador actual"
  },
  {
    "direction": "in",
    "protocol": "tcp",
    "port": "6443",
    "source_ips": ["${CURRENT_IP}/32"],
    "description": "Kubernetes API — acceso restringido al administrador actual"
  }
]
RULES
)

# ── Aplicar las reglas via API REST ───────────────────────────────────────────
echo "Actualizando reglas del firewall ${FW_ID}..."
RESPONSE=$(curl -s -w "\n%{http_code}" \
  -X POST \
  -H "Authorization: Bearer ${HCLOUD_TOKEN}" \
  -H "Content-Type: application/json" \
  -d "{\"rules\": ${RULES_JSON}}" \
  "${HETZNER_API}/firewalls/${FW_ID}/actions/set_rules")

HTTP_BODY=$(echo "$RESPONSE" | head -n -1)
HTTP_CODE=$(echo "$RESPONSE" | tail -n 1)

if [ "$HTTP_CODE" != "201" ]; then
  echo "ERROR: La API de Hetzner retornó HTTP ${HTTP_CODE}"
  echo "Respuesta: ${HTTP_BODY}"
  exit 1
fi

ACTION_STATUS=$(echo "$HTTP_BODY" | jq -r '.actions[0].status // "unknown"')
echo "Acción enviada — estado inicial: ${ACTION_STATUS}"

# ── Verificación post-actualización ───────────────────────────────────────────
echo ""
echo "=== Reglas activas del firewall '${FW_NAME}' ==="
curl -s \
  -H "Authorization: Bearer ${HCLOUD_TOKEN}" \
  "${HETZNER_API}/firewalls/${FW_ID}" \
  | jq -r '.firewall.rules[] | "[\(.direction)] \(.protocol):\(.port // "any") ← \(.source_ips // [] | join(", ")) — \(.description // "")"'

echo ""
echo "Verificando conectividad con talosctl..."
if talosctl version --nodes "${FLOATING_IP:-}" --timeout 5s &>/dev/null; then
  echo "OK: Talos API responde correctamente con la nueva IP."
else
  echo "AVISO: Talos no responde aún. Espera 10 segundos y vuelve a intentarlo."
  echo "  Los cambios del Hetzner Firewall pueden tardar ~5-10 segundos en propagarse."
fi
SCRIPT

chmod +x scripts/update-firewall.sh
```

### T-10.1.9 — Instalar alias de conveniencia

Para ejecutar el script sin recordar su ruta, añadir un alias al shell:

```bash
# Agregar al ~/.zshrc o ~/.bashrc (ajustar la ruta al monorepo)
cat >> ~/.zshrc << 'EOF'

# serenidad — actualizar IP en Hetzner Firewall
alias update-serenidad-fw='cd /ruta/al/monorepo && ./scripts/update-firewall.sh'
EOF

# Recargar la configuración del shell
source ~/.zshrc
```

Uses Hetzner REST API /firewalls/{id}/actions/set_rules to atomically replace
all firewall rules, preserving public ports (80, 443) while updating admin
ports (50000, 6443) to the current public IP.

Rationale: residential/office ISPs assign dynamic IPs; manual Hetzner dashboard
updates are error-prone and slow during an incident."

### T-10.1.11 — Uso operacional y escenarios

**Escenario normal — IP cambió después del fin de semana:**

```bash
# kubectl no responde → la IP ha cambiado
kubectl get nodes
# Error: connection refused / timeout

# Ejecutar el script de actualización
./scripts/update-firewall.sh
# IP pública actual: 198.51.100.42/32
# Actualizando reglas...
# OK: Talos API responde correctamente con la nueva IP.

# Verificar que K8s volvió a responder
kubectl get nodes
# NAME              STATUS   ROLES           AGE
# serenidad-prod-01 Ready    control-plane   Xd
```

**Verificación manual sin el script:**

```bash
# Ver reglas actuales del firewall
hcloud firewall describe serenidad-prod-fw

# O via API REST
curl -s \
  -H "Authorization: Bearer ${HCLOUD_TOKEN}" \
  "https://api.hetzner.cloud/v1/firewalls?name=serenidad-prod-fw" \
  | jq '.firewalls[0].rules[] | {dir: .direction, port, ips: .source_ips}'
```

## Criterios de Aceptación

| ID | Criterio | Verificación |
|----|----------|--------------|
| CA-10.1B.1 | Script detecta correctamente la IP pública actual | `./scripts/update-firewall.sh` muestra una IPv4 válida |
| CA-10.1B.2 | Script falla con mensaje claro si `HCLOUD_TOKEN` no está definido | `unset HCLOUD_TOKEN && ./scripts/update-firewall.sh` → mensaje de error + exit 1 |
| CA-10.1B.3 | Reglas públicas (80, 443) se conservan tras la ejecución | Verificación de reglas post-ejecución muestra ports 80 y 443 con `0.0.0.0/0` |
| CA-10.1B.4 | Puertos 50000 y 6443 quedan restringidos a la nueva IP `/32` | Verificación de reglas muestra la IP actual en esos puertos |
| CA-10.1B.5 | `talosctl version` responde después de ejecutar el script | El script lo verifica automáticamente en la sección de validación |
| CA-10.1B.6 | `kubectl get nodes` funciona después de ejecutar el script | `kubectl get nodes` muestra el nodo en estado `Ready` |
| CA-10.1B.7 | Script comprometido en el repositorio y ejecutable | `git ls-files scripts/update-firewall.sh` muestra el archivo; `ls -l scripts/` muestra bit `x` |
