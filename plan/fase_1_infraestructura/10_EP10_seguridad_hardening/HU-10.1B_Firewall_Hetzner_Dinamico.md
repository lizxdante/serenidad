# HU-10.1 (Parte B): Dinamismo del Firewall L3 (Hetzner Cloud)

## Descripción General
En el despliegue del componente perimetral de nuestra VPS (fase EP-02), cerramos al público general los puertos administrativos críticos: el API de Talos Linux (`50000`) y el API nativa de Kubernetes (`6443`), atándolos a la dirección IP actual de nuestra estación de trabajo física (`$MY_IP`).

El problema: En las redes de oficinas o el hogar, el proveedor de internet rota o asigna IP dinámicas rutinariamente, bloqueando automáticamente nuestra gestión de la infraestructura al cambiar. 
Crearemos un script que agilice la auto-provisión de nuestra *NUEVA* IP mediante el API de Hetzner sin que requiera el control manual desde su panel de control web.

---

## Ejecución Detallada

### T-10.1.8 — Programar la Herramienta de Actualización
Utilizaremos `curl` y `jq` integrados en el Bash para contactar a Hetzner Cloud y sobre-escribir nuestras exclusiones.

```bash
mkdir -p scripts

cat <<'EOF' > scripts/update-firewall.sh
#!/usr/bin/env bash
set -euo pipefail

# 1. Cargar el entorno para contar con HCLOUD_TOKEN 
source .envrc

# Validar existencia de token
if [ -z "${HCLOUD_TOKEN:-}" ]; then
  echo "CRÍTICO: No existe la variable HCLOUD_TOKEN en tu entorno."
  exit 1
fi

echo "Identificando tu IP Física actual en la red mundial..."
NUEVA_IP=$(curl -s -4 https://ifconfig.me)
echo "Tu IP actual de trabajo fue detectada como: ${NUEVA_IP}"

# 2. Descargar las métricas de tu Firewall actual 
# Nota: La herramienta de cli "hcloud" debió ser instalada en Fase 2.
FW_NAME="serenidad-prod-fw"

echo "Re-escribiendo regla del API de Talos (Puerto 50000) a tu favor..."
# Comando hcloud omite JSON y muta directamente la infraestructura
# CUIDADO: require hcloud version > 1.30 para uso nativo de replace
# En su defecto borraremos y reacrearemos las rutas especificamente:

# Quitamos las previas
hcloud firewall remove-rule $FW_NAME --direction in --port 50000 --protocol tcp --source-ips any || true
hcloud firewall remove-rule $FW_NAME --direction in --port 6443 --protocol tcp --source-ips any || true

# E incrustamos tu IP de rango dinámico local como un /32 absoluto
hcloud firewall add-rule $FW_NAME \
  --description "Talos API (IP Dinamica Administrador)" \
  --direction in \
  --port 50000 \
  --protocol tcp \
  --source-ips ${NUEVA_IP}/32

echo "Re-escribiendo regla del API de Kubernetes (Puerto 6443)..."
hcloud firewall add-rule $FW_NAME \
  --description "Kubernetes API (IP Dinamica Administrador)" \
  --direction in \
  --port 6443 \
  --protocol tcp \
  --source-ips ${NUEVA_IP}/32

echo "--------------------------------------------------------"
echo "VERIFICACIÓN EXITOSA: "
hcloud firewall describe $FW_NAME | grep -E -A 1 "(50000|6443)"
echo "--------------------------------------------------------"
EOF

# Otorgarle habilidades al motor de UNIX para correr el archivo de texto como un sistema compilado
chmod +x scripts/update-firewall.sh
```

### Inserción al Repositorio de Herramientas (Commiteo)
Puesto que son herramientas del equipo local y no manifiestos del ecosistema, un push tradicional alcanza en vez de demandar la atención de *FluxCD*.

```bash
git add scripts/update-firewall.sh
git commit -m "feat(security): add dynamic bash utility to auto-update hetzner firewall administrator ip"
git push origin main
```

### Ejecución Constante
A partir de hoy, si tecleas `kubectl get all` y el servidor arroja error local de **"Time out Connection"** pese a tener internet, sabes que debes invocar:
`./scripts/update-firewall.sh`
Y la luz verde reaparecerá al segundo tras sobre-apuntarte automáticamente a ti mismo.
